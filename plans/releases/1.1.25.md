# 1.1.25 — context 반환 실패와 다중 창 복구

기준 1.1.24, 검증일 2026-09-10. GR-03/04/11/12와 종료 알림 수명의 실제 증분이다. 책임 버전 1.1.25의 BMI·block cache·JIT 성능 과제와 구분한다.

## 5페이즈

1. **재현:** worker의 DoneCurrent 실패 뒤 GUI 생성·loader 진입과, 새 root/shared context의 반환 실패를 정상 경로와 대조한다.
2. **수정:** 반환 실패를 borrow 호출자까지 전달하고 부분적으로 확보한 worker를 되돌린다. 실패한 새 context는 생성한 GUI thread에서 정리한다.
3. **통합:** 창 생성·교체·제거가 실패한 소유권 이전을 사용하지 않도록 한다. 생성 실패의 software 설정을 기존 창에도 적용한다.
4. **검증:** 실제 Qt의 여러 인스턴스에서 실패·기존 상태 보존·재시도·native 전환·종료를 확인한다. 발견된 종료 후 앱 알림 충돌도 재현하고 수정한다.
5. **배포:** 확인한 Windows 경계를 버전·실행 파일·패키지에 반영한다. 물리 장치 상실과 다른 OS/driver·장기 수락은 유지한다.

## 변경

Screen→Window→Instance→EmuThread의 context 반환 결과를 연결했다. 반환이 실패하면 worker는 borrow 성공이나 대기 상태를 공개하지 않고 기존 그래픽 오류·실행 중단 경로로 들어간다. GUI scope는 실패 전에 받은 새 소유권만 되돌린다. 중첩 scope가 실패해도 바깥 scope의 소유권을 유지하며, 호출자는 성공을 확인한 뒤에만 창과 loader에 접근한다.

창 생성이 거부된 새 인스턴스는 전역 목록에 등록하거나 worker를 시작하지 않고 초기 준비 자원을 정리한다. 설정 교체가 거부되면 이미 해제한 창을 다시 초기화한다. 창 목록에서 제거하는 작업은 해당 인스턴스의 worker만 정지시키며, 그 요청도 실패하면 창을 유지한다.

새 root/shared context를 worker에 넘기기 전 DoneCurrent가 실패하면 생성한 GUI thread에서 정리하고 기존 native 표시로 전환한다. Windows는 호출 thread 자신의 current context 삭제 시 current 상태도 해제하지만, 다른 thread에서 current인 context 삭제는 오류로 정의한다. 이 계약에 따라 새 context 정리와 실행 중인 worker 소유 context 보존을 구분했다. [Microsoft WGL 삭제 계약](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-wgldeletecontext)

생성 실패가 전역 설정만 software로 바꾸고 기존 창을 OpenGL에 남기던 불일치도 수정했다. 생성·등록과 worker scope가 끝난 뒤 기존 설정 갱신을 GUI 큐로 요청하여 모든 창에 같은 전환을 적용한다.

실제 다중 창 실행 중 종료한 창에 앱 활성 상태 알림이 도착해 해제된 인스턴스를 참조하는 충돌이 발생했다. 디버거에서 `onAppStateChanged`→`keyReleaseAll` 경로를 확인했고, 닫힌 창은 이 알림을 처리하지 않도록 했다.

## 검증 범위

- 수정 전 worker 반환 실패 검사에서는 새 창과 loader 호출이 발생했다. 새 root/shared context 반환 실패의 두 검사도 실패했고, shared 경로는 worker 초기화까지 호출했다. 현재는 모두 거부·정리·native 전환을 확인한다.
- 기존 Qt 동기화 fixture에서 부분 borrow 반환, 중첩 scope의 바깥 소유권 보존, 실패 후 재시도와 기존 early/waiting 순서가 통과했다. GL 함수 조회·위젯·설정 갱신 큐는 이 fixture의 대역이며 실제 Qt 실행과 구분한다.
- 전체 Qt 프로그램의 현재 object 파일과 생성 DS guest 두 개를 사용했다. 두 번째 worker의 반환을 지속 실패시키면 세 번째 인스턴스 생성과 실패한 창의 종료가 거부됐다. 실패한 guest의 프레임·RAM·context를 유지하고, 먼저 빌린 다른 worker는 재개했다. Cancel 후 중단 유지, 명시적 복구, 새 인스턴스 생성 재시도와 종료가 통과했다.
- 새 root context 반환 실패 시 실제 WGL 삭제와 GUI current 해제를 확인했다. 세 인스턴스의 native 전환과 생성 게임 화면, shared context 반환 실패 후 보조 창의 native 이미지, 네 창의 OpenGL 재선택·최종 종료도 통과했다.
- 종료 후 앱 알림 검사는 수정 전 segmentation fault로 실패했다. 현재는 정상 창의 입력 해제·pause/unpause를 유지하면서 종료 이후 같은 알림을 무시한다. 기존 저장 실패·취소·복구·자식 창 종료 검사는 유지한다.

전체 Qt 검사는 실패 시 current를 일부러 유지하는 WGL wrapper를 사용한다. 이는 문서상 오류에서 current를 해제하는 실제 WGL 동작보다 강한 주입이며, 물리 driver 오류가 같은 상태를 만든다는 증거가 아니다. [Microsoft current 전환 계약](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-wglmakecurrent)

Windows x64 Release 전체 빌드가 통과했다. 최종 전체 CTest는 **440/441, skip 0**이었다(26.43초). 변경하지 않은 `gdb-protocol-loopback`의 TCP 세션 검사가 한 번 실패했고, 같은 바이너리에서 해당 검사만 다시 실행해 **1/1 통과**했다(0.34초). 전체 검사를 반복하거나 첫 실패를 성공 기록으로 덮어쓰지 않았다. 병렬 실행에서의 첫 실패 원인은 확정하지 않았으며 이번 그래픽 변경으로 해결됐다고 주장하지 않는다.

GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26과 기존 JIT/ISA 구성을 유지했다. core 에뮬레이션·GDB 프로토콜 소스는 변경하지 않았다. 실행 파일은 `1.1.25-melonDS.exe`, 패키지는 `1.1.25-melonDS-windows-x64.zip`과 `1.1.25-melonDS-source.zip`이다. 실행 파일·필요 DLL/plugin·라이선스만 포함하며 게임·설정·저장 자료는 포함하지 않는다.

## 남는 범위

전체 Qt 실행은 동일한 동작 구현의 버전 표기 최종 재링크 전 검증이다. 배포 EXE에 오류를 주입한 실행이나 새 상용 게임 수락으로 집계하지 않는다. SDL dummy 오디오를 사용했고 추가 인스턴스의 dummy 장치 열기는 실패했으므로 다중 장치 오디오 수락도 아니다.

물리 context/surface 상실·이종 GPU/DPI·휴면·다른 OS·native 삭제 자체의 실패·장기 실행은 미검증이다. 다음 실제 1.1.26은 GR-03의 Video settings 선택과 활성 renderer·capability·복구 후 Cancel 상태를 실제 Qt에서 대조한다. GPU 정밀도·Vulkan·JIT/ISA·DSP·오디오·네트워크·주변장치 등 공개 전체 계획은 유지하며 성능·전력·물리 지연 개선량을 주장하지 않는다.

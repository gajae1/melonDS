# 1.1.214 — 재개 프레임의 시간 기준 재설정

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

이전 일시정지 루프는 최대 75ms의 메시지 대기와 화면 갱신 전에 프레임 시각을 기록했다. 재개 후 프레임 제한기는 그 사이의 호스트 정지 시간까지 실행 지연으로 계산하고 누적 오차를 유지했다. AudioSync OFF이고 FPS 제한을 사용하는 경우, 재개 직후 프레임들이 쉬지 않고 연속 실행될 수 있었다. 오디오 큐는 일반 일시정지에서 보존되므로 이 일시적인 생산 집중은 큐를 추가로 채울 수 있다. 오차는 제한되어 있으므로 무제한 따라잡기 현상으로 해석하지 않는다.

호스트 중단 경로에서 재설정 요청을 남기고 재개 프레임에서 시각과 오차를 한 번 다시 맞춘다. 같은 메시지 처리 안에서 일시정지·재개가 끝나는 경우도 포함한다. 평상시 프레임 제한의 반올림 오차 보정, AudioSync가 이미 프레임을 제한하는 경우, FPS 제한을 끈 경우의 동작은 유지한다. 출력 큐·필터·장치 설정·입력 처리 앞의 대기는 추가하거나 변경하지 않는다.

## 검증과 한계

- 실제 메시지 처리기와 실제 프레임 제한 코드를 기존 검사에 연결하고 시계와 sleep만 가상화했다. 75ms·2초 정지와 같은 메시지 묶음 안의 250ms 중단을 검사한다. 재설정을 생략한 이전 동작 대조군은 연속 실행 검사에 실패하고 수정 경로는 통과한다.
- 정상 실행 300프레임에서 반올림 누적 보정이 유지되고, 오디오가 속도를 제한하거나 FPS 제한을 끈 경우 추가 sleep이 생기지 않는지 확인한다. 이는 결정적 가상 시계 검사이며 사용 중인 PC의 FPS나 물리 지연 측정이 아니다.
- 재개 시간·오디오 설정 메시지·상태 복구·GL 실패 복구·GDB 중단 경계의 집중 검사 5개를 통과했다. 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- 게임 플레이와 장기 청취를 하지 않았으며 틱 노이즈 전체 해결을 선언하지 않는다. 비동기 출력의 장기 클록 차이에 대한 자동 보정은 추가하지 않았다. 실제 큐 넘침과 청감 영향은 정지 전 큐 깊이·콜백 시점·기기 부하에 따라 달라진다.

9800X3D의 내장그래픽을 GPU 부하가 큰 조건의 기준으로 사용한다. CPU 자체가 느린 구형 기기의 전체 성능을 대표하는 구성으로 간주하지 않는다. 이번 수정에는 새로운 GPU 성능 측정을 포함하지 않는다.

# 1.1.137 — 일반 bitmap OBJ의 캡처 디테일 보존

2026-09-18. 기준 1.1.136 `5eea9164`. 메인 checkout과 빌드는 `F:/melonDS`, `build/windows-dev`다.

## 구현과 관측된 결함

3x의 캡처 bitmap OBJ는 양 engine에서 native 4,096픽셀 대조를 통과했지만 LCDC 표시 참조와 240픽셀이 달랐다. 원본 texel (32,24)은 정상적으로 투명한 RGB555 0000이었고 캡처 사본의 나머지 서브픽셀은 빨강이었다. OBJ에 캡처 합성이 활성화되지 않아 최종 표시가 검은 native 원점을 복제했다. 원본 행을 0으로 덮는 결함은 아니었다.

일반·비반전 direct-color bitmap OBJ가 기존 캡처 사본을 읽도록 확장했다. native 1D/2D 주소 계산을 재사용하고 AOBJ/BOBJ mapping에 기존 단일 bank·provenance·행 유효성·동일 배율 검사를 적용한다. 각 서브픽셀에서 기존 OBJ 우선순위와 OAM 순서를 적용하며 native 투명 원점 아래의 일반 OBJ도 보존한다. 창·BG/OBJ 합성·alpha·밝기는 기존 규칙을 따른다. CPU/DMA용 VRAM과 native 캡처 쓰기는 변경하지 않는다.

추가 버퍼는 현재 sprite 평가 행의 표시 사본이다. 캡처 포인터를 저장하지 않고 즉시 읽는다. 16배의 scratch 크기는 engine당 262,144바이트이며 성능 개선을 주장하지 않는다.

## 확인한 검증

Pro 실제 수정 후 melonDS·VulkanRendererIntegration·GLFrameReadback 빌드가 성공했다. 선택 CTest 10/10, 실패·skip 0, 22.44초를 확인했다. 양 engine 1x/3x OBJ, 기존 Vulkan 1x/2x/3x, LCDC capture, bitmap BG, 재링크한 software compositor를 포함한다.

양 engine에서 3x의 240픽셀 불일치가 0이 됐다. 1x/3x 각각 native 4,096픽셀과 캡처 VRAM 131,072바이트 보존, 기본 화면 49,152/442,368픽셀 대조를 확인했다. engine별 추가 조건은 1x 18개, 3x 23개이며 CTest 수와 중복 합산하지 않는다. 주소 pitch, alpha, OBJ/BG 우선순위, OAM 순서, 창, fallback, CPU alias 쓰기 무효화를 검사한다. 독립 고정 빨강 경계 assertion도 포함한다. LCDC 대조 자체는 공유 경로 동등성이며 실기 oracle가 아니다.

별도 xhigh 작업은 1.1.136 HEAD에서 추출한 BG 합성·샘플링 함수를 scalar 경로와 비교했다. 2,560개 버퍼 쌍, 188,284,928바이트, 불일치 0; 컴파일·실행 exit 0. 양 engine, 2/3/5/8/16배 및 배율 불일치, 정수·음수 wrap·일반 affine, 창·효과, 무효·다중 mapping을 포함한다. 이 CPU 하네스는 stub mapping/provenance를 사용하므로 실제 GPU 캡처 생성·무효화 시점·전체 게임 동등성의 증거로 확대하지 않는다. 로컬 재현 자료: `local-docs/hoist-byte-validation-20260918/`.

## 남은 범위

Affine·반전 bitmap OBJ는 sprite별 native 샘플링, 모자이크 sprite가 있는 행은 행 전체 native OBJ를 유지한다. 배율 불일치·겹친 mapping·무효 capture도 native fallback이다. 색인 OBJ는 경쟁 후보이며 캡처 디테일을 직접 향상하지 않는다. 3D texture 캡처 재사용·GPU 2D·직접 GPU 표시·실게임·DSi·다른 GPU/OS·설치 UI·고배율 성능 검증은 미완료다. 전체 로드맵 완료를 뜻하지 않는다.

## 배포

버전 1.1.137 표기를 포함한 전체 기본 타깃 빌드가 exit 0으로 성공했다. 이어 전체 CTest **975/975**, 실패·skip·disabled 0, **115.69초**, exit 0을 JUnit과 콘솔 로그로 확인했다. 전체 suite는 이 최종 소스에서 한 번 실행했다. 로컬 증거는 `local-docs/pro-obj-20260918/release-build.log`, `release-ctest.log`, `release-ctest.xml`이다. 이 결과가 실게임·장치·UI의 모든 경계를 수락한 것은 아니다.

기존 deploy-windows.py 및 package-windows.py로 버전별 runtime/source ZIP을 생성한다. 실제 완료와 SHA-256은 생성 manifest 및 후속 배포 기록을 따른다. 이전 패키지와 사용자 ROM·저장 파일을 보존한다.

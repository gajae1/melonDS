# 1.1.158 — Minimum-phase 이력 복사 비용 감소

2026-09-22. 기준 1.1.157 aee31c12, Windows UCRT64 Release 빌드.

## 변경

- Minimum-phase의 유효 기간이 끝난 dense 이력은 시작 위치만 옮겨 제외한다.
  예약 공간의 끝이 부족할 때 유효 이력을 앞으로 옮긴다. 서로 다른 길이의
  이력이 뒤에서 먼저 끝나는 경우도 기존 합산 순서로 정리한다.
- 계수, 덧셈 순서, 필터 품질, 출력 버퍼와 기본 지연은 바꾸지 않았다.
  처리 중 할당하지 않는 기존 계약과 reset 동작을 유지한다.
- ROMSmoke에 Vulkan 어댑터 선택, 실제 GL/Vulkan 장치명, Vulkan 프레임
  비용 계측을 연결했다. opt-in 렌더 계측 로그를 headless 플랫폼이 보존한다.
- 오디오 공급 측정 helper의 중복 FPS 대기를 제거해 제품의 audioPacesFrames
  경로와 맞췄다. 수정 전 helper의 부족 횟수는 제품 결함 증거로 쓰지 않는다.

## 검증 및 비용

실제 SPU::Mix, PCM16 16채널, 24,000 mix tick, 실행 순서를 번갈아 한 5쌍의
중앙값이다. GPU 작업을 끝낸 뒤 단독 측정했다.

| 부하 | 이전 ns/mix | 변경 ns/mix | 처리 시간 변화 |
|---|---:|---:|---:|
| dense 가변 timer | 22,355.9 | 19,195.1 | -14.14% |
| dense 고정 timer·중앙 pan | 6,888.7 | 5,318.7 | -22.79% |
| sparse 가변 timer 대조 | 4,667.7 | 4,748.5 | +1.73% |

전체 게임 속도나 모든 입력의 개선으로 확대하지 않는다. sparse 대조는 개선을
주장하지 않는다. 기존 구현의 계측에서 block 방문 18,672,256회 중 복사가
18,364,478회였으며, 이번 변경은 이 복사 비용을 겨냥했다.

- Auto/scalar, 352/512 mixer, native/sparse 대조를 포함한 6조건에서 PCM
  184,920바이트가 이전 코어와 일치하고 SPU 상태·capture 해시도 동일했다.
- 두 mixer의 실제 이력 상한 196개 중 194개를 사용하는 공간 재사용/reset
  검사와 DS/DSi 저장·capture·rollback 검사가 통과했다. 최종 core 집중 CTest 6/6.
- Solatorobo 1,200프레임 Minimum-phase 출력 3,851,152바이트도 이전 코어와
  동일했다. 수정된 측정 helper로 실제 SDL/WASAPI 장치에 요청 128/256/512
  버퍼를 각각 20초 전달했고 부족·빈 callback·코어 폐기는 모두 0이었다.
  장치 제출은 무음이며 Qt 표시와 외부 동시 부하는 없었다. 끊김 전면 해결이나
  청취 수락을 뜻하지 않는다.
- 프런트엔드 실제 callback/sync와 SPU 큐의 별도 검사에서는 수정할 결함을
  재현하지 못했다. 의도적으로 생산을 25.5~28.5ms 지연하면 부족이 발생했으며,
  생산 재개 후 4,646샘플이 기준과 같았다. 이것은 사용자의 실제 장면이나 청취
  수락을 대신하지 않으며 버퍼를 늘리는 근거로 사용하지 않았다.

## 남은 범위

- 실제 사용자 게임·장면의 고부하 저버퍼 끊김, 물리 출력 지연과 장기 청취.
- 같은 버전의 다른 보간 방식 대비 Minimum-phase 음색·음량 차이는 별도 문제다.
  이번 변경은 기존 PCM을 보존하므로 고음 감쇠 특성을 바꾸지 않는다.
- 실제 단일 PCM16 채널의 비교에서는 전역 gain 손실이 없었으나 소스 주파수
  한계의 96.875%에서 원음 자체가 크게 감쇠했다. 4,091Hz 소스의 1,982Hz
  기음은 None -3.82dB/Cubic -5.54dB/Minimum-phase -28.00dB,
  8,182Hz 소스의 3,963Hz 기음은 각각 -4.22/-6.10/-28.56dB였다.
  호스트 출력이 48kHz여도 저속 음원의 실제 가청 성분을 줄일 수 있는 현재
  프로파일의 한계이며, 단순한 불필요 고주파 제거만으로 설명하지 않는다.
- Radeon iGPU 측정에서 Vulkan의 속도 우위는 입증되지 않았다. 대규모 Vulkan
  개발은 보류하고 오디오 비용·품질과 검증된 기존 경로에 우선순위를 둔다.
  기존 backend 삭제나 정확성 기능의 폐기는 하지 않았다.
- 동일 Solatorobo 1,200프레임 Radeon 측정에서 8배율은 GL 82.86fps,
  GL compute 43.26fps, Vulkan 53.93fps였다. 별도 계측 실행의 마지막
  256프레임 Vulkan GPU 비용은 3D 28.78ms, 합성 4.26ms, 표시 readback
  1.88ms였다(누락 0). 표시 readback만 제거해도 3D 비용이 남는다.
  전체 1,200프레임 평균과 마지막 256프레임 비용은 다른 구간이며,
  Qt 표시 비용과 실제 사용자 장면을 포함하지 않는다.

## 배포 상태

최종 Windows 전체 CTest 1010/1010, 실패·건너뜀 0, 183.56초, exit 0.
코어와 프런트엔드 전체 빌드 후 실행했으며, 패키지 identity를 위한 재링크에는
이 성공한 소스 회귀 결과를 재사용한다. 패키지 확인은 후속 기록한다.

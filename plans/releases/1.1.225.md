# 1.1.225 — Vulkan 텍스처 Modulate 배치의 래스터·깊이 블렌드 융합

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

1.1.223은 Vulkan Compute 3D의 작은 무텍스처 배치에서 래스터 계산을 깊이·블렌드 셰이더에 융합했다. 1.1.225는 같은 융합을 텍스처 Modulate 배치로 넓힌다. 조건을 만족하는 배치는 간접 래스터 dispatch(GPU가 버퍼에서 작업 수를 읽어 실행하는 호출)를 생략하고, 폴리곤 순서와 깊이·블렌드 규칙은 기존과 같다. 일반 텍스처와 128·256 캡처 텍스처는 기존 샘플링·보간과 순서 보존 블렌드 계산을 재사용한다. 최종 배치는 Fog·AA가 모두 꺼진 경우에만 융합한다. 비최종 배치를 융합한 뒤에는 별도 최종 패스가 올 수 있다.

Vulkan 셰이더 프로그램은 44개에서 48개로 늘었다(44~47 추가). descriptor set(셰이더가 읽는 자원 묶음)은 4개를 유지한다. set 2의 샘플러 바인딩은 3개에서 5개로 늘었다. 0~2번은 기존 래스터 자원을 그대로 두고 3·4번은 융합 배치의 clear bitmap용이다. 융합 대상 텍스처 배치만 5개를 기록하고 나머지는 기존 3개를 기록한다. 바인딩 용량이 늘었을 뿐이며 전역 scratch 메모리가 줄었다는 주장은 하지 않는다. OpenGL Compute 동작은 바꾸지 않았고 기존 OpenGL 렌더러 `GPU3D_OpenGL.cpp`를 포함한 사용자 수정 파일 3개의 해시가 유지됐다.

## 적용 조건과 fallback

- 폴리곤 1~8개, 텍스처 variant 하나(Modulate, 셰이더 13·14), TileSize 8, 1~4배율.
- 비최종 배치, 또는 Fog·AA가 꺼진 최종 배치.

조건 밖의 variant·크기·최종 효과는 기존 경로를 그대로 쓴다.

## 검증

- 실제 AMD Radeon(TM) Graphics(GL·Vulkan 참조 GPU)에서 집중 GPU 검사 3개가 건너뛴 항목 없이 통과했다. 시간은 focused.xml의 검사별 값이며 합계는 28.50초다.

| 검사 | 시간(초) |
| --- | ---: |
| `gpu-vulkan-compute-spans` | 14.75 |
| `gpu-vulkan-pipeline-cache` | 3.97 |
| `gpu-vulkan-renderer` | 9.78 |

- 변경한 8개 소스·테스트 파일의 최종 diff를 검토해 수락했다. 검토 범위는 텍스처 융합 셰이더 4개, 샘플러 바인딩 격리, 24바이트 push constant, 제한된 호스트 자격 판정, 공유 descriptor set 수명, 픽셀·fallback 검사다. 파일 해시는 source-review.json에 있고 소스 커밋의 내용과 일치한다.
- 게임·창·실제 오디오 조작은 하지 않았다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 성능 측정

비공개 probe가 실제 `Vulkan::ComputePipeline::RenderView(..., Readback::None)`을 호출하고 Vulkan 진단 미터의 GPU3D·Record3D·Total을 읽었다. 두 경로는 같은 장치와 업로드한 텍스처를 공유하고 pipeline만 분리하며 `SetFusedRaster`로 융합 여부를 바꾼다. 입력은 합성 지오메트리와 Modulate(13·14) 셰이더 하나다. 96사례는 텍스처 3종(일반 8×16×2, 캡처 128×16×2, 캡처 256×16×2)×1·2·4배율×Z/W×넓은·좁은 폴리곤×폴리곤 1·4·8개이며, 4배율 8폴리곤은 기존 작업 용량 한도 때문에 제외해 종류당 32사례다. 사례마다 20쌍을 예열한 뒤 실행 순서를 번갈아 40쌍을 측정했고, 두 쪽 모두 일반 경로인 A/A 대조를 같은 방식으로 실행했다. 원본은 probe/ab.json·aa.json, 요약은 probe/comparison.json, 채택 판정은 adoption.json이다.

probe는 간접 dispatch 호출을 감싸 원래 함수를 그대로 호출하며, 일반 경로는 비어 있지 않은 배치마다 1회, 융합 경로는 0회임을 확인하고 다르면 중단한다. 96사례 모두 일반·융합·OpenGL 참조 프레임의 전체 픽셀이 같았고(다르면 probe가 실패한다) 폴리곤 4개 사례는 분할 배치와 빈 꼬리 배치도 같았다. AB와 AA는 96개 키와 픽셀 해시가 일치하고 사례마다 40쌍이다.

GPU3D 쌍별 중앙값은 96사례의 중앙값 기준 6.78% 낮았고(종류별 6.77·6.91·6.73%) 사례별 범위는 -0.26~9.72%다(음수는 느려짐). 앞선 쌍은 3840쌍 중 3697쌍이다. 91사례는 각자의 A/A 절대 쌍별 변동 중앙값(전체 최대 1.99%)보다 크게 낮았다. 나머지 5사례는 모두 4배율 좁은 폴리곤 1개이며 0.03~0.26% 느렸지만 각자의 A/A(0.37~0.71%) 안이라 이 조건의 이득과 손해를 모두 확정하지 못한다. 이 사례를 없애려고 폴리곤 수나 넓이의 임계값을 조정하지 않았고 모든 사례를 남겼다. A/A는 잡음 진단이며 통계적 신뢰 구간이 아니다.

Record3D 중앙값은 4.92% 낮았고 96사례 모두 중앙값이 낮았지만(범위 1.46~8.64%) 22사례만 A/A를 넘고 74사례(일반 8×16×2 27, 캡처 128×16×2 22, 캡처 256×16×2 25)는 A/A(최대 13.73%) 안이다. Total 중앙값은 5.34% 낮았고 90사례에서 낮았지만 62사례만 A/A(최대 11.04%)를 넘고 34사례(일반 8×16×2 11, 캡처 128×16×2 11, 캡처 256×16×2 12)는 그 안이다. 이 중 6사례는 중앙값이 높았고(0.08~2.75% 느림) 모두 A/A 안이다. 그래서 모든 조건에서 CPU 기록·전체 시간이 줄었다고 주장하지 않는다. 융합 배치의 추가 descriptor 갱신 비용은 Record3D에 포함된다.

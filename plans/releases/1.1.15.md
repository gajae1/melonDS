# 1.1.15 — x64 JIT ASR 명령·사이클

상태: 구현·Windows 빌드·로컬 회귀 완료. 기준 1.1.14. CJ-03의 증분이며 CJ-06은 근거 조사 단계다. 기존 책임 버전 1.1.15의 메모리·CP15 과제 완료를 뜻하지 않는다.

## 5페이즈

1. **재현:** ARM9/ARM7 실제 코어에 생성 ALU·shift 명령을 넣고 interpreter·일반 JIT·fastmem을 비교한다. 두 번째 block 진입으로 컴파일 시 interpreter 실행과 구분한다.
2. **수정:** `ASRS Rd,PC,#32`의 잘못된 x86 BT 피연산자와 Thumb ASR(register)의 내부 사이클 누락을 각각 수정한다.
3. **통합:** shift 경계값·destination alias·부분 flags·RRX·PC 피연산자·ADC/SBC/RSC를 실제 scheduler와 연결한다. interpreter를 그대로 기대값 함수로 사용하지 않는다.
4. **검증:** 두 결함의 수정 전 실패·수정 후 성공, 전체 CTest, 두 게임의 현재/이전 코어 결과를 확인한다.
5. **배포:** Windows 실행 파일·소스·공개 계획을 버전으로 묶고 의존성·독립 실행·원격 revision을 확인한다. 개인 입력과 실행 기록은 공개하지 않는다.

## 원인과 변경

`Comp_RegShiftImm`에서 ASR #32의 carry를 얻으려고 원래 Operand2에 BT를 적용했다. Rm=PC이면 이 값은 JIT의 즉시값이므로 x86 BT의 목적 피연산자로 인코딩할 수 없다. 실제 `0xE1B0204F`를 컴파일하는 일반 JIT는 SegFault, fastmem은 잘못된 명령 생성 오류로 종료됐다. 이미 계산된 산술 시프트 결과의 부호 비트에서 carry를 얻도록 바꿨다. ASR #32에서는 결과의 모든 비트가 원래 부호와 같으며, 음수 일반 레지스터 대조도 통과한다.

Thumb ALU의 내부 사이클 조건은 LSL·LSR·ROR만 포함하고 opcode 4인 ASR를 빠뜨렸다. 이 때문에 같은 양수 입력을 시프트하는 루프도 ASR가 더 많은 게스트 명령을 실행했다. ASR를 기존 `Comp_AddCycles_CI(1)` 경로에 포함했다. ARM7의 레지스터 지정 시프트는 내부 데이터 경로 사이클이 추가된다. [ARM7TDMI TRM DDI0210C §6.5](https://documentation-service.arm.com/static/5f4786a179ff4c392c0ff819)

| 수정 전 x64 JIT의 프레임당 반복 | LSR | ASR |
|---|---:|---:|
| ARM9 | 20370 | 20748 |
| ARM7 | 28008 | 46680 |

수정 후 일반 JIT·fastmem의 LSR/ASR는 각각 ARM9 20370/20370, ARM7 28008/28008로 interpreter의 상대 비교와 일치한다. 이는 게스트 사이클 수정이며 호스트 성능 향상 측정이 아니다.

## 검증 결과와 한계

`CoreALUExecution.cpp`는 ARM9/ARM7에서 각 backend당 3056회 결과·flags 대조를 실행한다. shift count 0/31/32/33/255/256, Rm/Rs destination alias, NZ/NZC 덮어쓰기, RRX carry, PC +8/+12 피연산자, ADC/SBC/RSC의 carry/overflow·alias·S=0을 포함한다. shift 기대값은 수기로 계산하고 산술 기대값은 독립된 64비트 정수 연산으로 구한다. 모든 ARM 명령이나 조건·예외 조합을 검증한 것은 아니다.

Windows x64 전체 프런트엔드 빌드와 CTest **378/378, skip 0, 7.32초**를 확인했다. UCRT64 GCC 16.2.0·Qt 6.11.2·SDL 2.32.10, C23/C++26·Release·JIT·OpenGL/Compute, 병렬 8 구성이다. 이전 릴리스의 직렬 검사 시간과 성능 비교하지 않는다.

별도로 제공된 DS 게임 두 개를 software renderer·같은 생성 입력으로 각 3600프레임 실행했다. interpreter·일반 JIT·fastmem과 두 수정만 되돌린 1.1.14 코어 JIT, 총 8회가 종료 0·실행 상태 유지였고 도입부 장면을 확인했다. 두 게임 모두 현재 일반 JIT/fastmem의 최종 화면 digest는 이전 코어 JIT와 일치했다. interpreter digest는 달랐고 이 차이는 이전 코어에도 존재했다. 같은 장면까지 진행했지만 차이의 원인·전체 상태 동등성·장기 플레이·입력 지연은 미확인이다.

CJ-06은 공식 ARMv5 ISA의 UNPREDICTABLE 분류와 구현별 호환 동작을 구분해야 한다. ARM7 빈 목록에 관한 [원저자의 ARM 하드웨어 테스트](https://github.com/jsmolka/gba-tests/blob/a7113b67e63f83a9b321696ddd7042ccfad6c881/arm/block_transfer.asm)와 [Thumb 테스트](https://github.com/jsmolka/gba-tests/blob/a7113b67e63f83a9b321696ddd7042ccfad6c881/thumb/memory.asm)를 확보했으며 다음 구현은 전송·writeback·implicit PC·decode·기존 fallback을 함께 다룬다. GBA ARM7 결과를 DS ARM9·빈 PUSH/POP·실기 사이클의 검증 결과로 확장하지 않는다.

native A64 실행, PC/CPSR 복원·조건부 경로, 전체 명령·타이밍과 앞선 장치 수락은 계속 남는다.

# 1.1.07 — 입력 수명과 마이크 버퍼 보호

상태: 구현·Windows 빌드·로컬 회귀 검증 완료(2026-09-10). 기준 소스: 1.1.06. 이번 증분은 FS-09/10과 AD-01/02의 재현 가능한 입력 경계를 다룬다. 과제의 책임 버전과 배포 증분 순서는 구분한다.

## 이번 증분의 5페이즈

1. **재현:** controller→joystick 전환·장치 분리, 터치 이동·취소·포커스 상실, 마이크 입력 끝과 생산/소비 순서를 정상 입력과 대조한다.
2. **수명:** 장치 핸들과 capability를 함께 정리하고, 터치 종료·취소·포커스 상실이 로컬 제스처와 전달 상태를 모두 해제하게 한다.
3. **게시:** 터치 좌표·눌림은 하나의 원자적 값으로 전달한다. 마이크의 입력 끝 보간과 공유 count/FPS의 동기화 경계를 정리한다.
4. **검증:** Qt 생성 이벤트와 실제 layout, SDL 가상 장치, 보호 페이지에 놓은 샘플·생산/소비 대조를 실행한다. 실제 Windows frontend 빌드와 기존 회귀를 확인한다.
5. **배포:** 동일 커밋의 소스·계획과 실행 파일을 묶어 포크 master에 반영한다. 물리 장치·게임·다른 플랫폼 수락은 증거 범위를 나눠 기록한다.

## 변경 범위와 계약

터치는 현재 이벤트 좌표를 사용한다. TouchCancel·종료와 창/앱 포커스 상실 시 눌림을 해제한다. 비활성 상태에서 받은 종료도 이전 눌림을 남기지 않는다. 취소된 펜·터치는 새 press/begin 전의 이동으로 다시 눌리지 않는다. 기존 마우스 drag clamp와 키 매핑·modifier 해제 동작은 유지한다.

GUI가 게시하는 눌림과 X/Y는 하나의 원자적 값이다. 에뮬레이션 스레드는 한 번 읽은 같은 값에서 좌표를 얻는다. 기존 u16 좌표 변환은 유지하며, 새 입력 queue나 별도의 프레임 지연은 추가하지 않는다. 물리 입력→화면 지연의 개선 수치를 주장하지 않는다.

컨트롤러를 바꾸거나 분리하면 controller와 joystick 핸들, rumble/motion capability와 진동 중 플래그를 같은 정리 경로에서 비운다. joystick open 실패는 그 상태로 반환하며 controller만 열지 못한 경우에는 사용할 수 있는 joystick을 유지한다. 기존 인덱스 선택·재연결 fallback 정책은 유지한다.

마이크 보간은 현재 callback에 포함된 마지막 샘플을 경계에서 유지한다. 다음 callback의 샘플을 임의로 읽지 않으며 빈 입력이나 보정 후 출력 길이가 0 이하인 경우에는 쓰지 않는다. 기존 -0.5 시작 위상, buffer 충전량에 따른 ±6 보정과 ring 용량은 유지한다.

외부 마이크의 count 판정과 소비는 기존 mutex 안에서 이루어진다. 이미 열린 장치를 다시 열라는 요청은 대기 샘플과 읽기 위치를 초기화하지 않는다. 새 장치의 분수 sample 상태는 callback을 시작하기 전에 초기화하고, 실행 속도는 callback이 한 번 atomic load한다. 새로운 장치 자동 복구나 필터·DSP 의미 변경은 포함하지 않는다.

## 검증 기록과 한계

Qt가 전달한 이벤트에서 이동 좌표 지연, 취소·포커스 상실·비활성 종료 후 눌림 잔류를 수정 전에 확인했다. 취소 뒤 TouchUpdate와 포커스 상실 뒤 TabletMove가 눌림을 다시 시작하는 반례도 확인했다. 현재 이벤트 회귀 7개와 기존 키 매핑 회귀가 통과했다.

기존 producer/consumer의 개별 좌표 공유는 서로 다른 시점의 X/Y 조합을 관측했다. 이 반례용 실행에서는 각 필드를 오히려 atomic으로 강화해 검사 자체의 C++ 데이터 경쟁을 제거했다. 개별 atomic만으로 좌표 쌍의 일관성이 보장되지 않는다는 증거이며, 원래 평문 필드에 대한 동적 race detector 결과는 아니다.

수정 전 가상 컨트롤러의 정상 매핑 대조는 통과했고 전환·capability·분리·open 실패·닫기 5개 반례는 실패했다. 수정 후 6개 모두 통과했다. 마이크는 정상 보간 대조를 제외한 5개 반례가 실패했고, 그중 보호 페이지 2개에서는 접근 위반을 확인했다. 수정 후 6개 모두 통과했으며 같은 입력을 frontend 테스트 target에 통합해 확인했다. 터치 게시/소비 함수의 동시 이동·해제에서도 혼합 좌표가 없음을 대조했다.

최종 Windows 전체 빌드와 CTest 178/178, skip 0, 22.09초를 확인했다. 기존 interpreter·warmed JIT·fastmem 상태 복원과 실제 OpenGL/Compute 출력 검사도 포함된다. 배포 EXE/DLL 129개의 import 누락은 0개였고, 개발 도구를 제외한 PATH에서 `--help` 종료 0을 확인했다. 공개 계획 16개 문서의 상대 링크와 개인 경로 제외 검사도 통과했다.

구성은 UCRT64 GCC 16.2.0, CMake 4.4.3, Qt 6.11.2, SDL 2.32.10의 Windows x64다. C23/C++26, JIT/OpenGL, 선택적 AVX2/AVX-512와 LTO OFF를 유지한다. Qt Test 의존성은 테스트 target에만 추가되며 배포 frontend가 요구하는 라이브러리는 늘지 않았다. 다른 호스트나 Qt5에서 실행했다는 증거는 아니다.

Qt 이벤트 검사는 offscreen 위젯·생성 장치를 사용한다. 물리 터치·펜·마우스, DPI/회전·다중 모니터·여러 창의 전체 수락, 실제 오디오 장치의 청취·지연·재연결과 게임 장기 실행은 별도다. FS-11/12의 장치 identity와 광범위한 창/배율 정책은 이번 증분으로 완료하지 않는다.

현재 좌표와 이전 좌표의 의미, 취소 이벤트의 빈 point 목록은 Qt의 공식 [QEventPoint](https://doc.qt.io/qt-6/qeventpoint.html)와 [QTouchEvent](https://doc.qt.io/qt-6/qtouchevent.html) 계약을 따른다. 테스트 이벤트 생성은 [Qt Test](https://doc.qt.io/qt-6/qtest.html#touchEvent)를 사용한다.

# 1.1.160 — OpenGL 팔레트 전송과 텍스처 설정의 중복 작업 감소

2026-09-22. 기준 1.1.159 `74ed701a`, Windows UCRT64 Release.

## 변경

- OpenGL 2D BG 팔레트는 최초·reset 이후 전체 65행을 초기화하고, 이후에는
  변경된 첫 행부터 마지막 행까지 한 구간을 전송한다. 원래 전송 조건과 호출 수를
  유지하며, OBJ와 공유하는 임시 버퍼의 구간 내부 행도 매번 새로 복사한다.
- Classic OpenGL 3D는 한 scene chunk 안에서 연속된 동일 텍스처·wrap 설정의
  bind와 parameter 호출을 생략한다. 중간 blend snapshot이 바꾸는 활성 texture
  unit은 매번 복원하고, chunk 경계에서는 기억한 설정을 버린다.
- 오디오 설정의 `frames / Hz`를 장치 주기 대신 해당 프레임 분량의 오디오 시간으로
  표시한다. 실제 장치 깨우기 간격·총 지연과 다를 수 있음을 안내한다.

렌더링 정밀도·배율, 기본 버퍼, 필터 계수, 오디오 공급·대기 방식은 바꾸지 않는다.
오디오 표시 수정은 저버퍼 끊김 해결이나 물리 지연 개선을 의미하지 않는다.

## 집중 검증

실제 GL 호출 계수에서 일반 팔레트 변경 전송은 엔진당 33,280→512바이트,
분산된 extended 팔레트 두 행을 포함한 구간은 33,280→4,096바이트였다.
검사 시나리오 전체는 2,995,200→1,192,960바이트, 호출은 전후 90회로 같다.
초기화·비활성 상태·재활성화·mapping·reset·savestate·renderer 교체·OBJ 임시 버퍼
덮어쓰기를 포함한 122개 검사와 전체 프레임·팔레트 5,633,024바이트 대조가 통과했다.

동일 일반 텍스처 설정 1,000회에서 bind는 1,000→1회, wrap은 2,000→2회이며
활성 unit 선택은 1,000회를 유지한다. 상태 전이 76,800건, chunk 초기 상태 1,280건,
호출 경로 6개와 AMD Radeon GL 3.2의 픽셀 6,291,456개가 기존 동작과 일치했다.
기존 renderer의 alpha·blend·shading·capture·bitmap·compressed 검사도 통과했다.

이 수치는 작업량 감소이며 게임 FPS 향상률이 아니다. 다른 GL 드라이버와
사용자의 실제 장면 전체에 대한 성능·정확성 수락은 별도다.
오디오 설정 창은 SDL dummy·Qt offscreen의 실제 대화상자 렌더링에서
128프레임/48kHz의 2.67ms 문구와 줄바꿈을 확인했다. 물리 장치 검사는 아니다.

## 통합 검증과 패키지

배포 빌드·전체 회귀·실게임 출력 대조와 패키지 결과는 완료 후 이 절에 기록한다.

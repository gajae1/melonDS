# 1.1.198 — Vulkan GPU2D 화면 읽기 통합과 캡처 완료 지연

2026-09-28. 릴리스 소스 커밋은 `c2fffe99af5f3409617c95f75dc2a658acbf02de`다. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 구현

CPU가 GPU2D의 두 화면을 요구할 때, 화면마다 따로 제출·대기하던 전송을 하나로 묶었다. 이미 유효한 CPU 화면은 건너뛰고 확대 화면의 native guest 픽셀도 함께 보존한다. 전송이 성공한 뒤에만 CPU 캐시를 유효하게 표시한다. 두 화면을 모두 읽는 경우 제출은 2회에서 1회로 줄며, 일반 GPU 상주 표시에는 여전히 CPU 이미지 복사가 필요 없다.

마지막 화면 줄의 캡처 배치는 제출 뒤 즉시 기다리지 않는다. 첫 CPU 읽기, 캡처 revision·snapshot 조회, 다음 writer 또는 수명 전환이 결과를 요구할 때 완료한다. 대기 중인 writer와 캡처 소유자는 양방향 연결을 유지하고 성공·실패·파괴 경로에서 이를 해제한다. 완료되지 않은 캡처를 초기화된 데이터로 공개하지 않는다. 같은 장치의 앞선 3D 작업을 기다리는 동작은 남아 있다.

GPU2D는 기본 비활성을 유지한다. GPU2D에서는 기존부터 1배율 GPU 상주 표시가 가능했고, CPU2D의 1배율 RAM 표시 경로는 그대로다. 이번 버전이 최초로 1배율 직접 표시를 추가한 것은 아니다.

## 근거와 한계

- 1·3배율에서 GPU 상주 전달에 이미지 다운로드가 없고, 첫 CPU 요구는 두 이미지 복사·한 번의 제출, 반복 요구는 추가 전송 0회임을 확인했다. 모든 픽셀은 독립 소프트웨어 렌더러와 일치하며 연속 프레임의 서로 다른 화면 색도 확인했다.
- 같은 배율에서 마지막 줄 캡처가 즉시 대기하지 않는 것과 첫 CPU 읽기·savestate 준비·reset·파괴를 확인했다. 앞선 3D fence는 측정 전에 분리해 캡처 대기만 검사했다.
- 캡처 중첩, 캡처 OBJ, native 텍스처, 확대 OBJ, 배율 변경, GPU2D 전환의 기존 검사 6개가 통과했다.
- CoD World at War·Solatorobo, RTX 5080·Radeon 내장 GPU, 1·3배율의 8개 조건에서 각각 1200프레임을 실행했다. 1.1.197과 **최종 framebuffer digest·PPM 및 실행 전체 PCM**이 일치했다. 매 프레임의 화면 비교나 수동 플레이 검사는 아니다.
- Opus는 화면 읽기와 캡처 수명 변경을 각각 한 번 검토했고 이번 변경의 차단 결함을 찾지 못했다. 기존 코드의 COW 준비 뒤 command begin 실패 시 캡처 무효화 부족은 후속 수정 항목이다.
- 통합 readback은 임시 host 버퍼가 더 크다. 16배율의 두 화면과 native 픽셀을 함께 읽으면 약 96.4MiB로, 기존 한 화면 약 48.2MiB보다 많다. 더 작은 버퍼로 재시도하는 fallback은 추가하지 않았다.
- 제출·대기 횟수 감소는 확인했지만 FPS 개선률, 실제 구형 기기의 이득, Vulkan의 OpenGL·Metal 대비 보편적 우위는 측정하지 않았다.
- Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

근거: `local-docs/native-readback-198/`의 `direct-display-success.json`, `focused.xml` 안의 native-deferred 성공 case, `acceptance-*.log`, `baseline-exact.json`, `candidate-exact.json`. 초기 검사 실패와 수정 근거도 보존했다. 중복 PCM은 해시 확인 후 삭제하고 로그·화면을 유지했다.

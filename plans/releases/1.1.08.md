# 1.1.08 — 네트워크 입력과 GDB 연결 보호

상태: 구현·Windows 빌드·로컬 회귀 검증 완료(2026-09-10). 기준 소스: 1.1.07. NP-01/05~07/10~12의 재현 가능한 경계를 선반영한다. 책임 버전의 전체 수락과 배포 증분은 구분한다.

## 이번 증분의 5페이즈

1. **재현:** 짧은 LAN payload·sender/peer 불일치, PCap caplen/len·누락 심볼, DNS 헤더/이름 끝, GDB M/X 길이·escape·응답 크기와 EOF를 정상 입력과 대조한다.
2. **입력:** 큐 삽입·guest 메모리 쓰기·host resolver 호출 전에 요청 전체를 검증한다. 정상 빈 reply와 주소 공간 끝의 유효 쓰기는 보존한다.
3. **복구:** 라이브러리/어댑터 소유권, 오류/부분 전송, 잘못된 checksum 뒤 재전송, NoAck 세션 종료와 재접속을 통합한다.
4. **검증:** 실제 ENet packet, 보호 페이지, driver/resolver 경계 대체와 실제 로컬 TCP로 검사한다. Windows 전체 frontend 빌드와 기존 회귀를 확인한다.
5. **배포:** 동일 커밋의 소스·공개 계획·실행 파일을 묶어 포크 master에 반영하고 실제 장치/다른 플랫폼 수락을 별도로 남긴다.

## 변경 범위와 계약

LAN은 선언한 payload 길이가 실제 ENet 길이와 일치하는지 검사하고, type·sender·ENet peer 및 player slot의 관계를 확인한다. sender ID와 DS AID는 서로 다른 값이다. 길이 0/AID 0 reply는 정상적인 무응답 통지이므로 유지한다. 다른 채널의 readiness 통지가 늦게 도착하는 정상 순서도 허용한다. wire payload 상한 0x2000과 기존 수신 복사 제한 2048/1024바이트를 유지한다. 거부한 packet은 큐·출력·timestamp·host 경로를 변경하지 않고 해제한다.

PCap은 실제 capture 길이와 원래 길이가 같고 14~2048바이트인 Ethernet 프레임만 전달한다. 어댑터의 datalink가 Ethernet인지 확인하며 다른 링크 형식을 Ethernet으로 해석하지 않는다. 누락 심볼은 shared ownership으로 한 번 unload하고, open 이후 실패는 RAII로 닫는다. 장치명 string_view의 지정 범위만 사용하고 adapter 열거 실패도 목록을 해제한다. send 실패는 0을 반환하며 dispatch의 idle/breakloop와 오류를 구분한다. 이는 [pcap_loop](https://npcap.com/guide/wpcap/pcap_loop.html), [pcap_datalink](https://npcap.com/guide/wpcap/pcap_datalink.html)의 길이·링크 형식 계약에 따른다.

Slirp의 DNS override는 EtherType·IPv4 IHL/전체 길이·UDP 길이와 질문 끝을 확인한 뒤 조회한다. 단일 비압축 A/IN 질문과 IPv4 NOP/EOL padding을 지원한다. 압축 이름·추가 section·다른 옵션·DNS IP로 향하는 단편화는 이 override에서 지원하지 않는다. 일반 네트워크 트래픽은 기존 slirp 경로로 전달한다. 정상 A 응답과 조회 실패 시 기존 0.0.0.0 응답 정책을 유지한다. DNS 정책·host resolver 비동기화·IPv6 지원을 추가한 것은 아니다.

GDB m/M/X는 주소/길이와 본문 전체를 범위 제한 파서로 읽는다. M은 정확한 hex 수, X는 escape 해제 후 정확한 바이트 수를 확인한 뒤 guest 메모리에 쓴다. 유효하지 않은 뒷부분 때문에 앞부분만 바뀌지 않는다. 8/16/32비트 정렬 접근 순서를 유지하며, 32비트 주소 공간 마지막 바이트까지의 유효 요청은 허용한다. 범위를 넘는 요청과 너무 큰 읽기 응답은 거부한다.

GDB packet data 상한은 기존 광고값 1147바이트다. framing/checksum/NUL 공간을 따로 확보하고, 수신 버퍼 끝에 NUL을 쓰지 않는다. checksum의 두 글자를 검증하고 잘못된 packet을 소비하여 다음 재전송을 처리한다. 기존 연속 동일 재전송의 응답 병합을 유지하며 서로 다른 coalesced 요청은 순서대로 처리한다. 응답은 예약 문자를 escape한 실제 전송 길이까지 검사한다. 길이와 escape 규칙은 [RSP 개요](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Overview.html)와 [PacketSize](https://sourceware.org/gdb/current/onlinedocs/gdb.html/General-Query-Packets.html)를 따른다.

Windows socket handle의 폭과 invalid sentinel을 보존한다. 새 연결은 nonblocking으로 읽어 분할 packet이 emulation 실행을 기다리게 하지 않는다. EOF·select 오류·0바이트 송신은 종료로 처리하고 부분 송신은 남은 바이트를 보낸다. 송신 대기와 ACK 재시도에는 상한이 있다. ACK를 기다리는 중 나뉘어 도착한 재전송은 완성한 뒤 확인하고, 다른 요청은 큐에 남긴다. listener 오류는 대기 루프를 종료한다. disconnect는 NoAck·받던 명령·상태를 초기화하고 Winsock startup/cleanup을 맞춘다. [새 연결의 ACK 규칙](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Packet-Acknowledgment.html)과 [Windows select timeout](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-select)을 따른다. debugger 설정의 기본 bind 주소는 유지한다.

## 검증 기록과 한계

LAN은 수정 전 27개 생성 입력 중 16개가 실패했고 수정 후 모두 통과했다. 실제 ENet packet 해제·queue·공개 MP 수신 메서드를 사용하며 socket은 열지 않는다. PCap은 정상 대조를 제외한 6개 묶음이 실패한 뒤 7/7 통과했다. 실제 backend 코드에 library/driver 경계를 대체하며 실제 어댑터를 캡처하지 않는다.

DNS는 정상 대조 1개를 제외한 7개 묶음이 실패했고 그중 헤더·이름 보호 페이지에서 접근 위반을 확인했다. 수정 후 8/8 통과했다. 현재 production 함수 정의를 CMake에서 추출하고 resolver/slirp 입출력만 대체한다. 실제 host DNS 조회 성공을 뜻하지 않는다.

GDB는 invalid hex/checksum의 trap, binary 마지막 바이트·escape 오류, 짧은/넘치는 요청, 응답 용량·부분 송신·EOF/연결 상태를 수정 전에 재현했다. 최대 메모리 응답은 수정 전 접근 위반을 확인했다. 정확히 찬 수신 버퍼의 범위 밖 NUL 쓰기는 정적 코드 결함이며 해당 baseline 검사는 통과했으므로 실행 재현으로 세지 않는다. 수정 후 memory/framing/transport 33개 묶음이 통과했다. 실제 로컬 TCP에서 분할 X 요청·NUL/예약 바이트·M checksum 실패 뒤 m 읽기·미지원 명령·NoAck 종료 뒤 ACK 재접속·detach를 확인했다. XML 전송은 continuation 접두사 공간도 남기도록 chunk 크기를 제한하고, 최대 요청에서 실제 target XML을 대조했다. 실제 ARM GDB/LLDB client나 에뮬레이션 중 양 CPU의 breakpoint/step 검증은 아니다.

분할 재전송은 응답 3회 뒤 연결 종료, listener 오류는 paused Enter의 15초 timeout을 수정 전에 확인했다. 수정 후 두 반례와 관련 GDB 회귀가 통과했다.

최종 Windows frontend 빌드와 CTest 227/227, skip 0, 22.42초를 확인했다. 기존 interpreter·warmed JIT·fastmem과 실제 OpenGL/Compute 출력 회귀도 포함한다. UCRT64 GCC 16.2.0, CMake 4.4.3, Qt 6.11.2, SDL 2.32.10, C23/C++26, 선택적 AVX2/AVX-512와 LTO OFF 구성이다. 배포 EXE/DLL 129개에서 import 누락 0, 개발 도구를 제외한 PATH의 `--help` 종료 0과 공개 계획 17개의 링크·개인 경로 제외 검사를 확인했다. 성능/지연 개선 수치는 측정하지 않았다. 실제 두 PC 게임 참가·교환·재연결, PCap 드라이버/어댑터 실패, DS 클라이언트 DNS, Linux/BSD 실행과 전체 debugger 명령은 남는다. LAN handshake/LocalMP 격리, GDB 레지스터/기타 명령 파서와 주변장치 구현도 후속이다.

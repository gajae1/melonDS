# 1.1.184 — 스케줄러의 반복 탐색과 ARM9 메모리 접근 비용 감소

2026-09-26. 이전 버전은 1.1.183이다. 기본 Windows 배포는 SDL3이며 SDL2 호환 빌드도 유지한다.

스케줄러는 다음 이벤트의 가장 이른 시각을 기억한다. 아직 실행할 이벤트가 없는 구간에서는 이벤트 목록을 다시 훑지 않는다. 이벤트 예약·취소, 리셋, 저장 상태 로드 때 캐시를 갱신하므로 이벤트 순서와 저장 형식은 유지한다. `95591099`.

ARM9 JIT의 느린 메모리 접근 함수는 CPU가 이미 가진 NDS 참조를 사용한다. 접근마다 스레드 로컬 `NDS::Current`를 다시 읽는 비용을 줄인다. CPU 인자가 없는 ARM7 경로는 바뀌지 않는다. `5242de07`.

두 변경은 처음에는 실행 시간 차이가 같은 바이너리끼리의 A/A 변동과 분리되지 않아 보류됐다. 이후 같은 입력의 명령어 실행 수를 서로 다른 Valgrind 계수기(lackey와 callgrind)로 재측정했다. 스케줄러는 Solatorobo에서 약 1.74~1.80%, Black에서 약 2.22~2.32%의 명령어를 줄였다. ARM9 참조 변경은 각각 약 2.17%, 1.15%를 줄였다. 각 변경의 화면·PCM·저장 상태 비교가 같았고, 기존 시간 측정에서 A/A 변동을 넘는 회귀는 관찰하지 않았다.

이 수치는 **명령어 수 감소이며 FPS 향상률이 아니다**. Linux x86-64, 300프레임, 소프트웨어 렌더러, JIT fastmem을 끈 측정이라 특히 ARM9 느린 메모리 경로의 비중을 일반 사용보다 크게 볼 수 있다. 두 수치를 더해 총 성능 향상률로 해석하지 않는다. 재측정 근거는 `local-docs/icount-harness-20260926/result.md`에 있다.

통합 소스의 Windows SDL3 전체 CTest는 기존 `build/dev-184` 실행에서 1043개 통과, 네이티브 표시 관련 3개 비활성이다. 같은 변경의 전체 검사를 로컬에서 반복하지 않고 해당 결과를 재사용했다. 소스 커밋 `dbc4b91fee7f0742862bc7f60445cedebcfd5c1b`의 깨끗한 스냅샷에서 SDL3·SDL2 배포를 각각 빌드했으며 다른 작업자의 `src/teakra/src/test_generator.cpp`는 제외했다.

두 게임의 Software 1배율, 1200프레임 ABBA 헤드리스 비교에서 1.1.183과 1.1.184의 최종 화면·누적 PCM·프레임버퍼 digest가 모두 같았다. 빌드와 병행한 정확성 검사이므로 이 실행 시간으로 성능 향상률을 주장하지 않는다. `local-docs/release-184-20260926/games-software-1x.json`.

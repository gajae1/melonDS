# 1.1.33 — Compute 작업량 분할·그래픽·통신 경계

기준은 1.1.32(`4238ec71f91b40b1c26b85a39cf20183d59dbe22`), 검증일은 2026-09-11이다. GR-06/07/08과 NP-03의 독립 수정을 통합한다. 전체 계획이나 실기 호환성이 완료됐다는 의미는 아니다.

## 변경과 근거

**Compute 작업량:** 실제 binning producer에서 1배율의 전면 사각형 17개가 저장 한도 12,288개를 넘어 13,056개 작업을 만들었다. 3배율의 10개는 69,120개 Z workgroup을 만들며 장치 한도 65,535개를 넘었다. 재현 검사는 잘못된 indirect dispatch를 GPU에 전달하기 전에 중단했다. [OpenGL 4.3 명세](https://registry.khronos.org/OpenGL/specs/gl/glspec43.core.pdf)에 따르면 이 초과는 오류 코드만으로 안전하게 판정할 수 없는 undefined behavior다.

폴리곤의 화면 타일 범위·scanline·edge 수로 작업량을 보수적으로 계산하고, 저장 용량·variant 수·장치 dispatch 한도에 맞춰 순서를 유지한 묶음으로 처리한다. 묶음 사이에는 두 층의 색·깊이·속성, stencil과 연속 shadow-mask 상태를 보존한다. 처음에만 화면을 지우고 마지막에만 안개·가장자리·AA 최종 처리를 한다. 초과 폴리곤이나 프레임을 생략하지 않는다.

**클래식 GL 알파:** VBlank에서 확정된 alpha reference를 선택한 Z/W shader에 전달하고, 텍스처 계산을 마친 fragment alpha에 적용한다. polygon alpha만 검사하면 A5I3의 투명도를 놓치므로 최종 alpha를 비교한다. 기준값과 같은 alpha는 거부하고 alpha test를 끄면 기존 비영점 alpha를 수용한다. 실제 register 쓰기·VBlank·source-A 캡처·guest LDRH로 확인했다.

**텍스처 메모리 끝:** 512KiB 끝을 넘는 direct-color texture를 16개 capture block 배열 밖에서 찾지 않는다. 일반 VRAM과 다른 캡처 bank가 이어진 범위는 하나의 capture layer로 표현할 수 없으므로, 기존 캡처를 RAM에 보존한 뒤 주소 wrap을 지원하는 디코딩 경로를 사용한다. dirty bitfield의 인덱스도 bit 수가 아닌 64비트 word 수로 감싸 텍스처·팔레트 끝 이후의 변경을 추적한다. 이 오류는 실제 캐시 함수에서 RAM의 첫 바이트만 바꾼 대조로 수정 전 실패·수정 후 통과를 확인했다.

**통신 timestamp:** LocalMP와 LAN의 reply 비교에서 요청 timestamp가 0~31일 때 `timestamp - 32`가 unsigned 범위를 돌아 정상 응답을 거부하던 문제를 고친다. 응답 시각이 요청보다 이전일 때만 차를 구하며, 정확히 32μs 이전 응답은 수용하고 33μs 이전 응답은 거부한다. 이 값은 guest 시각이며 host의 수신 대기 시간이나 자동조절 값이 아니다.

## 검증

Compute 초과 반례·정상 대조·685개 폴리곤을 확인했다. 마지막 폴리곤은 앞의 폴리곤과 다른 색으로 출력 누락을 판별한다. 생성 장면을 한 묶음과 여러 묶음으로 처리했을 때 Z/W buffer·shadow/stencil·반투명 polygon ID·fog/AA/edge의 최종 픽셀이 일치했다. 기존 GPU 32개 검사도 통과했다.

LocalMP의 실제 큐에서 timestamp 0의 정상·빈 AID0 응답, age 0/32/33과 미래 응답을 대조했다. 실제 ENet 루프백도 시작 시각 응답·경계·이후 정상 통신을 확인했다. LAN의 수신되지 않은 unsequenced 패킷은 전송 유실과 stale 거부를 구분하지 못하므로 age 33의 결정적 증거는 LocalMP 큐에 둔다.

클래식 GL 알파 32개 조합은 변경 전 12개가 실패했고 수정 후 모두 통과했다. 128/256 폭·1/2배율의 메모리 끝 전후 캡처와 이후 guest 쓰기 재사용을 software·클래식 GL·Compute에서 대조했다. 통합한 새 GPU CTest 11/11이 통과했다.

최종 Windows x64 Release 전체 빌드가 성공했고 CTest **619/619 통과·실패 0·건너뜀 0**, 병렬도 2에서 **79.74초**였다. 최종 application object로 실행한 생성 guest의 Qt 설정/Cancel/실패/재시도와 guest 상태·실행 진행 보존도 통과했다. 의도적으로 주입한 오류는 복구 검사의 입력이다.

배포본 129개 PE의 누락 import가 없고 깨끗한 PATH의 도움말 실행이 성공했다. 공개 문서 45개의 내부 링크와 개인 경로 검사를 통과했다. 커밋된 소스와 검증한 EXE·ZIP의 해시는 배포 manifest에 기록한다.

## 호환성과 남은 조건

- 일반 게임 저장·설정·LAN v1 wire 형식·상태 writer 14.2는 유지한다. 새 writer를 지원하지 않는 구버전의 역방향 상태 읽기와 Android의 별도 상태 형식은 별도 범위다.
- Compute 중간 상태 저장은 배율을 적용한 픽셀당 4바이트(1배율 약 192KiB)를 추가한다. 경계 계산과 여러 묶음의 처리 비용도 있다. 안정성 수정이며 성능 향상으로 발표하지 않는다. 큰 장면·고배율의 실제 게임 성능, 다른 GPU/driver 검증은 남는다.
- 메모리를 넘는 캡처 텍스처의 fallback은 기존 전체 캡처를 RAM으로 동기화하고 native texture 해상도로 디코딩한다. 같은 프레임의 다른 캡처도 고해상도 참조를 잃을 수 있다. 이 경로의 고해상도 품질·성능 동등성을 주장하지 않으며 정상 범위의 빠른 capture 경로는 유지한다.
- 생성 renderer 입력의 출력 보존은 DS 실기·모든 geometry 명령·모든 게임의 정확성 증거가 아니다. Android·native ARM64·Linux/macOS·물리 장치·장기 게임 수락은 열린 상태다.
- 네트워크 자동조절은 아직 도입하지 않았다. 기존 기본값과 구버전 호환성을 유지하며 계측·늦은 peer·취소·시각 wrap을 후속으로 진행한다. 실제 두 PC·구버전 혼합 다자간·원본 client의 첫 UDP 유실은 별도 수락 조건이다.
- Compute에서 blending을 끈 정상 반투명 출력이 software와 다른 추가 관측은 GR-08 후속 반례로 남긴다. 이번 클래식 GL 알파 수정으로 Compute의 모든 alpha/blend 의미까지 완료 처리하지 않는다.
- 다음 독립 블록은 JIT/ISA의 근거가 있는 반례와 빌드 source/EXE 신원 결속이다. 기존 외부 수락을 로컬 테스트 개수로 완료 처리하지 않는다.

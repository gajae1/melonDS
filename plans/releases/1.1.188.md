# 1.1.188 — Vulkan GPU 2D 완성도 보강(기본 비활성)

2026-09-27. 릴리스 소스 커밋은 `3375b547e8a3d1ef914ceee24c046f1e120e1422`이며 구현 커밋은 `237bc703`, `c63188fa`, `e9d0e618`이다. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

1.1.187의 native 2D 기반에 남아 있던 enhanced OBJ와 배율 변경 수명주기를 채우고, 설정으로만 켤 수 있는 GPU 2D 선택지를 추가했다. 기본값은 꺼져 있고 프런트엔드 옵션도 없으므로 기본 렌더러 동작은 1.1.187과 같다.

- enhanced OBJ: 확대 캡처된 bitmap OBJ를 GPU 2D가 확대 해상도로 합성한다(`Native2D/HiresOBJ.glsl`). OBJ 디코드가 후보 출처를 기록하고 큐가 줄마다 OBJ 출처 페이지를 남겨 이력 바인딩으로 확대 이미지를 찾는다.
- 배율 변경: 표시 배율이 바뀌면 native 2D 상태를 새 배율로 옮기고(`MigrateNative2DScale`) 확대 캡처 이력을 버린 뒤 슬롯을 다시 채운다. 장치 오류가 나면 native 2D를 끄고 CPU 2D로 되돌아간다.
- 선택 설정: `RendererSettings::VulkanNative2D`(기본 false)와 `DisableNative2D`, `Native2DActive()`를 추가했다. 테스트용 ROMSmoke는 `MELONDS_SMOKE_GPU2D=1`로 켤 수 있다.

## 측정과 기본값 결정

실제 게임 3종에서 GPU 2D는 CPU 2D와 같은 최종 화면을 만들었지만 모든 배율에서 프레임당 시간이 더 길었다. 그래서 기본값과 프런트엔드 노출을 바꾸지 않았다. 측정 조건은 RTX 5080 Vulkan, 부팅 후 1200프레임 무제한 실행, 앞 240프레임 제외, 각 1회다.

임시 계측(되돌림)에서 CPU 2D의 줄 그리기와 스프라이트 비용은 프레임당 약 0.3ms였다. GPU 2D는 스프라이트 스냅샷 0.21ms, 줄 기록 0.47ms, 제출·대기 0.48~1.32ms가 들었다. 줄마다 상태를 복사하는 비용만으로 최적화된 CPU 렌더러를 넘는다. 배율 2 결과와 원시 행은 `local-docs/gpu2d-activation-20260927/`에 있다.

## 한계와 다음 단계

GPU 2D를 켜면 느려지므로 성능 개선으로 집계하지 않는다. 다시 시도하려면 줄별 페이지 스냅샷 대신 dirty 범위만 프레임당 한 번 갱신하는 장치 VRAM 미러와, 다음 프레임과 겹치는 비동기 제출이 필요하다. 목표 기기에서 CPU 작업 약 0.3ms/프레임보다 빨라야 활성화를 검토한다. CoD의 GPU 2D p95 급증 원인은 아직 밝히지 못했고, 내장 GPU에서는 벤치마크하지 않았다.

# 1.1.183 — Vulkan 렌더러의 표시 경로 고정, GL 빨리 감기 표시 제한, 소프트웨어 3D 스레드 경쟁 수정

2026-09-26. 이전 버전은 1.1.182이다. 기본 Windows 배포는 SDL3이고, SDL2 빌드는 `-sdl2` 접미사 ZIP으로 함께 낸다.

**Vulkan 렌더러는 Vulkan 표시를 쓴다(Windows).** Vulkan 렌더러와 OpenGL 표시를 같이 고르면 내부 배율 2배 이상에서 매 프레임 GPU 이미지를 CPU로 기다려 읽고 다시 GL로 올렸다. 이제 Vulkan 프레젠터가 빌드된 곳에서는 Vulkan 렌더러가 항상 1.1.182의 Vulkan 직접 표시를 쓴다. 저장된 `Screen.UseGL`/`Screen.UseVulkan` 값은 바꾸지 않아서 다른 렌더러로 돌아가면 그대로 적용되고, Vulkan 표시를 만들 수 없으면 이전처럼 기본 표시로 돌아간다. 비디오 설정 창은 실제로 쓰이는 표시를 보여 준다. 판단은 `RendererImpliesVulkanDisplay` 한 곳에 있다. `local-docs/vk-gl-route-20260926/`.

**OpenGL 표시의 빨리 감기 제한.** 수직동기가 꺼진 상태(빨리 감기, FPS 제한 해제)에서 OpenGL 표시는 에뮬레이션 프레임마다 창 전체를 지우고 그리고 넘겼다. 화면은 주사율만큼만 보여 주므로 나머지는 버려지는 작업이고, 약한 내장 그래픽에서 창이 클수록 빨리 감기 속도를 깎았다. 이제 에뮬레이션이 도는 동안 주사율 간격마다 최대 한 번만 넘긴다. 수직동기가 켜진 일반 속도, 일시정지, 프레임 단위 진행은 전처럼 매번 넘긴다. 주사율은 GUI 스레드에서 창 정보와 함께 읽는다. 새 `gl-presentation-ff-throttle` 검사는 실제 `drawScreen` 본문으로 넘긴 횟수를 센다(수직동기 8/8, 간격 0에서 13프레임 중 1, 일시정지 3/3, 일반 속도 20/20). 실제 빨리 감기 속도는 창을 띄울 수 없어 재지 않았다. `local-docs/gl-ff-throttle-20260926/`.

**소프트웨어 3D 스레드 경쟁 수정.** 스레드 모드(앱 기본값)에서 저장 상태를 불러오면 `GPU::PostSavestate`와 `NDS::DoSavestate`가 프레임을 두 번 제출한다. 첫 프레임이 올려 두고 아무도 읽지 않은 줄 신호가 남아서, 2D 엔진이 두 번째 렌더가 시작되기 전의 3D 줄을 읽을 수 있었다. 이제 이전 렌더가 끝난 뒤 다음 렌더를 제출하기 전에 줄 신호를 비운다. 새 `software-thread-stale` 검사는 수정 전 HEAD에서 실패하고 수정 후 10회 반복 모두 통과한다. `local-docs/soft3d-stale-permits-20260926/`.

**Sinc 반올림.** Sinc 모드는 음성과 출력 샘플마다 `std::lround`로 ucrtbase를 호출했다(프로파일에서 Black 모드 6 프레임의 약 3.4%). 인라인 반올림은 2^22 미만의 모든 float에서 같은 값을 내며(전수 비교 불일치 0), 모드 0~6 PCM이 바이트 동일하다. 세 번의 측정 캠페인에서 회귀 없이 1~3.5% 빨랐지만, 두 칸은 A/A 흔들림 안이었다. `local-docs/sinc-ucrt-20260926/`.

같은 라운드에서 채택하지 않은 것: 소프트웨어 3D 두 구간 병렬 래스터화(2코어·스레드 모드에서 Solatorobo 28.3% 느려짐, `soft3d-parallel-20260926`), Sinc 인접 위상 내적 합치기(0.7~1.5%, 회차별 잡음 3~10% 이하, `sinc-fast-voice-20260926`). 1.1.182 프로파일은 `local-docs/profile-182-20260926/hotspots.md`에 있다.

비공개 게임 두 개의 헤드리스 Software 1200프레임 ABBA 실행에서 1.1.182와 1.1.183의 최종 화면·누적 PCM·프레임버퍼 digest가 같았다.

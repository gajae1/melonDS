# 1.1.166 — ARM9 JIT 메모리 타이밍 보정

2026-09-23. Windows UCRT64 Release. 이전 버전 1.1.165.

ARM9 JIT가 블록을 처음 추적할 때 관찰한 데이터 접근 시간을 네이티브 코드에 고정해 두어, 같은 코드의 레지스터 주소가 DTCM에서 RAM으로 바뀌면 재개 시 실행 타이밍이 달라졌다. 단일 접근과 다중 레지스터 전송에서 현재 주소의 타이밍을 확인하고, 달라졌으면 해당 명령을 인터프리터로 실행한다. `LDM`이 PC를 읽을 때는 인터프리터와 같이 분기 대상의 파이프라인을 채운 뒤의 코드 타이밍으로 사이클을 보정한다.

새 회귀 사례는 DTCM에서 추적한 블록을 RAM 주소로 재사용할 때의 레지스터·PC·CPSR·사이클과, PC를 읽는 `LDM`의 인터프리터/네이티브 타이밍을 비교한다. `LDM` 사례는 수정 전 4 대 20사이클로 실패했고 수정 후 일치했다. 관련 JIT·fastmem·MPU 테스트 15개가 통과했다. 별도 읽기 전용 코드 검토에서 확정된 회귀는 없었다.

사설 Solatorobo 실험에서는 동일한 JIT 바이너리로 12,000프레임 연속 실행한 최종 PPM과 6,000프레임 저장 상태를 불러와 이어 실행한 최종 PPM이 바이트 단위로 일치했다(256×384, 다른 픽셀 0개). 이전 1.1.165 JIT의 같은 비교는 하단 화면의 1,594픽셀이 달랐다. 두 실행의 ROMSmoke 종료 코드는 모두 0이고, ROM·입력·기존 save·작업 중인 `src/teakra/src/test_generator.cpp`는 보존됐다. 사설 원시 기록은 `local-docs/bv17-jit-current-long-20260923/`에 있다.

6,001프레임의 JIT 전체 저장 상태는 캐시 이력에 따라 여전히 다르다. 최종 화면 일치가 전체 게스트 상태 일치나 모든 게임의 재개 정확성을 증명하지는 않는다. Qt 화면의 실제 픽셀·오디오 장치·물리 장치·모든 중간 프레임도 별도 수락 대상이다.

## 구현 — Vulkan GPU 어댑터 선택

Vulkan 렌더러와 Vulkan 표시의 GPU를 사용자가 고를 수 있다. Device::Enumerate가 compute 자원 한도와 형식 지원 검사를 통과한 Vulkan GPU 목록을 UUID로 돌려주고, Device::Create(error, preferred)가 명시 선택을 우선한다. 선택이 비어 있으면 첫 번째 적격 기기 대신 discrete를 선호한다. 설정창에 그래픽 카드 콤보를 추가했다(Automatic + 기기 목록 + 사용 불가 이전 선택 보존). Video.GPU 설정 문자열로 저장되고, 변경 시 렌더러와 표시 surface를 모두 재생성해 presenter가 다른 GPU를 계속 쓰는 일을 막는다. 취소하면 이전 값으로 복원하고, 활성 렌더 GPU 이름을 상태 표시에 노출한다. OpenGL 표시·렌더링은 운영체제 선택을 그대로 쓰며, 선택한 GPU를 못 쓰면 기존 규칙대로 소프트웨어/native 표시로 떨어진다. guest VRAM·savestate 형식은 그대로다.

이 기기(RTX 5080 + AMD iGPU)에서 제품 auto는 RTX 5080을 선택하고, 차등 검사는 이제 GL 참조 컨텍스트의 GL_RENDERER와 이름이 맞는 Vulkan 기기를 명시 선택해 같은 기기끼리 비교한다(이름 불일치·열거 실패 시 기존 auto 유지).

## 구현 — GL compute strict 드라이버 호환 수정

Vulkan 어댑터 선택 검증 중 이 기기의 OpenGL 기본 기기가 NVIDIA에서 AMD로 바뀌면서 GL compute 검사 13개가 실패했고, 원인은 제품 이식성 버그였다. GL compute 래스터라이즈 셰이더는 4개 uniform을 고정 layout location(0~3)으로 선언하지만 NoTexture·ShadowMask 빌드는 texture 3개 uniform을 전혀 참조하지 않아 비활성 uniform이 된다. RenderBatch가 모든 variant에 이 위치를 호출했고, NVIDIA는 무시하지만 strict 드라이버는 GL_INVALID_OPERATION을 내고, 남은 오류 상태가 다음 SetRenderSettings의 CheckError를 실패시켜 스케일·hires 설정 적용이 모두 중단됐다.

수정은 texture uniform 호출을 실제로 그 uniform을 사용하는 texture 래스터라이저 프로그램(Texture!=0 && BlendMode!=4)으로 한정하는 것이다. CurVariant는 모든 래스터라이즈 빌드에서 참조되므로 그대로 둔다. 이로써 GL compute가 기기의 OpenGL 기본 기기에 따라 동작한다. vulkan-native-presentation 검사는 합성 데스크톱을 읽는 검사로 병렬 GPU 검사와 경합할 수 있어 RUN_SERIAL 격리를 추가했다.

# 1.1.04 — 상태 로드 실패 복원과 저장 동기화

상태: 아래 증분 구현·Windows 로컬 회귀 완료(2026-09-10). 기준 소스: 1.1.03. 실행 순서에 따라 상태 복원과 저장 worker의 좁은 증분을 먼저 반영했다.

## 이번 증분의 5페이즈

1. **반례:** 실제 코어로 만든 상태의 마지막 섹션을 손상시키고 앞 RAM·CPU 적용 뒤 실패를 재현한다. undo 실패, 복원 자체 실패, worker flush 중 경로 변경을 별도 입력으로 확인한다.
2. **최소 수정:** load·undo에 이전 상태의 백업과 실패 시 복원을 연결한다. 파일 길이·전체 읽기를 확인하고 기존 mutex로 저장 상태의 소유권을 일치시킨다.
3. **통합:** 성공·복원 가능한 실패·복원 실패를 Qt 메시지와 UI까지 전달한다. 복원 실패 시 실행·프레임 진행·상태 저장을 차단하고 성공한 재부팅·reset으로 복구한다. 버전은 1.1.04로 올린다.
4. **검증:** 수정 전 반례와 수정 후 관련 회귀, Windows frontend 빌드 및 최종 전체 검사를 기록한다. 실제 게임·물리 장치 수락은 합성 검사와 구분한다.
5. **배포:** 실행 패키지·소스·공개 계획을 같은 커밋으로 연결하고 개인 자료를 제외한다. 기존 실행 환경과 저장 파일을 보존한다.

## 동작

파일 로드 전에 완전한 백업을 만든다. 후반 장치 섹션에서 실패하거나 로드 중 할당 예외가 발생하면 백업을 새 reader로 읽어 복원한다. 실패한 로드는 기존 undo 백업을 교체하지 않는다. 성공한 undo는 한 번 소비하며 실패한 undo는 현재 상태를 복구하고 재시도할 수 있다.

복원마저 실패하면 코어와 프런트엔드를 멈춘다. 이미 대기 중인 재개·프레임 진행·상태 읽기/쓰기 요청도 차단한다. UI에서 게임을 다시 열어 계속할 수 있으며, 코드의 명시적 reset이나 성공한 부팅도 정지 상태를 해제한다. 실패한 부팅은 해제하지 않는다.

상태를 적용하는 동안 기존 audioDisable/audioEnable 경로로 오디오·마이크 callback을 멈추고, 원래 실행 중이었던 정상 세션만 다시 활성화한다. 이 조치는 이미 출력된 소리·화면이나 외부 매체·네트워크 부작용을 되돌리지 않는다.

SaveManager의 경로·두 버퍼·길이·버전·debounce 시각은 한 mutex로 보호한다. worker의 쓰기와 명시적 flush는 같은 잠금 내부 함수를 공유하고, RAII로 조기 반환에서도 잠금을 해제한다. 같은 게임의 경로 이동과 펌웨어 reload의 기존 의미를 유지한다.

## 검증

| 검사 | 결과 |
|---|---|
| load·undo·읽기·할당 오류 | 11개 합성 사례 통과. 실패 후 전체 직렬화 상태와 다음 프레임을 기준 결과와 비교 |
| warmed JIT·fastmem 복원 | 2개 변형 통과. 변경된 명령이 포함된 상태 적용 실패 뒤 기존 코드와 다음 프레임 복원 |
| 실제 Qt 메시지 dispatcher | 성공·실패 전달, paused 상태 유지, 복원 실패 뒤 대기 요청 차단, 성공/실패 boot·reset 경계 통과 |
| 실제 저장 worker·Qt 파일 | 기존 4개 쓰기/재시도와 경로 잠금·부분 reload·버퍼 크기 변경 3개 검사 통과 |
| Windows frontend Release | 빌드 성공. 기존 Qt/toml11 deprecation 및 CMake 정책 경고는 남아 있음 |
| 최종 전체 회귀 | **74/74 통과, skip 0**, 13.39초. 실제 OpenGL/Compute context 회귀 포함 |
| 배포 실행 환경 | EXE·DLL·plugin 129개 import 검사에서 미해결 0, 독립 PATH의 `--help` 종료 코드 0 |

구성: Windows x64, GCC 16.2.0, CMake 4.4.3, Qt 6.11.2, SDL 2.32.10, C23/C++26. JIT·OpenGL·AVX-512 커널 ON, LTO OFF. [검증 방법](../Validation.md)의 기존 개발 폴더를 사용했다. GPU 회귀 통과는 GPU 상태의 모든 실패 복원 경로를 검증했다는 뜻이 아니다.

수정 전에는 후반 섹션·장치 오류·undo 오류·복원 실패 정지·JIT/fastmem 복원의 6개 반례가 실패했다. 파일 헤더·짧은 읽기·읽기 오류·백업 오류·정상 load/undo 대조는 통과했다. 저장 worker 검사에서는 잠금 유지 중 SetPath 완료가 관측되었으며 reload·버퍼 크기 변경 대조는 통과했다.

## 수락 한계와 복구

- 합성 ARM 루프와 실제 코어·직렬화·메시지 dispatcher·Qt 파일을 사용한다. 사용자 게임, DSi NAND/DSP 장치 상태와 물리 오디오·마이크·느린 저장장치의 장기 실행은 이번 증분의 수락 증거가 아니다.
- 할당 예외와 과대 길이는 실패 주입으로 확인한다. 실제 수 GiB 파일이나 물리 메모리 고갈을 재현한 것은 아니다.
- 저장 상태 형식과 저장 파일 이름을 변경하지 않는다. 문제 발생 시 보관한 이전 실행 파일로 되돌릴 수 있다. 저장 데이터를 삭제하거나 자동 이관하지 않는다.
- FS-06의 종료 시 지속 쓰기 실패 문제는 남아 있으며 이 증분을 해당 문제의 해결로 기록하지 않는다. 성능 향상 수치도 주장하지 않는다.

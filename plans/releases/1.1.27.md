# 1.1.27 — software 3D 대기·NDMA 정지·DSi Wi-Fi 응답

기준 1.1.26, 검증일 2026-09-10. GR-13, AD-16, NP-08의 독립 반례를 함께 수정했다. 책임 버전 1.1.27의 software 2D 성능 과제와 공개 전체 계획은 유지한다.

## 5페이즈

1. **재현:** 렌더 worker의 시작/완료 경계, packed geometry 명령의 FIFO 포화, DSi WMI 거부·연결 응답을 정상 흐름과 대조했다.
2. **수정:** software 3D는 부모가, NDMA와 Wi-Fi는 별도 작업 공간의 작성자가 맡았다. 기존 동기화·DMA 정지·WMI 이벤트 경로를 사용했다.
3. **통합:** GPU 재설정 전에 렌더 완료를 기다리며, NDMA 정지를 기존 GX stall 호출과 연결하고, Wi-Fi 이벤트 본문·연결 상태·IRQ 순서를 맞췄다.
4. **검증:** 각 반례와 정상·재시도·상태 복원을 확인하고 최종 Windows 빌드 및 전체 CTest를 한 번 실행했다. 통합 Qt의 렌더러 교체와 종료도 확인했다.
5. **배포:** 검증된 증분을 Windows/source 패키지와 버전에 반영한다. 실기·다른 플랫폼·게임·장기 수락 및 미구현 장치 타이밍은 남긴다.

## 변경과 근거

**Software 3D:** worker가 작업을 받았지만 아직 렌더 중이라는 flag를 쓰지 않은 순간에 저장·재설정이 먼저 진행됐다. 반대로 완료 신호를 소비한 직후에는 늦게 지워지는 flag 때문에 같은 완료를 다시 기다렸다. 호출 측이 작업 제출부터 완료 신호 소비까지 대기를 책임지도록 바꾸고, reset·중단·모드 전환 전에 해당 작업을 끝낸다. GPU reset은 register·polygon·VRAM 변경보다 먼저 기다린다. 기존 세마포어를 유지하며 `FrameIdentical`도 초기화한다. [Qt 세마포어 계약](https://doc.qt.io/qt-6/qsemaphore.html)

**NDMA:** packed geometry 명령이 FIFO를 채워도 빈 `StallNDMAs`가 실행 중인 ARM9 채널을 멈추지 않았다. 이로 인해 뒤의 명령이 유실되고 완료 IRQ가 먼저 발생했다. 네 ARM9 채널의 기존 `StallIfRunning`을 연결하고 reset에서 세 상태 flag를 초기화했다. FIFO 소비 후 재개·우선순위는 기존 경로를 사용한다. 물리 지연이나 새 arbitration 규칙을 만들지 않았다. [GBATEK geometry FIFO](https://problemkaputt.de/gbatek.htm#ds3dgeometrycommands), [DSi NDMA](https://problemkaputt.de/gbatek.htm#dsinewdmandma)

**DSi Wi-Fi:** 기존에 거부하던 CONNECT 매개변수에는 CMDERROR/INVALID_PARAM을 응답하고 이전 연결을 유지한다. 정의되지 않은 scan type도 오류를 알리며 진행 중인 scan을 보존한다. 정상 연결 이벤트는 필요한 association 본문 길이를 선언하면서 실제로는 한 byte만 보내던 결함을 수정했다. 기존 가상 AP의 SSID·rate·channel과 요청/응답의 필수 header를 담아 선언 길이와 실제 본문을 맞췄다. 연결 상태를 먼저 반영한 뒤 성공 이벤트를 공개한다. [Atheros WMI 형식](https://github.com/torvalds/linux/blob/v2.6.39/drivers/staging/ath6kl/include/common/wmi.h), [DSi WMI header](https://github.com/devkitPro/calico/blob/81b75e314d57ed1784545e28554e567f26f572f1/include/calico/dev/ar6k/wmi.h), [association 길이 소비자](https://github.com/torvalds/linux/blob/v6.12/drivers/net/wireless/ath/ath6kl/cfg80211.c)

## 검증 결과

Windows x64 Release 전체 빌드와 최종 CTest **509/509, 실패 0, skip 0**이 통과했다(42.44초, 병렬 2). 전체 검사는 반복하지 않았다.

최종 빌드의 객체 파일을 연결한 전체 Qt 검사도 종료 코드 0으로 통과했다. 생성 DS 실행에서 shader·limit·표시 실패, software/native 전환, 일시정지 중 Cancel·재시도와 새 context의 capability 갱신을 확인했고 guest RAM·진행과 정상 종료를 보존했다. 기존 검증 진입점의 오류 주입과 dummy audio를 사용한 결과이며, 배포 실행 파일의 실제 게임이나 물리 driver 장애 수락은 아니다.

- Software fixture는 실제 core/rasterizer와 기존 host 동기화 구현을 사용한다. 수정 전 네 경계가 실패했고 정상 대조는 통과했다. 수정 후 시작 전·완료 직후·abort·reset과 렌더 중 모드 해제/재시작, scalar/threaded 전체 scanline 픽셀, 반복 frame·실제 NDS 저장/복원이 통과했다. 결정적인 host 실행 순서를 사용하며 물리 GPU나 ARM 메모리 순서 수락은 아니다.
- NDMA는 실제 MMIO·DMA·GPU·전체 상태 저장을 사용한다. immediate 전송의 마지막 PUSH 유실과 조기 IRQ, GX 시작 모드의 burst 중 조기 정지를 수정 전 재현했다. 현재 live/복원 양쪽에서 마지막 명령·완료 IRQ·경쟁 채널을 보존한다. ARM9/7 정상 우선순위·즉시/VBlank 시작·마지막 짧은 block도 확인했다. 검사 slice는 관찰용 예산이며 하드웨어 cycle 값이 아니다.
- Wi-Fi는 실제 DSi SDIO CMD52·HTC/WMI mailbox·ARM7 IRQ를 사용한다. 네 수정 전 반례와 수정 후 오류→credit 순서, 진행 중 연결/scan 보존, 명시적 disconnect/reconnect, 생성 Ethernet payload와 정상 association 본문을 확인했다. host 네트워크는 메모리 대역이고 guest CPU는 실행하지 않는다.

## 범위와 남은 조건

새 제품 소스 파일은 없다. NDMA는 기존 장치 시험 파일을 확장했고 software/Wi-Fi 검증 파일 세 개와 이 기록만 추가했다. Software 3D와 DSi Wi-Fi의 해당 소스는 [공식 기준 revision](https://github.com/melonDS-emu/melonDS/commit/e07688114057f742dde332a247f43799607f080b)과 1.1.26에서 동일했다. 빈 NDMA 정지 경로는 upstream의 2019년 구현에서 이어진 것이다. 이를 포크 변경 때문에 새로 생긴 결함으로 분류하지 않는다.

GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26과 기존 JIT/ISA 구성을 유지한다. 실행 파일은 `1.1.27-melonDS.exe`, 패키지는 `1.1.27-melonDS-windows-x64.zip`과 `1.1.27-melonDS-source.zip`이다. 게임·firmware·NAND·설정·저장 자료는 포함하지 않는다.

GR-13의 aborted scanline 픽셀 정확도·실제 ARM·장기 게임 수락은 남는다. AD-15의 AES 즉시 처리/SD 고정 지연은 바꾸지 않았고, AD-16의 timer 시작·subblock 지연·round-robin·실기 bus 우선순위도 미완성이다. NP-08은 부분 구현이며 retail guest의 CMDERROR 처리·실제 인증/host 소실·DS retry·CMD53/DMA·혼잡/상태 복원·channel/SSID/scan 취소 정책과 실기 게임 검증이 남는다. 공개 Calico snapshot은 CMDERROR를 명시적으로 처리하지 않으므로 오류 전달 성공을 guest의 자동 복구로 보지 않는다. 성능·전력·물리 지연 개선량은 주장하지 않는다.

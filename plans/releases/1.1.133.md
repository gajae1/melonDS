# 1.1.133 — Vulkan의 캡처 후 VRAM 직접 표시 디테일

2026-09-16. 메인 `F:/melonDS`의 기존 1.1.132 변경을 보존하고 이어서 작업했다.
이전 고배율 검사는 직접 3D 표시를 중심으로 했으며, 캡처 후 표시의 고해상도 보존까지 증명하지 못했다.

## 재현과 범위

합성 입력에서 3배 3D를 bank B에 캡처한 뒤 LCDC VRAM 직접 표시 모드로 출력했다.
수정 전에는 `scaled display only stretches native pixels`로 실패했다.
고해상도 3D 결과가 존재해도 native RGB555 캡처로 돌아오면서 표시 디테일이 사라지는 경로다.
특정 사용자 게임/장면을 직접 실행해 같은 원인으로 확정한 결과는 아니다.

## 구현

기존 native 캡처 함수는 그대로 VRAM에 한 번 기록한다. 별도의 표시용 RGB555 캡처 사본만 보관한다.
GPU의 기존 캡처 provenance가 무효화되는 지점에 표시 사본 폐기 통지를 연결한다.
캡처를 포함한 bank의 CPU/DMA 쓰기·겹치는 캡처 교체·전체 캡처 무효화가 지난 표시 데이터를 되살리지 않도록 한다.
캡처 줄 전체를 준비한 뒤 기록하므로 source B와 destination이 같은 bank인 경우도 준비 중 데이터를 덮지 않는다.
VRAM 직접 표시는 해당 줄의 새 캡처 기록보다 먼저 준비하고, master brightness는 표시 단계에서 적용한다.
동일 배율·256폭의 사본은 연속 메모리로 읽어 subpixel마다 provenance 조회와 좌표 나눗셈을 하지 않는다.
1배 캡처, reset/stop 및 무효화는 오래된 향상 사본을 버린다. allocation 실패는 native 표시로 돌아간다.

이는 표시 향상이며 guest가 읽는 VRAM·캡처 포맷·DSP/CPU 명령·셰이더 수식 변경이 아니다.
사본은 RAM에만 있으며 파일을 만들지 않는다. 고배율에서는 표시 사본과 임시 줄 메모리 비용이 추가된다.

## 남은 경로와 주의점

- 캡처를 bitmap BG/OBJ로 읽거나 3D texture로 다시 사용하는 경로는 여전히 native 데이터를 사용한다.
- 따라서 모든 게임에서 OpenGL과 같은 고해상도 결과를 보장하지 않는다. 특히 두 화면 3D와 후처리 장면은 후속이다.
- `ScreenPanelNative`는 draw와 paint 사이에 raw framebuffer 주소를 보관한다. 배율 전환 시 오래된 주소를 쓸 가능성을 검토했지만, 관련 수정 요청이 차단되어 이번에 고치지 못했다. 사용자 종료 현상의 직접 원인도 아직 확정하지 않았다.
- 전체 GPU 2D/capture·직접 GPU 표시·실제 게임 FPS·다른 GPU/OS·DSi 실기 수락은 별도다.

## 실제 실행 검증

메인 Windows 빌드의 전체 기본 타깃이 성공했고 앱 도움말은 `melonDS 1.1.133`이다.
확인한 장치는 NVIDIA GeForce RTX 5080, 설치 드라이버 610.88이다. 드라이버를 갱신한 것은 아니다.
전체 등록 CTest **969/969, 실패0·skip0, 107.44초**를 확인했다.
새 캡처 표시 검사는 2/3/5/8/16배에서 실제 subpixel 차이, native 원점 픽셀 일치, 전체 capture 무효화 후 native 복귀를 검사한다.
기존 Vulkan 1x/2x/3x·guest capture·texture 재사용·save/load와 GL·CPU·오디오 등록 회귀도 포함된다.
이것은 모든 게임·실기·드라이버의 정확성을 인증하는 결과가 아니다. 사용자 장면과 강제 종료의 동일성을 확정하지 않았다.
별도의 CPU 쓰기/alias 확장 시험 작성 요청은 도구에서 차단돼 새 검사의 수락 범위에 포함하지 않는다.

성능 개선율은 측정하지 않았다. 이 변경은 먼저 표시 디테일의 누락을 해결하며, 표시 사본의 RAM 비용이 추가된다.
앱 pipeline cache 정책은 바꾸지 않았고 디스크 cache 파일도 추가하지 않는다.
원본 실패·최종 빌드·JUnit은 `F:/melonDS/build/evidence/display-1.1.133/`에 보존한다.
Actions·개인 ROM/BIOS/NAND·다른 작업트리는 사용하거나 변경하지 않았다.

## 최종 재검증과 미해결 반례

Native 표시의 기존 paint 함수를 추출해 실제 Qt QImage로 시험했다.
화면 게시 뒤 renderer를2배 크기로 바꾸자 `paint consumed retired framebuffer at 2x`로 실패했다.
이는 메모리를 실제로 해제해서 충돌시키는 시험이 아니라, 더 이상 유효한 게시본이 아닌 주소를 사용한다는 반례다.
제품 수정 요청이 차단되어 Screen.cpp는 변경하지 않았다. 사용자 앱 종료와 동일 원인인지는 아직 확정하지 않았다.
시험 코드와 CMake 조각은 `unapplied-native-lifetime/`, 실패 로그는 `native-lifetime-red.log`에 보존했다.
미해결 반례를 기본 통과 집계에 포함하지 않았다. 테스트를 완화해 통과시킨 것이 아니며 이 결함은 계속 열려 있다.

해당 임시 검사 등록을 분리한 뒤 전체 기본 빌드와 등록 검사를 다시 실행했다.
최종 **969/969, 실패0·skip0,103.51초**다. 이는 Native 수명 반례의 해결이나 모든 게임의 정확성을 의미하지 않는다.
`final-build.log`, `final-tests.log`, `final-tests.xml`이 마지막 전달본의 근거다.
CPU 쓰기·alias의 추가 확장 검사는 작성 요청이 차단돼 새 검증 범위에 포함하지 않았다.

# 1.1.128 — Vulkan 1~16배 표시와 배치 자원 제한

2026-09-16. 제품 기준 `c80adcd1`(1.1.127). 중단 전에 작성된 배율 확장 작업을 실제 소스·빌드·실행 로그와 대조해 이어받았다.
관련 과제는 D-004 / GR-15, GR-14, BV-04/10이다. 전체 계획 완료나 실기 정확성 승격을 의미하지 않는다.

## 페이즈 1 — 재현·범위

OpenGL과 같은 1~16배를 Vulkan에서도 선택하고, 기존 확대 표시·native capture 분리를 유지한다.
중단 전 로그에는 4배 요청과 1~16배 설정 검사가 기존 구현에서 거절된 RED 결과가 남아 있다.
이번에는 시작 시 변경 파일 20개의 SHA-256을 보존했다. 타인의 작업트리·ROM·BIOS·NAND·저장 파일을 사용하거나 변경하지 않았다.

## 페이즈 2 — 핵심 구현

`ComputeShader::VulkanMaxScale`을 16으로 지정하고 셰이더 내장·export·설정 검증·표시 scanline 용량을 확장했다.
배율 1~4는 8×8, 5~8은 16×16, 9~16은 32×32 tile을 사용한다. 마지막 구간의 coarse Y=6, clear local size=48을 dispatch에 반영한다.
32개 variant × 16개 배율, 총 512개 SPIR-V를 빌드 시 내장한다. 기존 1~3배 셰이더 96개는 이전 해시와 전부 일치한다.
`ComputeResources`가 이미지·storage/texel/uniform 범위·push constant·local workgroup·직접/간접 dispatch 제한을 할당 전에 검사한다.
실제 한 배치가 소비할 수 있는 tile scratch와 span 수만 확보한다. polygon 순서는 유지하며 tile와 span 양쪽 용량으로 batch를 나눈다.

## 페이즈 3 — 통합과 비용

UI 선택은 OpenGL과 같은 1~16배다. 지원 범위를 초과한 입력은 거절하고, 실제 GPU의 자원 제한이나 할당 실패는 기존 실패 처리로 전달한다.
고배율을 모든 GPU에서 보장하지 않는다. 9배 이상은 현재 shader의 32×32 local group에 필요한 1024 invocations 등을 만족해야 한다.
16배의 표시 크기는 화면당 4096×3072이며, CPU/DMA용 native 결과와 표시용 이미지는 계속 별도다. 2D 원본 디테일을 새로 생성하는 기능은 아니다.
다음은 실제 선택된 RTX 5080의 한도를 넣어 계산한 11개 버퍼의 요청 바이트 합이다. 물리 VRAM 사용량이나 FPS 측정이 아니다.

| 배율 | 1.1.127 요청 bytes | 1.1.128 요청 bytes |
|---|---:|---:|
| 1x | 26,652,256 | 13,340,256 |
| 2x | 74,511,968 | 47,887,968 |
| 3x | 145,190,496 | 70,258,016 |

画像·readback·texture cache·driver 정렬과 host framebuffer는 위 합계에서 제외한다. 16배의 같은 버퍼 합은 1,170,463,072 bytes이며 배율 증가 비용은 여전히 크다.

## 페이즈 4 — 검증

Windows x64, CMake 4.4.3 / GCC 16.2.0, C23/C++26, LTO OFF. 기존 1.1.128 앱 빌드의 incremental 재검사는 성공했다.
선택된 GPU는 NVIDIA GeForce RTX 5080이다. 4~16배 각각의 Z/W native 사각형과 확대 origin, 16배→1배 복귀, 16배 batch/capture를 실행했다.
4/5/8/9/16배의 shared span과 8장면 Z/W 전체 graph를 GL 셰이더 경로와 비교한다. 이 대조군은 full Classic renderer나 실기를 대신하지 않는다.
512개 SPIR-V를 `spirv-val --target-env vulkan1.1`로 다시 검사해 실패 0, 기존 96개 해시 일치 96을 확인했다.
현재 소스로 관련 CTest 114개를 실행: 111개 통과, Qt offscreen 환경 때문에 3개 skip, 실패 0(93.21초).
해당 3개를 native Qt 창 환경에서 재실행해 3/3 통과(14.09초)했다. 최종 합산 커버리지는 114개이며 최초 skip 이력을 지우지 않는다.
이 선택에는 오디오/오디오 상태 복원 32개가 포함된다. 1.1.127의 물리 endpoint 무음 시험을 이번에 다시 실행한 것으로 세지 않는다.
headless 구성에서 Qt 전용 VulkanComputeSpans 타깃 없이 high-graph 검사가 등록되는 결함을 확인했다. TARGET 조건을 추가한 후 실제 재구성으로 해당 등록이 사라지고 코어 Vulkan 검사 7개가 유지됨을 확인했다. headless 전체 빌드/전체 suite 실행은 아니다.

## 페이즈 5 — 수락 범위와 후속

1~16배 선택·제한 검사·합성 입력의 GPU 출력이 확인된 범위를 반영한다. guest 수식·savestate 형식·오디오 계수·CPU cycle·새 ISA는 변경하지 않았다.
전체 CTest, 실제 게임 장기 진행, DSi 실기, AMD/Intel, 다른 OS, 물리 장치 탈착/청취, Vulkan validation layer는 이번 검증 범위 밖이다.
추가 GL scratch 과다 할당은 기존 split-batch 시험에서 재현했다. 제한1536 work에 각3,145,728 bytes를 확보하지만 계산상 필요한 상한은393,216 bytes다. 화면 비교는 동일했고 메모리 조건만 실패했다.
이 추가 GL 수정 요청은 도구 보안 판정에서 차단됐다. 실패 시험 diff/로그를 로컬에 보존하고 일반 시험 소스는 원상복원했다. GL 메모리 개선을 구현·통과로 세지 않는다.
해상도 콤보의 `.ui` 도움말에는 예전 1~3배/native 표시 설명이 남아 있다. 현재 선택 항목·Vulkan 라디오 설명은 1~16배이며, 잔여 도움말 정정은 후속이다.
후속 항목은 [현재 상태](../Current_Status.md)에서 원 과제 ID별로 추적한다. 새 API나 대규모 공통화를 선행 조건으로 만들지 않는다.

# 1.1.218 — 컨트롤러 미지정 상태의 반복 조회 제거

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

컨트롤러를 사용하지 않거나 구형 장치 인덱스의 일회성 선택이 실패한 뒤에도 입력 처리는 매 프레임 장치 목록을 조회했다. 후자의 경우 누락된 장치를 주기적으로 다시 열려고 하면서 현재 연결된 장치들의 식별 정보를 조회할 수도 있었다. 저장된 GUID가 없고 구형 인덱스 이관도 끝난 상태에서는 기존 Resolve 규칙상 명시적으로 다시 선택하기 전까지 연결할 수 없으므로, 이 작업은 선택 결과를 바꿀 수 없다.

이제 열린 조이스틱이 없고 저장된 GUID와 미완료 이관도 없을 때 목록 조회와 자동 열기 재시도를 생략한다. SDL 장치 갱신은 계속 호출하며 키보드·단축키 입력을 계속 병합한다. 설정에서 명시적으로 장치를 선택하면 정상 조회·입력 처리로 돌아간다. 저장된 GUID가 있는 컨트롤러의 재연결·중복 식별 정책과 매 프레임 조회는 그대로다. SDL 이벤트 정책과 버퍼·오디오 설정은 변경하지 않았다.

## 검증과 한계

- 실제 입력 처리 함수를 추출한 SDL2 가상 장치 검사에서 비활성 선택과 이관 실패 선택을 각각 300프레임 처리했다. 이전 코드는 각 300회 목록 조회와 이관 실패 상태의 식별용 열기 1회가 발생했다. 수정 후 두 상태 모두 조회·열기 0회이며 SDL 갱신은 각 300회를 유지했다.
- 키보드·단축키 누름/해제, 미지정 상태 이후 명시적 장치 선택과 버튼 입력을 검사했다. 관련 컨트롤러 검사 12개가 통과했으며 기존 분리·재정렬·시리얼 재연결·중복 식별·열기 실패 처리도 포함한다.
- 이 호출 횟수 측정은 SDL2 fixture 결과다. SDL3 경로는 패키지 빌드로 컴파일을 확인하며 SDL3 물리 장치에서 같은 횟수를 계측했다고 주장하지 않는다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- 첫 NetBSD 작업은 소스 구성·컴파일 이전의 패키지 설치에서 `pkg_install>=20200701` 의존성을 찾지 못해 실패했다. 해당 작업만 재실행하며, 먼저 성공한 FreeBSD·OpenBSD와 다른 플랫폼 결과는 재사용한다.
- 게임 플레이·물리 입력 지연·장기 청취·바쁜 호스트 FPS 비교는 수행하지 않았다. 반복 조회 제거를 틱 노이즈 해결이나 특정 지연 개선률로 환산하지 않는다. 1.1.216의 선택적 클록 보정은 기본 OFF를 유지한다.

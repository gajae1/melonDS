# 1.1.216 — 선택적 비동기 오디오 클록 보정

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

AudioSync OFF에서는 에뮬레이션과 출력 장치가 별도 시계로 움직인다. 작은 속도 차이도 누적되면 오디오가 부족해지거나 넘칠 수 있다. 이번 변경은 이 원인을 줄이기 위한 선택적 보정이다. 사용자가 보고한 모든 틱 노이즈의 원인이 확인됐거나 해결됐다는 의미는 아니다.

오디오 설정의 `Correct asynchronous audio clock drift`는 기본 OFF다. Sinc (sharp), AudioSync OFF, 피치 보존 OFF, 정상 속도 제한 실행, 실행 중인 출력 장치, 보정 가능한 출력률에서 동작한다. DSi 47 kHz를 44.1 kHz로 출력하는 등 업샘플링 여유가 없는 경우에는 동작하지 않는다. 설정을 즉시 미리 적용하고 Cancel은 이전 값을 복구한다. 출력 상태는 설정 창에서 주기적으로 갱신한다.

장치 콜백의 요청/공급 샘플 수·시각과 실제 프레임 완료 직후의 SPU 큐·드롭 수로 상대 위상을 추적한다. 기존 오디오 락을 try-lock으로 얻지 못하면 해당 관측을 건너뛴다. 초기 안정 구간 이후 Sinc 출력률을 최대 ±0.1%, 초당 최대 100ppm씩 조절한다. 보정 자체는 계수 재생성·출력 이력 초기화·추가 PCM 할당을 하지 않는다. 게임 실행 속도, 버퍼 용량, 대기 정책, 게스트 오디오 캡처와 세이브 형식은 바꾸지 않는다. 음높이는 미세하게 변할 수 있고 실제 큐 점유량도 달라질 수 있다.

긴 생산/콜백 중단이나 불연속 관측은 보정을 초기화한다. 지속적인 포화 또는 큰 위상 차이는 보정을 중지하고 출력·모드 등의 재설정 이후 다시 시작한다. 옵션·출력·필터·배속·셰이더 준비·재개 경계에서 상태를 초기화하며, 프레임 도중 게스트 샘플률이 비호환 값으로 바뀌어도 즉시 보정을 해제한다. 호스트 과부하를 게임 속도 변경으로 숨기지 않는다.

## 검증과 한계

- 실제 SPU/Sinc의 생성·버퍼·읽기 경로와 가상 호스트 시계를 연결한 14조건이 통과했다. DS 32 kHz 및 DSi 47 kHz 출력, ±100/±500ppm 장치 시계 차이, 44.1/48 kHz 출력, 100ms 생산/콜백 중단, ±250μs/±1ms 타이밍 흔들림과 지속 과부하를 포함한다. 일반 조건은 가상 120초, 과부하는 10초다.
- +500ppm·48 kHz 조건은 초기 보정 중 누락 111프레임을 기록했고 마지막 30초의 누락·드롭은 0이었다. ±1ms 흔들림에서는 마지막 30초에 2프레임 누락이 남았다. 중단 자체의 누락·드롭은 제거하지 않으며 지속적인 2% 생산 부족은 보정을 중지했다.
- Sinc 출력률/이력/유효 범위 검사, 기존 콜백·장치 재열기·세이브 복원 오디오 검사, 옵션 미리 적용·저장·취소, 생산 코드의 모드 전환·큐 보존·락 경합 검사가 통과했다. 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- 최초 가상 검사에서 생산 시각과 콜백 시각의 정밀도가 달라 콜백이 0.333ns 미래처럼 보였다. 양쪽에 동일한 정수 시계를 적용한 뒤 실패 조건을 재검증했다. 통과 기준은 낮추지 않았다.
- 가상 시계 검사는 실제 ROM 실행·DSi BIOS/NAND·WASAPI 장기 청취·전체 RunFrame·물리 오디오/입력 지연 검증이 아니다. 게임 플레이나 바쁜 호스트의 FPS 비교는 하지 않았다. 사용자 설정과 설치 앱은 변경하지 않았다. 9800X3D 내장그래픽은 GPU 제약 환경이며 저성능 CPU의 대체 검증으로 취급하지 않는다.

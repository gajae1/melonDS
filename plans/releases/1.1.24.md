# 1.1.24 — 실행 중 표시 실패와 안전한 복구

기준 1.1.23, 검증일 2026-09-10. GR-03/04/11의 실제 증분이다. 책임 버전 1.1.24의 카트리지·homebrew·GBA 주변장치 과제와 구분한다.

## 5페이즈

1. **재현:** 표시 중 MakeCurrent·SwapBuffers 실패와 root renderer가 남은 상태의 해제를 정상 경로와 대조한다. 전체 Qt에서는 주 창·보조 창에 지속 실패를 주입한다.
2. **수정:** current 확보 실패를 상위로 전달하고 core 실행·상태 변경을 중단한다. GL 해제가 실패하면 기존 context와 창을 유지한다.
3. **통합:** 안전한 native 전환과 실패 시 Retry/Cancel을 연결한다. 이전에 해제한 창은 다시 초기화하고, 일시정지 화면은 다음 실제 프레임까지 보존한다.
4. **검증:** 실패 중 상태·자원 보존, 저장·창 닫기 거부, 명시적 재시도, 두 창 전환, 일시정지 이미지와 입력·프레임 보내기를 확인한다. 최종 Windows 전체 회귀는 한 번 수행한다.
5. **배포:** 확인된 동작을 버전·실행 파일·패키지에 반영한다. context 반환 실패와 실제 장치 상실·다른 플랫폼 수락은 유지한다.

## 변경

표시의 MakeCurrent·SwapBuffers 결과를 worker까지 전달한다. current 확보 실패 뒤 화면을 그리거나 swap하지 않는다. worker는 오류를 기억하고 오디오를 중단하며, 복구 제어 메시지를 처리하는 동안 프레임·저장·로드·reset·boot 같은 core 소비자를 차단한다. 오류 알림은 GUI 큐에 한 번 전달한다.

root context를 확보하고 현재 화면을 보존한 뒤에만 capture와 core renderer를 정리한다. 표시 객체의 부분 소유 상태를 유지하고, 해제와 current 반환 성공을 상위에 전달한다. 설정 변경·창 닫기·인스턴스 제거는 해제 실패 시 기존 창과 context를 파괴하지 않는다. 여러 창 중 뒤쪽에서 실패하면 이미 해제한 창을 다시 초기화한다.

GUI는 안전하게 정리할 수 있으면 software/native 표시로 전환한다. 자원을 해제할 수 없으면 게임 상태를 유지하고 Retry/Cancel을 표시한다. Cancel 뒤에도 실패한 세션을 실행하지 않으며 Config > Video settings에서 재시도할 수 있다. 전환이 성공한 뒤 현재 설정을 software로 바꾸는 기존 정책을 유지한다.

실제 Qt 검증에서 일시정지 중 native로 전환하면 새 renderer의 빈 출력으로 화면이 검게 바뀌는 문제가 재현됐다. 전환 직전 두 화면을 보존해 native 표시와 OpenGL 재선택에 전달한다. 실제 프레임이 진행되면 새 출력으로 갱신하고, 성공한 reset·boot·상태 로드/undo에서도 보존 이미지를 비운다.

## 검증 범위

- 표시 current 실패·swap 실패·root 해제 current 실패의 세 회귀는 수정 전 모두 실패했다. current 실패 뒤 swap이 진행됐고, swap 실패를 호출자가 받지 못했으며, current 확보 없이 core renderer 해제에 진입했다.
- 현재 표시 메서드와 root 해제 메서드를 실제 Windows GL에서 실행해 실패 반환·잘못된 소비 차단·정상 재시도를 검사한다. 기존 OpenGL/Compute core 해제와 source-B 캡처 보존 검사는 유지한다. 상태 메시지 검사에서는 오디오·게임 세션 유지, 저장/로드/reset/boot/프레임 보내기 거부와 정상 복구를 확인한다.
- 전체 Qt 프로그램의 현재 object 파일을 사용한 로컬 실행에서 생성 DS guest를 구동했다. 실제 WGL current/swap 호출에 linker wrapper로 실패만 주입하며 실제 창·worker·설정·queued signal·교체 코드를 사용했다. 주 창과 보조 창 각각에서 지속 current 실패 중 프레임·RAM·context 보존, 상태 파일 미생성, 창 닫기 거부, Cancel 후 중단 유지와 명시적 재시도가 통과했다.
- 일시정지 중 swap 실패→두 창 native 전환에서 프레임 수와 게임 이미지가 유지됐다. OpenGL 재선택 후에도 화면을 유지했고, VRAM을 바꾼 뒤 한 프레임 보내기에서 새 색으로 갱신됐다. Qt 키 이벤트를 통한 A 버튼 입력·해제도 guest에서 확인했다. 단색 생성 화면의 영역 검증이며 전체 게임 픽셀 정확도나 물리 키보드·터치 수락으로 집계하지 않는다.

Windows x64 Release 전체 빌드와 CTest **436/436, skip 0**이 통과했다(30.15초). GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26과 기존 JIT/ISA 구성을 유지했다. core 에뮬레이션 소스는 변경하지 않았다.

실행 파일은 `1.1.24-melonDS.exe`, 패키지는 `1.1.24-melonDS-windows-x64.zip`과 `1.1.24-melonDS-source.zip`이다. 실행 파일·필요 DLL/plugin·라이선스만 포함하며 게임·설정·저장 자료는 포함하지 않는다.

## 남는 범위

물리 context/surface 상실을 재현한 결과가 아니다. 화면용 해제의 DoneCurrent 실패는 거부로 전달하지만, 일반 worker borrow와 context 생성의 반환 실패는 아직 별도 검증·전파가 필요하다. 다음 실제 1.1.25에서 이 소유권 경계를 먼저 다룬다.

전체 Qt 검사는 동일한 복구 구현의 버전 표기 최종 재링크 전 실행이며 배포 EXE 자체에 실패를 주입한 결과와 구분한다. 새로운 상용 게임 실행은 수행하지 않았다. 다중 인스턴스·이종 GPU/DPI·최소화/휴면·다른 OS, 실기·장기 실행과 GPU 정밀도·Vulkan·JIT/ISA·DSP·오디오·네트워크·주변장치 등 공개 전체 계획은 유지한다. 성능·전력·물리 지연 개선량은 측정하지 않았다.

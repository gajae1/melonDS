# 1.1.156 — savestate KeyInput 직렬화·clang64 언어 probe

2026-09-22. 기준 1.1.155 HEAD 1aac8b3b. 빌드는 93f6 worktree의
build/windows-dev다.

## 구현

- CJ-20 입력 복원 경계 첫 이행: NDS::DoSavestate가 KeyInput을 조건부
  필드로 직렬화한다. KeyInput은 SetKeyMask가 덮어쓰지 않는 래치 상태를
  담는다 — lid closed(bit 23)·touch pen(bit 22)·홀드 중인 키. 이전에는
  save→load가 lid/pen/키 상태를 잃었다(TODO 주석).
- 포맷은 조건부 minor 14.14: prepare pass가 KeyInput이 콘솔 idle 값과
  다를 때만 RequireMinorVersion(14)를 올린다. DS idle은 0x007F03FF,
  DSi native idle은 0x003F03FF(DSi::Reset이 pen 비트를 지우고,
  DS-compat TSC 모드는 다시 세운다 — 그것도 저장 대상 상태). idle
  상태는 14.2를 유지해 구 reader가 계속 읽는다. 14.14 상태는 구
  reader(MAX_MINOR=13)가 "from the future"로 깨끗이 거부한다.
- 로드 시 게스트 가시 비트(0x00FF03FF: ARM9 하위 10비트 + ARM7 바이트
  16-23)만 복원하고 아무도 구동하지 않는 24-31비트는 버린다.
  Savestate.h의 minor 표에 14.13(flash power)·14.14 문서를 보완했다.

## 검증

- 신규 ctest 2개: savestate-keyinput(5 cases — idle-default가 minor<14
  유지·live 입력 보존, lid/held-key/pen-down 왕복, 예약 비트 마스크)와
  savestate-future-minor(minor>MAX 거부와 rewind 후에도 거부 유지).
- windows-dev 전체 ctest 1010/1010(307.58s) 통과.
- 첫 구현은 DS idle 상수만 비교해 DSi idle(pen 비트 clear)을 전부
  14.14로 올리는 결함이 있었고, cart-spi 7건+audio-one-shot-state가
  이를 잡았다. 콘솔별 idle 비교로 수정 후 동일 테스트 재통과.

## BV-06 toolchain probe — clang64

- MSYS2 clang64(Clang 22.1.8, libstdc++)로 기존 probe 두 개를
  compile·실행: LanguageStandard.cpp(-std=c++26, __cplusplus=202400,
  bitops static_assert 통과, exit 0), CStandard.c(-std=c23,
  __STDC_VERSION__=202311, typeof_unqual/bool 실행, exit 0).
- Clang/libstdc++ 셀은 실측으로 채워졌다. libc++·MSVC·GCC14·다른 OS는
  미설치/미보유로 후속.

## 남은 범위·한계

- CJ-20의 RTC·외부/다중 인스턴스 시간 정책과 링크 pause/resume은 후속.
- 구 build가 쓴 14.14 이전 파일은 필드가 없어 읽기에서 건너뛰며 live
  입력 상태를 유지한다 — 이전 행동과 동일.

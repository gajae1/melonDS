# 1.1.26 — DSi 부팅·SD 전송·LocalMP·그래픽 설정

기준 1.1.25, 검증일 2026-09-10. GR-03, AD-09/10/11/12/13, NP-03의 독립 작업을 한 증분으로 통합했다. 책임 버전 1.1.26의 ISA·CRC·hash 성능 과제와 공개 전체 계획은 유지한다.

## 5페이즈

1. **재현:** 독립 암호 vector, 합성 NAND와 저장 파일, 큐 넘침·수신 순서, 실제 Qt의 그래픽 실패를 정상 입력과 대조했다.
2. **수정:** DSi 부팅, SD 저장, LocalMP를 서로 다른 작업 공간·소유 파일로 병렬 처리했다. 그래픽 설정과 공유 연결부는 한 작성자가 통합했다.
3. **통합:** 직접 부팅 실패를 코어→프런트엔드→worker까지 전달하고, 설정창에는 worker의 실제 렌더러·지원 상태를 전달했다.
4. **검증:** 각 블록의 반례·정상 경로를 확인한 뒤 통합 소스에서 Windows 전체 빌드와 전체 CTest를 한 번 실행했다. 같은 최종 object 파일로 전체 Qt 복구 흐름도 확인했다.
5. **배포:** 버전·실행 파일·Windows/source 패키지에 검증된 범위를 반영한다. 실제 게임·장치·장기 수락은 아래와 같이 남긴다.

## 변경

**DSi 부팅:** 개발 키의 초기화 대상과 debugger 선택 bit를 수정하고, 네 binary의 modcrypt subarea를 해당 RAM offset에서 복호화한다. HWINFO는 정확한 길이의 읽기가 성공한 뒤에만 출력에 반영한다. 사전 검사 실패는 기존 세션을 보존하고, 준비 이후 새 I/O 실패는 부팅 성공·CPU 진입·실행 재개로 이어지지 않는다. 명시적 firmware 부팅은 direct-boot 설정의 영향을 받지 않는다. [DSi header 형식](https://dsibrew.org/wiki/DSi_cartridge_header#Modcrypt), [독립 modcrypt 구현](https://github.com/TuxSH/twlnandtool/blob/master/source/crypto/crypto_twl.hpp), [FatFs 읽기 계약](https://elm-chan.org/fsw/ff/doc/read.html)

**SD 전송:** producer·host 길이 불일치와 sector 밖 접근을 거부하고 홀수 길이의 마지막 byte를 안전하게 처리한다. 짧은 읽기·쓰기, seek 실패, 읽기 전용·매체 끝 오류를 controller 상태까지 전달하며 실패한 전송의 FIFO·완료 event를 정리한다. FATStorage의 기존 sparse EOF 정책은 유지하면서 seek 실패와 Qt의 명시적 -1 I/O 오류를 성공으로 해석하지 않는다. [SD 물리 계층 규격](https://www.sdcard.org/cms/wp-content/themes/sdcard-org/dl.php?f=Part1_Physical_Layer_Simplified_Specification_Ver7.10.pdf), [Qt 읽기 계약](https://doc.qt.io/qt-6/qiodevice.html#read)

**LocalMP:** ring의 빈 상태와 가득 찬 상태를 구분한다. 넘침 시 뒤처진 수신자의 backlog를 완전한 기록 단위로 폐기하고 정상 수신자는 유지한다. 커서·permit을 같은 lock 안에서 맞추고, permit을 이미 받은 수신자도 reset 이후 상태를 다시 확인한다. 종료·재가입·새 host의 이전 reply 상태를 정리한다. 기존 한 host 계약을 유지하며 독립된 여러 무선 그룹을 지원한다고 주장하지 않는다.

**그래픽 설정:** 선택한 렌더러와 실제 활성 렌더러, 적용 대기·shader 컴파일·실패를 구분해 표시한다. 현재 context의 Compute 지원 여부는 worker에서 확인한다. 미지원 선택은 비활성화하고 새 context에서 다시 평가한다. software 복구 후 명시적 재선택과 설정 취소의 원래 값 복원을 유지한다.

## 검증 결과

Windows x64 Release 전체 빌드와 최종 CTest **498/498, 실패 0, skip 0**이 통과했다(56.60초, 병렬 2). 전체 검사는 반복하지 않았다. 1.1.25의 GDB loopback 첫 실패 원인은 여전히 미확정이며 이번 성공을 그 원인의 수정으로 보지 않는다.

- 독립 OpenSSL vector의 15개 modcrypt 시나리오와 실제 AES·NAND crypto·FatFs·guest RAM에서 exact/missing/truncated/I/O 실패를 대조했다. 실제 direct-boot wrapper의 실패 반환·CPU/RAM 보존·성공 표시 차단, 기존 DS/DS-on-DSi/DSi 준비, 세션·카트·저장 경로 보존과 늦은 실패의 정지를 확인했다.
- 현재 SD controller 소스와 scheduler 대역에서 보호 페이지·단/다중 block·FIFO16/32·부분 전송·IRQ·명시적 재시도를 확인했다. 실제 Qt 파일 I/O에서는 failed seek·-1 오류·정상 sector·주변 byte·sparse EOF/확장을 대조했다.
- 현재 LocalMP 구현에서 가변 길이·정확한 ring wrap, 정상 왕복, 종료·새 host, permit 획득 뒤 reset의 두 순서를 확인했다. 동기화 fixture와 실제 무선 게임 수락은 구분한다.
- 실제 Qt 설정창과 생성 DS 실행에서 진짜 shader 컴파일 실패, 주입한 자원 한도, 일시정지·Cancel·재개, 표시 실패의 native 복구, 미지원 Compute·새 context 재시도, RAM·프레임 진행 보존과 정상 종료를 확인했다. GUI의 capability 직접 조회는 없었다.

Qt 검증 중 안내창의 modal 처리 전에 뒤의 설정창과 메인 창을 강제 조작한 시험 스크립트에서 종료 오류가 발생했다. 안내창 확인 후 실제 사용자 순서대로 진행하면 동일 제품 코드가 정상 종료했다. 이 시험 도구 오류를 제품 결함으로 기록하거나 우회 코드를 추가하지 않았다.

## 범위와 남은 조건

새 제품 소스 파일은 없다. 기존 코드를 수정하고 검증 fixture/CMake 12파일과 이 릴리스 기록을 추가했다. DSi.cpp·LocalMP.cpp는 [공식 upstream 기준](https://github.com/melonDS-emu/melonDS/commit/e07688114057f742dde332a247f43799607f080b)과 1.1.25의 blob이 동일하고, NAND reader·SD 전송도 관련 로직이 그대로였다. 해당 반례는 이 포크에서 새로 생긴 동작으로 분류하지 않는다. 모든 과거 변경이나 파일 수가 적정하다는 전면 감사 결과는 아니다.

GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26과 기존 JIT/ISA 구성을 유지했다. 실행 파일은 `1.1.26-melonDS.exe`, 패키지는 `1.1.26-melonDS-windows-x64.zip`과 `1.1.26-melonDS-source.zip`이다. 게임·firmware·NAND·설정·저장 자료는 포함하지 않는다.

실제 DSi 게임·firmware 부팅, 물리 SD/MMC 오류·버스 타이밍, SDIO/Wi-Fi 연속 전송, 실제 LocalMP 게임·다중 그룹, 3.2-only 및 다른 GPU/OS·surface 상실·장기 실행은 미검증이다. 짧은 쓰기의 이미 기록된 prefix는 되돌리지 못하며 지속 저장·전원 상실 원자성을 보장하지 않는다. Platform에서 short count와 EOF만 함께 반환하는 모호한 backend 오류는 sparse EOF와 구분할 수 없다. 이번에 그 형태의 추가 Qt 결함을 재현한 것은 아니다. 전체 Qt 검사는 오류 주입용 entrypoint로 최종 object를 재링크한 것이며 배포 EXE의 물리 GPU 오류 재현은 아니다. 성능·전력·지연 개선량은 주장하지 않는다.

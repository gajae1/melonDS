# 1.1.03 — 재현 기반과 파일·상태 입력 방어

상태: 아래 증분 구현·Windows 로컬 검증 완료(2026-09-09). 기준 소스: 1.1.02. 공개 계획을 정리하고 재현한 세 경계를 먼저 수정했다.

## 이번 증분의 5페이즈

1. **기준·반례:** 현재 소스·빌드 구성을 기록한다. 활성 event의 잘못된 callback ID, Zstd의 크기 미기록·잘린 frame, 손상 TOML의 시작·저장을 합성 입력으로 재현한다.
2. **최소 수정:** production 이벤트 입력, Zstd 해제, Config Load/Save 경계만 수정한다. 정상 파일과 기존 비활성 이벤트의 호환성을 확인한다.
3. **통합:** 기존 CMake/CTest에 연결하고 표시 버전을 1.1.03으로 올린다. 오류가 성공으로 처리되거나 원본 설정이 조용히 덮어써지지 않게 한다.
4. **검증:** 수정 전 반례 실패·수정 후 관련 회귀, Windows frontend 빌드와 해당 구성의 최종 검사를 기록한다. 검증하지 않은 게임·물리 장치·다른 OS는 별도로 남긴다.
5. **배포 기록:** 실제 반영 범위·검사 결과·복구 방법을 갱신한다. 원래 1.1.03 재현 도구 확장 및 1.1.05/07의 남은 범위를 완료로 세지 않는다.

## 범위

| ID | 이번 범위 | 후속 범위 |
|---|---|---|
| BV-01, BV-04 | 공개 계획·현재 증거 색인과 기존 도구의 로컬 명령 | 전체 profile·산출물 도구화는 1.1.43 |
| CJ-09 | 저장 상태의 scheduler event 값 검증 | CJ-10/FS-01의 전체 load/undo rollback은 1.1.05 |
| FS-08 | 실제 Zstd 출력 길이와 frame 완료·오류 경계 | archive/전체 파일 읽기·취소는 FS-02/07/20 |
| FS-04 | 손상 TOML 원본 보존과 실패 반환 | 설정 UI의 상세 저장 오류·복구 흐름 |

CJ-20의 event 입력 확장, BV-10의 통합 지연 계측, BV-11의 sanitizer 지원표, BV-18의 전체 upstream 변경 대조는 이번 증분에서 완료하지 않는다.

## 검증 결과

| 검사 | 수정 전 | 수정 후 |
|---|---|---|
| Zstd 실제 길이 | 4,099바이트 출력에 16MiB, 16MiB+257 출력에 32MiB를 반환 | 실제 길이·내용 일치, 입력/출력 소유자가 같은 호출도 정상 |
| Zstd 완료·프레임 경계 | 잘린 checksum/body·후행 partial header·빈 출력 일부를 성공 처리, 연결 frame 처리 불일치 | 완료 frame만 수락; 연결·skippable frame 처리, 손상·빈 입력 거부 |
| Zstd 할당·크기 경계 | 신규 실패 주입은 수정 후 검사 | context/초기 버퍼/증가/최종 출력 할당 실패에서 오류 반환·입력 소유자 보존; 과대 선언은 할당 전 거부 |
| 손상 TOML Load→Save | 잘못된 성공 반환과 원본 덮어쓰기 재현 | 실패 반환·쓰기 차단·원본 바이트 보존; 수리 후 재로드·설정 저장 정상 |
| scheduler 값 | FuncID 3/UINT_MAX·미등록 callback·잘못된 mask 네 종류를 수락 | 정상·비활성 호환·잘못된 값 거부·거부 뒤 기존 이벤트 실행·늦은 등록을 포함한 9사례 통과 |
| 전체 회귀 | 새 증분의 기준 실행과 구분 | **57/57 통과, skip 0**. interpreter/JIT/fastmem, 파일 저장, 실제 OpenGL/Compute context 포함 |
| Windows 배포 구성 | 기존 실행 패키지와 구분 | frontend Release 빌드 성공; 실행 파일·DLL/plugin 129개 import 검사에서 미해결 0, 독립 PATH `--help` 성공 |

구성: Windows x64, GCC 16.2.0, CMake 4.4.3, Qt 6.11.2, SDL 2.32.10, Zstd 1.5.7, C23/C++26.
`MELONDS_BUILD_TESTS=ON`, `MELONDS_TEST_GPU=ON`, `ENABLE_AVX512=ON`, LTO OFF. 명령은 [검증 방법](../Validation.md)을 따른다.
기존 toml11/Qt 헤더의 deprecation 경고는 남아 있다. 경고를 숨기거나 의존성을 이번 수정에 함께 교체하지 않았다.

## 수락 한계와 복구

- scheduler 값은 유효성 검사 뒤 적용한다. 실제 DSi HLE 복원, CPU/RAM/장치 전체 rollback, 실패 후 전체 게임 세션 재개는 CJ-10/FS-01의 후속이다.
- Zstd의 실제 1GiB 출력 끝 경계와 물리적 메모리 고갈은 미검증이다. 할당 실패 주입 통과를 실제 시스템 고갈 수락으로 확대하지 않는다.
- TOML 구문 오류가 나면 세션의 설정 저장을 막고 시작 화면에서 복구 방법을 알린다. 원본을 수리하거나 별도 보관한 뒤 재시작하면 된다. 일반 설정 저장 오류의 상세 UI 전파는 후속이다.
- 이번 변경은 속도 향상을 측정·주장하지 않는다. 실제 게임 장기 실행·물리 장치·다른 OS 수락은 이번 검증에 포함하지 않았다.
- 저장 상태 형식과 설정 형식을 바꾸지 않았다. 배포 교체 시 기존 실행 파일과 저장 데이터를 보관하고, 문제 발생 시 이전 실행 파일로 되돌린다.

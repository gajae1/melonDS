# 1.1.23 — 표시 초기화 실패 복구와 OSD 재생성

기준 1.1.22, 검증일 2026-09-10. GR-03/04/11의 실제 증분이다. 책임 버전 1.1.23의 DSi·카메라 과제와 구분한다.

## 5페이즈

1. **재현:** 실제 ScreenShader·OSDShader에 잘못된 입력을 전달하고, 초기 MakeCurrent 실패와 OSD가 있는 재초기화를 정상 초기화와 대조한다.
2. **수정:** 성공한 초기화만 ready로 공개한다. 부분 생성된 객체를 해제하고 OSD의 업로드 상태를 다시 준비한다.
3. **통합:** Screen→Window→Instance→EmuThread의 성공 결과를 연결하고, 실패 알림을 GUI 큐로 전달해 기존 native 표시 전환과 명시적 재선택을 사용한다.
4. **검증:** 실제 GL의 실패·재시도·해제와 전체 Qt 프로그램의 두 창 교체·오류 알림·재선택·종료를 확인한다. Windows 전체 회귀는 최종 소스에서 한 번 수행한다.
5. **배포:** 검증된 초기화 경계만 버전·실행 파일·패키지에 반영한다. 실행 중 current/swap 실패와 실제 surface 상실은 다음 증분에 남긴다.

## 변경

표시 shader의 컴파일 결과를 무시하고 초기화 완료로 설정하던 경로를 수정했다. 첫 MakeCurrent가 실패하면 GL 호출 없이 실패를 반환한다. ScreenShader 실패와 OSDShader 실패는 생성된 부분만 정리하고 context를 반환한다. 소유 GL handle은 0으로 초기화하고 해제 뒤 비우므로 부분 초기화와 반복 해제에서도 이전 handle을 재사용하지 않는다.

OSD texture를 지운 뒤 남아 있던 rendered 상태를 초기화한다. 기존 메시지와 splash 항목은 다음 표시에서 texture를 다시 생성한다. texture가 없는 메시지에서 iterator가 전진하지 않던 표시 반복문도 범위 순회로 바꾼다.

worker는 root 표시 초기화가 성공했을 때만 OpenGL 사용 상태를 켠다. 보조 창 초기화 결과가 root의 상태를 덮어쓰지 않는다. 오류는 GUI에 queued signal로 전달하고 기존 pause→deinit→창 교체→재개 경로로 software/native 표시를 적용한다. 기존 native-context 생성 실패와 동일하게 현재 설정을 software로 바꾸며, 사용자는 Config > Video settings에서 OpenGL을 다시 선택할 수 있다. 저장 선호를 별도로 유지하는 새 정책은 도입하지 않았다.

## 검증 범위

- `GLPresentation`의 네 실패 회귀는 수정 전 모두 실패했다. Screen·OSD shader 실패에서도 ready가 켜졌고, 첫 MakeCurrent 실패 뒤 shader 호출이 발생했으며, OSD 재초기화 뒤 rendered 상태가 남았다.
- 현재 표시 init/deinit/draw 및 OSD update 메서드를 실제 Windows GL에서 실행한다. 잘못된 shader는 실제 driver가 거부하며 초기 MakeCurrent 실패만 대역에서 주입한다. 부분 생성 객체의 실제 생존 여부, 초기화 거부, current 반환, 정상 재시도·반복 해제·OSD texture 재생성을 검사한다. glyph 생성과 QWidget layout은 이 fixture에서 격리한다.
- 전체 Qt 프로그램의 현재 object 파일을 이용한 로컬 실행에서 시작 시 ScreenShader 실패→경고→native 표시, 두 창 OpenGL 재선택, OSDShader 실패→두 창 native 전환, 두 번째 재선택과 실제 WGL 종료가 통과했다. shader 입력만 linker wrapper로 주입하며 실제 창·worker·queued signal·설정·교체 메서드를 사용했다. 게임은 실행하지 않았고 자동으로 확인한 경고 외의 사용자 입력·장치 조작은 수행하지 않았다.
- 기존 실제 WGL 교체와 OpenGL/Compute core 해제 시 source-B 캡처 보존 검사는 유지한다. 코어 실행 소스는 변경하지 않았다. 이전 1.1.22의 실제 게임 프레임 대조를 이번 버전의 새 게임 실행으로 집계하지 않는다.

Windows x64 Release 전체 빌드와 CTest **432/432, skip 0**이 통과했다(60.06초). GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26과 기존 JIT/ISA 구성을 유지했다. 위 전체 Qt 검사는 동일한 초기화 구현의 버전 표기 최종 재링크 전 실행이며, 최종 소스의 전체 CTest와 구분한다.

실행 파일은 `1.1.23-melonDS.exe`, 패키지는 `1.1.23-melonDS-windows-x64.zip`과 `1.1.23-melonDS-source.zip`이다. 실행 파일·필요 DLL/plugin·라이선스만 포함하며 게임·설정·저장 자료는 포함하지 않는다. 이번 수정의 성능·전력·물리 지연 개선량은 측정하지 않았다.

## 남는 범위

이미 초기화된 표시와 코어 renderer가 실행되는 동안의 MakeCurrent·SwapBuffers 실패는 미완료다. 현재 확보 실패 시 표시 deinit 자체는 GL 삭제를 건너뛰지만, 상위 core 해제·창 교체 호출자는 실패를 전달받지 못한다. 실제 context 상실에 안전한 완전 복구로 보고하지 않는다.

다음 실제 1.1.24는 실행 중 표시 실패의 상위 전달·프레임 중단·해제 거부·명시적 재시도와 안전한 native 전환을 다룬다. paused 게임 이미지와 입력 보존, 다중 인스턴스·이종 GPU/DPI·휴면·다른 OS, 전체 게임·실기·장기 실행은 별도 수락 조건으로 유지한다. GPU 정밀도·Vulkan·JIT/ISA·DSP·오디오·네트워크·주변장치 등 공개 계획의 전체 범위도 유지한다.

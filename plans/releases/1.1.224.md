# 1.1.224 — OpenGL Compute 소형 무텍스처 배치의 래스터·깊이 블렌드 융합

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

OpenGL Compute 3D는 span 준비와 타일 binning 뒤에 간접 dispatch(GPU가 버퍼에서 작업 수를 읽어 실행하는 호출)로 래스터 결과를 ColorDepthAttr(색·깊이·속성 중간 저장소)에 쓰고, 순서 보존 깊이·블렌드 셰이더가 이를 다시 읽어 합성했다. 1.1.224는 조건을 만족하는 배치에서 래스터 계산을 깊이·블렌드 셰이더 안으로 옮긴다. 폴리곤은 기존 순서대로 처리하고 블렌딩 규칙은 바꾸지 않는다. 해당 배치는 간접 래스터 dispatch 1회, 그 뒤의 장벽 1회, ColorDepthAttr 중간 접근을 생략한다. 스크래치 할당량은 기존과 같다.

Fog·AA 등 최종 효과는 융합 여부와 관계없이 항상 별도 패스로 실행한다. 그래서 1.1.223의 Vulkan과 달리 최종 Fog/AA 배치도 융합 대상에서 빠지지 않는다.

OpenGL 셰이더 프로그램은 1~4배율에서 32개에서 34개로 늘었다. 배율이 더 크면 기존 32개를 유지한다. Vulkan의 44개와 기존 OpenGL 렌더러 `GPU3D_OpenGL.cpp`는 변경하지 않았다. 공유 셰이더의 융합 함수는 GL 전용 출력 속성(outattr)을 명시 인자로 받아 초기화하고 원래 속성을 보존한다. Vulkan의 속성 패킹은 바꾸지 않았다. 새 프로그램 2개가 시작 컴파일 시간에 주는 비용은 측정하지 않았다.

## 적용 조건과 fallback

호스트(GPU3D_Compute.cpp)는 다음 조건을 모두 만족할 때만 융합한다.

- 폴리곤 1~8개이고 텍스처 없는 일반 variant 하나로 이루어진 배치.
- TileSize 8, 1~4배율.
- 그릴 span이 있고 융합 프로그램이 유효한 배치. 그림자 그리기(draw)도 위 조건을 만족하면 대상이 될 수 있다.

텍스처 배치, Toon·Highlight, 그림자 마스크, 9개 이상의 폴리곤, 4배 초과 배율은 기존 경로를 그대로 쓴다.

- 기존 일반 워크로드의 dispatch·용량 assertion은 일반 경로 대조군으로 유지했다. 여기에 융합 경로가 래스터 dispatch 0회, 일반 경로가 1회임을 확인하는 검사와, 그림자·반투명 배치가 분할되어 이어지는 경우를 포함한 픽셀 단위 비교를 추가했다.
- 변경한 7개 소스·테스트 파일의 최종 diff는 한 번 검토해 수락했다. 창을 띄우거나 게임을 실행하지 않았다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 성능 측정

제품 렌더러의 실제 `GLRenderer::Start3DRendering`을 호출하고, 같은 렌더러에서 `ComputeRenderer3D::SetFusedRaster`를 바꿔 기존 경로와 융합 경로를 비교했다. 숨김 SDL 창과 실제 AMD Radeon(TM) Graphics를 쓰며 입력은 합성 native 지오메트리뿐이다. 32사례는 1·2·4배율, Z/W, 폴리곤 1·4·8개(4배율은 1·4개), 겹치는 폴리곤과 좁은 폴리곤 열이다. 실제 GL dispatch Z 용량을 넘을 수 있는 4배율 8폴리곤은 보수적으로 제외했다. 모든 사례에서 융합 경로와 일반 경로의 전체 픽셀이 같았고, 실제 간접 래스터 호출은 일반 경로 1회, 융합 경로 0회임을 확인했다. 사례마다 20쌍을 예열한 뒤 실행 순서를 번갈아 40쌍을 측정했고, 일반 경로를 양쪽에 넣은 A/A 대조를 같은 방식으로 실행했다. 원본은 product-ab.json·product-aa.json, 요약은 product-comparison.json이다.

쌍별 중앙값은 32사례 중 30사례에서 일반 경로보다 낮았다. 겹치는 폴리곤 16사례는 16.93~58.85% 감소했고 사례별로 40쌍 중 37쌍 이상에서 앞섰다. 전체 사례의 범위는 -0.65~58.85%다(음수는 느려짐). 좁은 1배율 1폴리곤 두 사례는 0.42%와 0.65% 느렸는데, 해당 사례의 A/A 절대 쌍별 변동 중앙값이 2.56%와 2.55%라서 이 조건의 이득은 확정하지 못했다. 나머지 30사례는 각자의 A/A 변동보다 큰 감소를 보였다. 전체 A/A 중 가장 큰 쌍별 변동 중앙값은 7.88%다. 불리한 사례를 없애려고 폴리곤 수나 넓이의 임계값을 조정하지 않았고 두 사례를 그대로 남겼다.

| 배율 | 사례 수 | 겹치는 폴리곤 감소 | 좁은 폴리곤 감소 |
| --- | ---: | ---: | ---: |
| 1x | 12 | 16.93 ~ 28.15% | -0.65 ~ 13.32% |
| 2x | 12 | 23.64 ~ 58.85% | 3.51 ~ 25.17% |
| 4x | 8 | 30.21 ~ 45.49% | 10.99 ~ 25.50% |

이 수치는 Radeon 내장 GPU 한 대에서 실제 OpenGL 제품 렌더러의 3D 시작 호출(GLRenderer::Start3DRendering) 전후를 GL_TIME_ELAPSED로 잰 합성 GPU3D 경과 시간이다. 제출 사이의 공백을 포함하고 CPU readback은 제외한다. 게임 FPS, 물리 입력·오디오 지연, 다른 GPU, OpenGL·Vulkan·Metal 사이의 순위와는 무관하다. 이전에 만든 비공개 명령열 probe도 32사례의 픽셀이 일치했지만 호스트 제출과 시간이 달라 릴리스 주장에는 쓰지 않았다. 새 외부 코드나 라이브러리는 도입하지 않았다.

# 1.1.208 — 캡처 뱅크별 무효화·Sinc 위상 공유·Thumb 시프트

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

- Vulkan 캡처 텍스처: 성공적으로 완료된 GPU 캡처의 물리 뱅크별 revision을 기록한다. 텍스처 범위의 소유권 마스크와 해당 뱅크 revision으로 캐시를 무효화해 무관한 뱅크 갱신의 재디코드·업로드를 생략한다. 전체 뱅크를 지우는 초기화/복구는 모두 갱신하며 실패한 배치는 완료 revision을 공개하지 않는다. CPU 변경·소유권 변경과 source-bank 갱신은 계속 반영한다.
- Sinc 채널 보간: period≥mixPeriod일 때 인접 계수 위상 두 개를 기존 `DotFloatStereo`로 계산한다. 두 입력은 스테레오 채널 대신 계수 위상이며 SIMD 경로에서 공통 history를 한 번 읽는다. 유한 곱셈의 교환 법칙을 이용하고 각 위상의 누적·lane reduction·위상 보간·반올림 순서는 유지한다. 탭·계수·MAC·다운샘플 경로를 바꾸지 않는다.
- x64 Thumb 레지스터 시프트: LSL/LSR/ASR/ROR의 결과를 mapped Rd에 직접 계산해 scratch 왕복 MOV 두 개를 제거한다. 원래 count를 ECX에 먼저 보존하므로 Rs=Rd도 처리한다. ARM 호출자는 기본 scratch를 유지하며 count 하위 8비트·0/32/큰 값·carry·guest 사이클을 보존한다.

텍스처 무효화의 전역 세대 스캔은 남고 관련 뱅크마다 작은 해시 계산이 추가된다. 같은 물리 뱅크의 다른 줄이 바뀌어도 무효화하므로 줄별 최적화는 아니다. Sinc 스칼라 경로는 기존 dot 루프 두 개를 유지하며 실행 경로 선택만 공유한다. SIMD 읽기는 코드의 논리적 읽기이며 물리 메모리 트래픽·캐시 miss 감소 측정값이 아니다. 다른 프로그램을 사용 중인 PC의 시간 변동을 성능 근거로 쓰지 않았다. 게임 FPS·구형 기기 전체의 속도·음질 개선을 주장하지 않는다. 새 API/ISA 요구는 없고 GPU2D 기본 비활성은 유지한다.

## 검증

- 실제 Vulkan 캡처→텍스처 렌더링과 소프트웨어 화면 전체가 일치했다. B 텍스처를 쓰며 D를 갱신해도 256×256 이미지 업로드 수는 늘지 않고, B를 파란색으로 재캡처하면 한 번 갱신된다. CPU OR 기여분 쓰기와 마지막 GPU 소유권 해제도 확인했다.
- 기존 재사용/COW 캡처 실패 주입에서 실패 전후 뱅크 revision은 같고, 성공한 재시도는 쓴 뱅크만 갱신한다. 지연 제출·기존 캡처 수명 검사도 같은 집중 검사에서 통과했다.
- Sinc 이전 소스와 새 소스의 x64 AVX2/FMA·SSE2·각 강제 스칼라 구성에서 각각 2,972,160개 `AudioSinc::Output` 정수값 해시가 일치했다. 다섯 period·여섯 elapsed 경계·세 reset 값·난수/극값/임펄스·ring wrap을 포함한다. 이는 믹서 전 채널 출력의 대조이며 ARM64 구버전 직접 대조는 수행하지 않았다. 기존 Sinc 이력·savestate·최종 출력 검사도 SIMD/스칼라 양쪽에서 통과했다.
- Thumb 레지스터 시프트의 수계산 alias 경계와 기존 경계 입력을 실행했다. ARM7/9·일반 JIT/fastmem·carry·부분 플래그·컴파일/재실행 포함, ALU 각 8,964건과 기존 Thumb shift timing 검사 통과.
- 로컬 집중 검사 총 7개 통과. full suite는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

# 1.1.167 — 조건부 ARM9 JIT 사이클 이중 과금 수정

2026-09-23. Windows UCRT64 Release. 이전 버전 1.1.166.

ARM9 JIT가 조건부 PC 로드의 일반 코드 접근 사이클을 이미 블록의 공통 비용에 넣은 뒤, 조건 실패 경로에서 다시 더할 수 있었다. 실제 명령 `0x18BD8FF8`을 건너뛰는 회귀 사례는 수정 전 인터프리터 18사이클, 네이티브 JIT 36사이클이었다. 이제 해당 명령의 공통 비용이 이미 누적됐으면 실패 경로에 중복 추가하지 않는다. 명령이 실행되는 조건 경로와 건너뛰는 경로를 모두 비교하는 회귀 사례가 통과했고, 관련 JIT·fastmem·MPU 집중 테스트 15개가 통과했다. 별도 정적 검토에서는 현재 x64 JIT 핸들러에 이 조건의 반례를 찾지 못했다.

같은 개발 바이너리와 사설 Solatorobo 입력으로 12,000프레임 연속 실행한 최종 PPM과 6,000프레임 저장 후 재개한 최종 PPM은 다시 동일했다(256×384, 다른 픽셀 0개, SHA-256 `19bd1dbe3d1ac85771d52a737ca3c70a84c4ed04596aa12fabccd0469784c28b`). 두 실행은 exit 0이었고 ROM·입력·기존 save·작업 중인 teakra 파일은 보존됐다. 사설 원시 기록은 `local-docs/bv17-jit-cond-long-20260923/`에 있다.

JIT 전체 저장 상태 일치는 아직 달성하지 못했다. 기본 최대 블록 크기 32에서 캐시 유지/재설정 경로는 같은 목표 시각을 서로 다른 JIT 블록 경계에서 지나쳐, 6,001프레임의 ARM9 레지스터·타이머 상태가 달라진다. 최대 블록 크기 1의 같은 실험에서는 저장 파일의 `ARM9.CurInstr` 4바이트 외의 상태가 일치했지만, 이를 성능 검토 없는 제품 설정 변경의 근거로 삼지 않는다. 실제 Qt 화면·오디오/물리 장치·모든 게임의 장기 재개 수락도 별도 대상이다.

제품 커밋 `bb094c3b`의 독립 소스 `build/1.1.167-source`에서 Release 빌드 exit 0, 전체 CTest **1,023/1,023** 통과(205.38초). 실행 파일의 빌드 소스 식별자는 `580e3e3fe05b0d1b8a762ff2ec2fdcd1b5fbe8c2af20b754a6e96ea3f8919cf4`이며 독립 소스의 현재 식별자와 일치한다. 기존 작업 중인 teakra 파일은 빌드·커밋에서 제외했다.

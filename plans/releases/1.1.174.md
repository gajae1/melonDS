# 1.1.174 — 인터프리터 LDM/STM 선택 레지스터 순회와 Software 2D 창 구간 채우기

2026-09-24. 이전 버전은 1.1.173이다. 기본 배포는 SDL2이고 SDL3는 `ENABLE_SDL3=ON` 선택형 빌드다.

ARM 인터프리터의 LDM/STM과 Thumb PUSH/POP/LDMIA/STMIA가 16개(또는 8개) 레지스터 비트를 모두 검사하던 루프를, 선택된 비트만 낮은 번호부터 순회하도록 바꿨다. 전송 순서, 첫 접근의 비순차 타이밍, 베이스 레지스터 포함 규칙, 사용자 뱅크 전송, abort 시 조기 반환과 베이스 복원은 그대로다. HEAD와 후보 인터프리터를 실제 ARM9/ARM7 핸들러로 구동한 925,688개 사례(실제 MPU data abort 110,550건 포함)에서 레지스터·뱅크·CPSR·RAM·파이프라인·사이클 기록이 모두 같았고, 비순차 타이밍 변이는 두 CPU에서 검출됐다. 12쌍 교대 측정에서 드문 레지스터 목록은 중앙값 −24.8%(136/144), 촘촘한 목록은 −7.4%(104/144)였고 변경 없는 대조군은 A/A 잡음 안이었다.

Software 2D의 창 마스크는 256픽셀마다 창 좌표를 검사하는 대신 가로 래치 사건으로 결정되는 최대 두 구간을 채운다. `x1>x2` 줄바꿈, `x1==x2`, 세로 비활성 중 래치 갱신, 0x3 정확 조건과 바깥<OBJ<WIN1<WIN0 순서를 유지한다. 두 엔진의 `DrawScanline_BGOBJ`로 구동한 4,216,592개 사례(가로 좌표 65,536쌍×래치 상태 전수 포함)에서 창 마스크·합성 행·최종 래치가 모두 같았고 4개 변이가 검출됐다. 창이 켜진 행의 마스크 구성은 합성 측정에서 2.1~7.1배 빨라졌고, 창이 없는 대조군 차이는 A/A 위치 편향 안이었다. 두 결과 모두 함수 단위 합성 부하이며 게임 FPS 향상은 주장하지 않는다.

비공개 게임 두 개의 헤드리스 Software 1200프레임 ABBA 실행에서 1.1.173과 1.1.174의 최종 화면·누적 PCM·프레임버퍼 digest가 같았다.

같은 라운드에서 fog/AA R·B 묶음 계산(전수 산술 동일, 시간 이득 없음), ADPCM 크기표(제품 빌드의 인라인화로 16채널 부하 약 3% 느림), OBJ 우선순위 버킷(촘촘한 장면 +17~34% 느림), OpenGL 동일 UBO 전송 생략(호출당 약 0.03µs 이득에 비해 전역 상태 추가와 실패 경로 변경)은 채택하지 않았다.

SDL2 전체 CTest는 첫 실행에서 1021/1023이 통과했고, 동시 빌드 부하 중 제한 시간을 넘은 `pgo-profile-contract`·`package-source-identity` 두 도구 검사는 단독 재실행에서 각각 11.2초·20.5초로 통과했다.

# 1.1.219 — Sinc 무음 구간의 필터 연산 생략

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

Sinc 채널 필터의 이력은 최대 32,768개 샘플이다. 기존 코드는 이력 전체가 비워지기 전까지, 현재 필터가 읽는 범위가 이미 모두 0이어도 계속 계수·dot를 계산했다. 이제 최신 연속 0 샘플 수를 포화 카운터로 추적해 고정 48탭 또는 다운샘플링에 필요한 확장 범위가 모두 0이면 출력 0을 즉시 반환한다.

전체 이력과 전체 링에 대한 Empty 의미는 유지한다. 현재 짧은 범위의 출력이 0이어도 타이머가 바뀌면 더 긴 범위의 과거 샘플을 다시 참조할 수 있다. 저장 상태에는 기존 Head와 이력만 기록하고, 정상 복원 후 파생 카운터를 다시 계산한다. 계수·탭·합산 순서·SIMD 선택·오디오 버퍼·클록 보정 설정은 바꾸지 않았다.

## 검증과 한계

- 같은 회귀 입력을 이전/새 코드에 적용한 자동 SIMD 및 강제 scalar 검사에서, 각각 1,980개 출력과 저장 상태 5개의 서명 `f71a19652aed948a`가 일치했다. 생성·reset, 링 경계, 짧은/긴 필터 범위와 타이머 변경, 중간 무음 복원, 새 음 재생을 포함한다. 기존 SPU 이력·HOLD·출력률·모드 전환 검사도 통과했다.
- 해당 검사는 전체 core 타깃이 있어야 등록된다. CI의 x86 JIT ON/OFF 및 ARM64 실행 목록에 기존 `audio-sinc-history`와 scalar 검사를 추가했다. 테스트 성공을 물리 오디오 청취로 취급하지 않는다.
- GCC16 -O3로 이전/새 함수를 따로 빌드해 순서를 교차한 7회 중앙값을 비교했다. 무음 이력이지만 전체 링에는 이전 음이 남은 입력에서, period512는 약 20.5→2.7ns, period256은 172→4.2ns, period1은 46,097→5.3ns/Push+Output이었다. 이는 정해진 함수 입력의 비용이며 실제 게임의 무음 빈도나 전체 프레임 성능을 보여 주지 않는다.
- 비영 샘플의 긴 표본은 period512 약 24.9→24.7ns, period256 약 195.8→195.5ns였다. 0/비영 혼합은 각각 약 26.1→26.6ns 및 194.2→186.8ns였다. 사용 중인 호스트에서 측정했으므로 작은 차이를 일반적인 향상·회귀로 단정하지 않는다. 초기 짧은 표본의 period256 약 13% 지연 증가는 긴 표본에서 재현되지 않았으며 초기 결과도 보존했다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- 게임 플레이·장기 청취·물리 입력/오디오 지연·구형 기기 전체 성능은 측정하지 않았다. 무음 계산 생략을 음질 개선이나 틱 노이즈 완전 해결로 주장하지 않는다.

# 1.1.237 — Vulkan→GL GPU 화면 공유

2026-09-29. 핵심 회귀 검증을 통과했고 SDL3·SDL2 패키지와 플랫폼 CI는 준비 중이다.

1.1.237은 Windows에서 네이티브 Vulkan 표시를 사용할 수 없을 때 같은 GPU의 OpenGL로 화면 이미지를 공유한다. 지원되는 확장 해상도 출력은 평상시 GPU→RAM→GL 왕복을 생략한다. 일반 1배 출력과 지원되지 않는 장치에는 RAM 폴백을 유지한다. 공유 실패 후 복구와 실제 GL 폴백의 VSync 설정도 수정했다. 합성 전달 구간의 이득을 확인했지만 게임 FPS·물리 지연은 미측정이다.

## 구현 범위

- 네이티브 Vulkan WSI의 기존 지원 조건은 유지한다. Windows에서 해당 표시가 초기화되지 않으면 GL 화면 패널을 시도한다. GPU·드라이버 UUID와 외부 메모리·세마포어 지원이 일치할 때 Vulkan R32_UINT 출력 이미지를 GL에서 직접 읽는다.
- 출력 전환 시 기존 픽셀을 GPU 내부에서 한 번 복사한다. 이후 두 화면의 더블 버퍼를 재사용하며 반복 표시에도 소유권·세마포어 인계를 수행한다. 평상시 공유 표시는 화면 다운로드·GL 픽셀 업로드를 하지 않는다. 스크린샷·게스트 캡처 등 CPU 소비자는 기존 경로를 유지한다.
- 내보낸 핸들은 GL 가져오기 객체를 삭제할 때까지 보존한다. 완료 여부가 불명확한 인계 실패는 해당 장치를 중지하고 관련 자원을 보존한다. 이는 실패 후 프로세스 종료까지 남는 제한적인 자원 보존이며 정상 경로의 해제와 구분한다.
- 실패한 장치에서 마지막 GPU 화면을 읽으려다 복구가 반복되는 경로를 차단한다. 소프트웨어 표시 복구와 실제 GL 폴백의 VSync 설정·출력 상태 표시를 맞춘다.
- Native2D의 공유 출력은 내부 선택 경로와 검사에 포함된다. 일반 사용자 설정에서 Native2D를 새로 활성화하지 않으며 기본 1배 표시의 CPU 왕복 제거를 주장하지 않는다.

## 검증과 한계

- AMD Radeon 내장 GPU에서 실제 Device·외부 메모리·GL 공유 헬퍼로 두 화면, 버퍼 재사용, 재표시, 재생성, 실패 후 재제출 거부를 확인했다.
- VulkanDirectDisplay external: 확장4배 출력과 Native2D1배·3배, 늦은 공유 전환, 명시적 CPU 읽기, 해상도 변경과 기존 메모리 부족 폴백을 확인했다. Native2D 화면은 소프트웨어 렌더러와 픽셀 단위로 일치했다.
- GLPresentation external-display: 실제 Screen 그리기 함수를 사용해 Native2D1배·확장3배의 두 화면을 소프트웨어 기준 화면과 비교했다. 공유 표시 동안 CPU 다운로드가 없고 화면 재표시·렌더러 교체·GL 재초기화가 동작했다. GLLoaderBoundary·deinit-recovery·설정 UI·메시지 게이트 검사도 통과했다.
- 실제 화면 셰이더의 최근접·선형 필터와 회전을 별도 숨은 GPU 검사로 확인했다. 소수 배율의 CPU 분석 좌표 오차는 실제 GPU 보간 좌표를 관측해 분리했다. 최초 허용 오차를 유지한 비교에서 색상 계산이 일치했다. 허용 오차를 넓힌 중간 결과는 채택 근거로 사용하지 않았다.
- 합성 전달 구간에서 32개 교차 표본의 중앙값 RAM/공유는 1배329.9/313.6µs, 3배1863.8/408.4µs, 4배4323.7/483.4µs였다. 두 경로에 같은 단순 셰이더와 완료 대기를 사용했다. 기준 경로에는 CPU 복사가 있고 실제 직접 매핑 합성 경로는 이를 생략할 수 있다. 최종 필터·화면 교환·전체 에뮬레이션 비용은 포함하지 않으므로 배포판 프레임 절감량이나 FPS 향상률로 환산하지 않는다.

사용 중인 PC의 다른 작업을 종료하지 않았고 게임 플레이·화면 활성화는 하지 않았다. Vulkan 검증 레이어는 설치되어 있지 않았다. 오디오 틱 노이즈·물리 입력 지연·다른 GPU 드라이버의 실기 결과는 이번 검증 범위에 없다. 전체 회귀 검사는 CI에서 실행한다.

## 패키지

SDL3 기본·SDL2 호환 패키지와 필수 플랫폼 CI는 준비 중이다. 설치 앱·GitHub tag/release는 변경하지 않았다.

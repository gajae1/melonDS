# 1.1.138 — 반전·affine bitmap OBJ의 캡처 디테일 보존

2026-09-18. 기준 1.1.137 `4e841dbd`. 메인 checkout과 빌드는 `F:/melonDS`, `build/windows-dev`다.

## 구현

Vulkan 표시용 캡처 bitmap OBJ를 X/Y 반전과 affine 변환으로 확장했다. 양 engine의 native 주소 배치와 OAM 순서를 재사용하며, 표시용 서브픽셀 오프셋에 행렬의 두 열을 모두 적용한다. 음수·범위 밖 좌표를 나눗셈 전에 검사하고 64비트 중간값을 쓴다. 분수 확대, shear, 회전, 음수 계수, double-size 및 화면 clipping을 포함한다.

각 native 픽셀 원점의 후보는 그대로 보존한다. 반전은 원본 native 샘플 원점을 기준으로 하므로 한 texel 안의 샘플 순서만 뒤집는 방식과 다르다. 반전 끝 가장자리에서는 원본 좌표 0을 벗어난 표시 서브픽셀 띠가 잘릴 수 있다. 분수 affine에서도 native 원점은 기존 결과로 고정한다. 이 규칙은 guest 픽셀 보존을 위한 표시 계약이며 실기 고해상도 출력의 재현 주장이 아니다.

정수 identity는 기존 캡처 행 조회 경로를 쓴다. 일반 변환은 캡처 행을 즉시 소비한다. 일부만 캡처된 OBJ의 나머지 영역, 무효 행, 중복 bank mapping, 배율 불일치는 해당 목적지의 native 후보를 유지한다. 다른 캡처 OBJ가 같은 행을 활성화해도 native-only 부분을 임의로 자르지 않는다. CPU/DMA용 VRAM·savestate 형식·사용자 설정은 변경하지 않는다.

## 검증

Pro의 수정 전 관측에서 양 engine의 3배율 변환 16개는 각각 표시 픽셀 13,690개가 달랐고 고정 색상 지점 22개 중 10개가 실패했다. native 픽셀과 캡처 VRAM 검사는 통과했다. 좌표·색상 oracle와 고정 지점을 사용하며 LCDC 향상 경로만을 정답으로 삼지 않는다.

부모가 현재 소스로 melonDS·VulkanRendererIntegration·GLFrameReadback 빌드 exit 0과 양 engine 1·3·5배율 OBJ CTest **6/6**, 실패·skip 0, **3.38초**, exit 0을 확인했다. 실행 전후 4개 renderer/test 파일의 Git blob 해시는 동일하다. 엔진 A 3배율 직접 실행에서는 변환 16개와 고정 지점 22개 불일치 0, native 캡처 131,072바이트 보존 및 34개 조건 통과를 확인했다. 로컬 근거는 `local-docs/pro-obj-affine-20260918/parent-matrix.log`, `parent-matrix.xml`, `parent-build.log`, `result.md`다.

Pro 실행은 exit 0으로 완료됐고 선택 모델 확인 및 결과 저장을 확인했다. Pro 최종 소스에서 별도 3배율 engine A 검사와 나머지 선택 CTest **14/14**, 실패·skip·disabled 0, **27.18초**를 통과했다. 기존 Vulkan·LCDC·bitmap BG·software 합성/capture 검사를 포함한다. 부모의 6개 재확인과 중복 합산하지 않는다.

## 남은 범위

모자이크 sprite가 있는 행은 native OBJ를 유지한다. 색인 OBJ의 캡처 향상, 3D texture 캡처 재사용, 전체 GPU 2D/capture, 직접 GPU 표시는 후속이다. 이번 확장의 실게임·DSi·다른 GPU/OS·설치 GUI·장기 사용과 고배율 성능은 미검증이다.

병렬 작업의 일반 OBJ CPU 하네스는 1.1.137의 캡처 lookup을 synthetic 입력으로 대체한 제한 구성이다. 성공한 sanity 검사와 소스/바이너리 식별 자료는 보존했지만 수치 성능 향상이나 게임 FPS 증거로 쓰지 않는다.

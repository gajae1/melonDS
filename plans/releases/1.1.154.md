# 1.1.154 — sanitizer bring-up이 찾은 UB·이식성 수정

2026-09-21. 기준 1.1.153 HEAD aa99598d. 빌드는 93f6 worktree의
build/windows-dev다.

## 구현 — clang64/UBSan bring-up에서 드러난 결함 수정

BV-11 후속으로 MSYS2 clang64(Clang 22.1.8)를 설치하고 실제 sanitizer
빌드·ctest를 실행하는 과정에서 나온 수정 9파일.

이식성(libc++/C++26에서 컴파일 불가):

- MPInterface의 std::atomic<std::shared_ptr>는 C++26에서 제거됐고(P2867)
  libc++에는 specialization이 없다. 짧은 mutex 보호의 plain shared_ptr로
  바꿔 Acquire의 copy-out semantics를 모든 표준 라이브러리에서 유지한다.
- tests/VulkanMemoryType.cpp의 <initializer_list> 누락 보완.

UB 수정(x86에서는 우연히 동작하던 것):

- CP15::CodeRead32·NDS ARM9BIOS/ARM7BIOS 읽기·Savestate magic 비교의
  비정렬 u32 로드를 memcpy로 — strict-alignment 플랫폼 대비.
- ARMJIT_Memory::MapAtAddress의 nullptr+offset 포인터 산술 제거.
- ARMInterpreter_ALU ROR_REG_S의 s=32·64 signed 1<<31/1<<63 UB를
  (s-1)&31 마스크로 수정 — ARM 의미론·결과 동일.
- SPU::BufferAudio의 avail<=0 비양수 VLA·blip_read를 early return으로
  차단 — avail==0이면 쓸 데이터가 없어 동작 동일.

## 검증

- clang64-ubsan ctest 440/441 ×2 — runtime error 보고 0건. 유일 실패
  package-version-boundaries는 clang64 resource toolchain이 만드는 PE의
  문자열 버전 필드 차이이며 ucrt64 출시 경로에서는 2/2 통과로 확인
  (local-docs/bv11-clang64-20260921/).
- clang64-asan은 dynamic ASan runtime이 자체 초기화 중 crash하는
  toolchain 결함(최소 재현 hello.exe 동일 crash)으로 이 PC에서 불가 —
  melonDS 코드 무관.
- ucrt64 windows-dev 전체 리빌드 630 target clean 후 전체 ctest
  990/990(155.30s) 통과.

## 남은 범위·한계

- ASan 경로는 clang toolchain 수정·static runtime 변형 또는 MSVC 포팅
  대기. fastmem과 ASan의 VEH/주소공간 충돌은 runtime이 살아야 검증 가능.
- 수정은 정확성·이식성 범주 — 성능·기능 변화 없음. 실기·다른 OS는
  미검증.

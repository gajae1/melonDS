# 1.1.222 — Vulkan 그림자 상태 저장소 통합

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

Vulkan의 배치 간 결과 버퍼에서 그림자 stencil 2비트와 직전 fragment의 shadow-mask 여부 1비트를 상위 레이어 속성의 미사용 비트 4~6에 저장한다. 다음 배치에서 상태를 추출하고 속성에서 제거한다. clear·불투명·반투명 속성 생성은 이 비트를 사용하지 않으며, 최종 에지 마킹·포그·AA도 이 비트를 소비하지 않는다.

별도 그림자 상태 평면이 없어져 픽셀당 결과 저장소가 7→6워드(28→24바이트)로 줄어든다. 중간 결과를 기록하는 픽셀은 store 하나, 이전 결과를 가져오는 픽셀은 load 하나가 줄고 비트 패킹·추출 연산이 추가된다. 이미 중간 저장을 생략하는 최종 융합 배치와 빈 후속 타일에서는 이 저장 감소를 중복 계산하지 않는다. 색상·깊이 정밀도, 그림자 판정 순서, 배치 경계·동기화, OpenGL 경로는 유지한다.

| 배율 | 이전 결과 버퍼 | 현재 결과 버퍼 | 감소 |
| --- | ---: | ---: | ---: |
| 1 | 1,376,256 B | 1,179,648 B | 192KiB |
| 4 | 22,020,096 B | 18,874,368 B | 3MiB |
| 16 | 352,321,536 B | 301,989,888 B | 48MiB |

이는 해당 결과 버퍼의 14.3% 감소다. GPU 전체 메모리·실제 메모리 버스 전송량·실행 시간·게임 FPS·입력 지연의 개선율은 측정하지 않았다. 16배율 수치는 자원 크기 계산이며 이번 로컬 픽셀 대조는 1~3배율이다.

## 검증

- 기존 `gpu-vulkan-compute-spans`의 그림자 장면을 보강한 검사가 실제 AMD Radeon(TM) Graphics에서 2.14초에 통과했다. 1·2·3배율 Z/W 스팬·장면의 모든 픽셀을 GL 참조와 비교하며 GL 참조에서 shadow draw를 제거하면 출력이 달라짐을 요구해 그림자가 실제 보이는 장면인지 확인한다. 그림자/텍스처 분할 배치, 단일 variant 배치, 1배율 모든 최종 효과 조합과 빈 마지막 배치를 포함한다.
- 기존 `vulkan-resource-limits`의 1~16배율 허용·거절·제한 장치 검사가 통과했다. 생성 Vulkan 셰이더의 빌드·SPIR-V 검증도 완료했다.
- 처음 Qt offscreen 플랫폼 플러그인에서는 GL context 생성이 불가능해 GPU 검사가 건너뛰어졌다. Windows 플랫폼 플러그인과 기존 비표시 QOffscreenSurface를 사용한 실제 통과 결과를 위 근거로 사용한다. 창을 띄우거나 게임을 플레이하지 않았다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

별도 Native2D 루프 불변 읽기 이동 후보는 채택하지 않았다. `spirv-opt -O` 비교에서 대부분 이미 루프 밖으로 이동했고 작은 잔여 감소만 남았다. 드라이버 ISA·실행 시간·레지스터 점유는 측정하지 않았으므로 속도 저하나 개선을 단정하지 않는다.

# 1.1.211 — Vulkan native 2D 캡처 copy-on-write 초기 복사 축소

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

- Vulkan native 2D 캡처 파이프라인은 copy-on-write로 새 배치를 시작할 때 이전 뱅크 512KiB 전체를 새 뱅크로 복사했다. 1.1.211은 COW 경로에서 배치의 각 명령이 소스 B(`gpuMask|hiresMask`)를 목적지 쓰기 전에 읽는 구간과 실제로 쓰는 구간을 256바이트 segment 2,048개(512KiB)로 추적한다. 목적지 쓰기 전의 읽기는 `initialReads`, 누적된 목적지 쓰기는 전역 `written`으로 기록하며 이 정보는 dispatch 경계를 넘어 유지된다.
- 초기 device→device 복사에서 `written&~initialReads`(나중에 다시 읽히기 전에 덮어써지는 구간)를 제외하고, 남은 보존 구간을 같은 src/dst offset의 `VkBufferCopy` 목록으로 병합해 `vkCmdCopyBuffer` 한 번에 기록한다. 쓰지 않은 뱅크 구간와 이전 스냅샷은 보존한다. 첫 접근이 완전 덮어쓰기인 구간은 초기 복사를 생략할 수 있고, 초기 self-alias와 읽기-후-쓰기는 보존해야 한다.
- COW 선택 뒤 `Begin`이 실패해 재시도할 때도 원래 `previousBanks`를 보존하고 재시도 명령에 대해 분석을 다시 계산한다. 비-COW 경로는 분석을 수행하지 않으며 할당 512KiB·배리어·fence는 그대로다.

## 작업량과 한계

| 조건 | 1.1.210 | 1.1.211 |
| --- | ---: | ---: |
| COW 초기 뱅크 복사량 | 이전 뱅크 512KiB 전체 | 최대 128KiB 생략(384~512KiB) |
| 초기 복사 기록 | 전체 크기 복사 1개 | 보존 구간 병합 목록 1회 |
| 새 CPU 비용 | 없음 | 명령 2차 순회·2,048 segment 스캔·copy region 증가 |

추적 단위는 256바이트 segment 2,048개이고, 한 배치는 최대 256개 명령 × 2 segment = 128KiB까지 생략하므로 남는 복사는 384~512KiB다. 보존 구간 목록은 보수적 상한 513개로 재사용하며 한 번의 `vkCmdCopyBuffer`로 보낸다. 명령 2차 순회·segment 스캔과 늘어난 copy region은 새 CPU 비용이다. 물리 DRAM 트래픽·게임 FPS·처리 시간 향상률을 측정한 것은 아니며 그 수치로 제시하지 않는다. 비-COW 경로와 오디오·JIT는 변경하지 않았고 새 ISA·API 요구나 기본 설정 변경은 없다.

## 검증

- 로컬 `gpu-vulkan-native-deferred`가 2.44초에 통과했고 새 full 512KiB CPU oracle·현재 스냅샷·이전 스냅샷 검사를 포함한다. 192 overwrite rows는 524288→425984바이트(512→416KiB)를 정확히 한 번의 복사 호출로 처리했다. self-alias는 0, WAR 후 RAW는 1024, 쓰기-후-나중-읽기/self는 1024, 마지막 뱅크 경계는 256, hires native B fallback은 1024바이트를 생략했다.
- COW 선택 뒤 begin-failure/retry 검사도 통과했다.
- full suite는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

# 1.1.171 — JIT 유휴 루프의 실행 사이클 보존

2026-09-24. 이전 버전은 1.1.170이다. 기본 배포는 SDL2이고 SDL3는 `ENABLE_SDL3=ON` 선택형 빌드다.

ARM9 x64 JIT의 캐시된 블록이 DIV/SQRT 레지스터를 쓴 다음 폴링 루프에 들어가면, 새 이벤트가 목표 시각을 블록 진입 후 25사이클로 당길 수 있었다. 같은 게스트 PC·레지스터 상태에서 캐시 경로와 새 컴파일 경로 모두 110사이클의 명령을 실행했지만, 캐시 경로는 `IdleLoop=1`을 세워 이미 실행한 110사이클을 버리고 25사이클만 전진했다. 첫 컴파일 경로는 110사이클을 반영했다. 비공개 추적은 두 경로의 DIV/SQRT 쓰기 값·순서·예약 시각과 블록 종료 레지스터가 같음을 확인했다.

이번 변경은 ARM9·ARM7에서 유휴 루프에 들어가기 전 이미 실행한 사이클을 먼저 시각에 반영하고, 목표 시각까지 남은 유휴 시간만 건너뛴다. 유휴 분기 최적화는 블록 전체가 순수 폴링 루프인 경우에만 붙인다. 첫 컴파일 추적도 실제로 분기를 택했을 때에만 캐시된 경로와 같은 유휴 플래그를 설정한다. DIV/SQRT 쓰기 같은 접두 작업을 유휴 시간으로 취급하지 않도록 한 보정이며, 명령별 하드웨어 타이밍 정확성까지 증명한 것은 아니다.

ARM9·ARM7의 차가운 컴파일/캐시 재사용, 목표 시각이 블록 비용보다 짧은 경우, 남은 유휴 시간, 쓰기 접두부를 확인하는 집중 회귀 검사는 수정 전 잘못된 `timestamp=101`과 `pending=84`를 검출했고 수정 후 통과했다. 같은 비공개 게임 입력의 프레임 6000 직전 savestate는 기준/저장 후 JIT 리셋 경로에서 동일하다. 프레임 6001의 화면·게스트 MainRAM/WRAM·ARM7·타이머 저장 구간은 같지만 저장 파일 전체는 다르다. 남은 차이는 ARM9의 현재 명령 기록 4바이트와 비어 있는 GPU3D FIFO의 커서·지난 슬롯 내용이다. 중간 Timer5 기록의 갱신 경계도 다르다.

프레임 12000까지의 기준/리셋 비교에서는 프레임 6000 이후 **6000개 화면 해시와 최종 PPM이 모두 일치**했다. 최종 MainRAM/WRAM, 양쪽 CPU, 타이머, 활성 스케줄러 상태도 같다. 저장 파일의 남은 차이는 비활성 이벤트 5번 슬롯의 시각 1틱과 점유 수 0인 GPU3D FIFO의 커서·지난 슬롯 내용이다. 빈 FIFO의 과거 슬롯은 현재 GP3D 명령 처리 경로에서 읽히지 않는 것으로 코드에서 확인했으나, 이후 모든 실행의 동등성이나 저장 파일 바이트 일치를 증명하지는 않는다. **BV-17의 정확 상태 일치 수락은 여전히 미완료**다. 비공개 ROM·savestate·원시 계측 파일은 배포하지 않는다.

소스 커밋 `d646232abee94277b94ab7e0e72c3146bbc6dc87`의 깨끗한 복제본에서 Windows UCRT64 Release를 SDL2·SDL3로 각각 빌드했다. SDL2 전체 CTest **1023/1023**, SDL3 오디오·입력 집중 CTest **48/48**을 통과했다. 두 배포·패키징은 모두 exit 0이다. 두 패키지의 소스 ID는 `2ea8242471da67a3faceca3d93188d248a7cc4ae010bd64d04d856c2bd398f16`로 같다. 기존의 다른 작업자 변경은 깨끗한 복제본과 패키지에 들어가지 않았다. 각 런타임 ZIP은 325개 파일이고 검사한 비공개 파일은 0개다. 기본 ZIP에는 SDL2 DLL만, 선택형 ZIP에는 SDL3 DLL만 있다.

두 런타임 ZIP을 각각 새 폴더에 풀고, 한글 이름의 게임 archive와 새 프로필로 첫 실행했다. SDL2·SDL3 모두 `[60/60]` 창에서 실제 게임 화면과 메뉴를 육안 확인했고, `VCDJ` 카트 진입·부팅 로그, `WM_CLOSE` exit 0, 실행 파일·archive·원본 ROM·기존 작업 파일 해시 보존을 확인했다. 비공개 창 캡처 SHA-256은 SDL2 `402369ff0e9513a0e5d6949e914a385a5eda5f50125eb72f9638ac72514aed9d`, SDL3 `e69519994faede1eee737f16c8253ec7a14843fc6ad5df348d071817dc0a298b`이다. 원시 기록은 로컬 `local-docs/release-171-20260924/`에 있다. 메뉴 첫 실행은 실제 조작·저장 영속성·절전 복귀·장기 사용·물리 스피커/마이크/패드 수락을 뜻하지 않는다.

후속 비공개 재개 검증에서는 서로 다른 프레임 12000 상태를 각각 새 인스턴스에 불러와 1000프레임 더 실행했다. 새 입력이 없을 때와 동일한 짧은 버튼 입력 8회를 가했을 때 모두 **1000개 화면 해시가 쌍별로 일치**했다. 버튼 입력은 화면을 실제로 바꿨다. 재저장 상태의 게스트 RAM·CPU·타이머 등 활성 구간도 같았으나 비활성 이벤트 시각이나 빈 GPU3D FIFO의 과거 기록 차이는 남았다. 프레임 6001 상태의 1프레임 재개에서는 ARM9 현재 명령 기록 차이가 사라지고 빈 FIFO 기록만 남았다. 정확 상태 일치와 이후 모든 동작의 동등성은 여전히 수락하지 않았다.

별도 비공개 DSi 게임으로 기본 SDL2 ZIP을 새 폴더에 풀어 실제 키보드 조작과 **게임 자체의 저장·앱 종료·새 프로세스 재실행·이어하기**를 확인했다. 게임의 저장 메뉴에서 확인 후 쓰기가 끝나자 격리된 `.sav` 내용이 바뀌었다. 새 프로세스의 제목 화면은 저장된 플레이어·위치·플레이 시간을 표시했고, `이어하기`는 같은 게임 장면으로 복귀해 이동 입력을 받았다. 원본 게임·DSi BIOS·NAND·기존 상태 파일은 해시가 보존됐으며, 배포본과 소스는 바뀌지 않았다. 이는 한 게임의 DSi 저장 영속성 수락이다. 다른 게임의 저장 지점, SDL3의 실제 게임 저장, 물리 스피커·마이크·패드, 절전 복귀와 장기 사용은 별도로 남는다.

패키지 해시와 첫 실행 기록은 패키징 후 추가한 문서이므로 위 소스 ZIP의 릴리스 문서에는 최종 표가 없다. 실행 코드와 패키지 소스 식별자는 바뀌지 않았다.

# 1.1.217 — 오디오 콜백·컨트롤러 준비 비용 감소

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

SDL3 출력은 처음 콜백이 호출될 때 임시 PCM 벡터를 할당했다. 이제 장치가 정지한 열기 단계에서 실제 협상된 블록 크기만큼 임시 저장소를 준비한다. 큐에 넣는 오디오 양·장치 버퍼 설정은 그대로다. 예상보다 큰 요청은 기존처럼 저장소를 확장하고 요청 전체를 한 번의 생산 콜백으로 전달한다. 1.1.216 클록 보정의 콜백 시각·블록 크기 관측을 보존하기 위해 요청을 작은 콜백들로 나누지 않는다.

SDL은 콜백 요청량이 호출마다 달라질 수 있다고 명시한다. 따라서 이 변경은 협상 블록 이내의 자체 임시 버퍼 할당을 앞당기는 것이며, SDL 내부나 모든 큰 요청에서 할당이 없다고 주장하지 않는다. [SDL 콜백 계약](https://wiki.libsdl.org/SDL3/SDL_AudioStreamCallback), [데이터 복사 계약](https://wiki.libsdl.org/SDL3/SDL_PutAudioStreamData).

컨트롤러의 연결/재시도 경로는 선택한 모델의 GUID를 알고도 모든 현재 장치를 열어 시리얼을 읽었다. 이제 전체 장치의 인덱스·세션 ID·이름·GUID는 계속 열거하되, 알려진 선택 GUID가 있으면 같은 GUID 장치만 시리얼 조회를 위해 연다. 설정 UI와 구형 인덱스 이관의 필터 없는 목록, 같은 모델의 시리얼·모호성 판정, 락·재시도 주기는 유지한다. 대상 장치 자체의 열기는 여전히 실행 경로에 남으며 비동기 장치 관리자를 추가하지 않는다.

## 검증과 한계

- SDL3 dummy 스트림을 열고 물리 재생은 정지한 채 실제 출력 콜백을 수동 호출했다. 첫 협상 블록의 자체 C++ 할당은 이전 코드 1회→현재 코드 0회였다. 반복 요청, PCM 스테레오 순서·바이트 수, 부분 프레임 정렬, 무시할 요청, 더 큰 요청의 단일 생산 콜백 전달도 확인했다. SDL 제출은 고정 수집 버퍼로 대체했으므로 SDL 내부 할당을 검증한 것은 아니다.
- SDL 가상 컨트롤러를 사용해 선택한 GUID와 다른 모델의 시리얼 조회용 열기를 계측하고, 대상 누락 재시도 때 키보드 입력 병합을 유지하는지 확인했다. 같은 모델의 시리얼 재연결·중복 시리얼·열기 실패 회귀도 검사했다. 실제 HID 열기의 시간이나 리듬게임 입력 지연은 측정하지 않았다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- 실제 게임 플레이, 장기 청취, 물리 입력/오디오 지연, 바쁜 호스트의 FPS 비교는 수행하지 않았다. 장치 열기/메모리 할당 횟수 감소를 틱 노이즈 완전 해결이나 프레임 시간 개선률로 환산하지 않는다. 1.1.216의 선택적 클록 보정은 기본 OFF를 유지한다.

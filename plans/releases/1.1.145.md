# 1.1.145 — Vulkan 확대 표시의 GPU 최종 합성(GR-15 후속)

2026-09-20. 기준 1.1.144 HEAD 3b52bd7c. 메인 checkout과 빌드는 F:/melonDS, build/windows-dev다.

## 구현 — final-pass compositor

1.1.144까지 Vulkan 확대 표시는 프레임당 확대 3D 전체를 CPU로 readback한 뒤 스캔라인마다 ComposeScaledLine으로 scale² 픽셀을 CPU에서 합성해 ScaledBuffers에 썼다. 실게임 측정(local-docs/realgame-display-cost-20260920/findings.md)에서 이 경로만 배율 제곱으로 느려졌다(solatorobo tail median 1x 1.21ms→16x 18.30ms, 60fps 갱신 불가). 이번 단위는 GR-16 design.md가 정한 순서의 "최종 프레임의 GPU 합성"이며 설계는 local-docs/pro-vk-compose-20260920/design.md다.

CPU native 스캔라인 파이프라인은 그대로다. SoftRenderer2D에 additive ScaledLineContext export(픽셀별 top/second/below3D pair/window + 라인 blend·brightness·mode·scroll·abort, 약 1MiB/프레임)를 추가하고, Vulkan compute pass(DisplayCompose.comp)가 GPU 상주 확대 3D image와 같은 정수 시맨틱으로 합성한다(Resolve3DPixel·CompositePixel·master brightness·RGB6→BGRA8·RenderXPos wrap). 합성 결과는 readback으로 기존 ScaledBuffers를 채우고 GetDisplayFrame은 계속 CpuBGRA를 돌려준다 — 프론트엔드·generation·이중 버퍼·무효화 계약 무수정.

GPU 합성 활성 시 표시용 확대 3D readback은 생략하고 native origin만 추출한다(NativeReadback.comp, 196,608B — guest/capture 가시성용). capture-layer/capture-display 라인은 CPU가 provenance 경계에서 합성하고 readback이 덮어쓰지 않는다. scale=1은 기존 경로다. 합성 불가 시 기존 CPU 경로로 fallback하고, 래치 후 불가해지면 frozen context로 CPU replay한다.

수명: GPU::StartHBlank이 VCount 215에서 다음 3D 렌더를 시작하므로 pending context는 DrawFrame의 image 재사용·SetRenderSettings·SwapBuffers 전에 flush한다. 라인별 VCount·RenderXPos·AbortFrame은 래치 시점 값이다.

부모 조정: 처음에는 flat/forced-blank 라인도 GPU 경로를 탔으나 실게임 재측정에서 2D-only 화면의 readback 고정비가 회귀로 나타나(black 16x 3.81→7.66ms), Composite3D 라인만 래치하고 나머지는 기존 즉시 CPU fill로 되돌렸다. 전체 2D 화면은 GPU 제출·readback이 없어 1.1.144와 같은 비용이다.

## 남은 범위·한계

- SubmissionCount()는 3D upload/render 범위를 유지하고 새 TotalSubmissionCount()가 display pass를 포함한 장치 합계를 돌려준다(진단 의미 조정 — display 제출이 사라진 것이 아니다).
- 물리 device loss/은퇴 뒤 GPU-only subpixel 복구는 보장하지 않는다 — CPU replay를 시도하고 불가하면 native 가시성을 보존하며 renderer failure를 보고한다(result.md 명시).
- 유지된 GPU image에는 CPU-only capture override 픽셀이 없다 — GpuImage kind로 노출하기 전에 해결해야 한다.
- VkImage 직접 표시·장치 공유/external-memory·acquire/release·전면 GPU 2D/capture 이식은 후속이다.
- 실기·DSi·다른 OS/GPU·대화형 UI·장기 실행·validation layer·실제 OOM은 미검증이다.

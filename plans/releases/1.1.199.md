# 1.1.199 — 캡처 실패 처리와 readback 메모리 fallback

2026-09-28. 릴리스 소스 커밋은 `244125aa80834ffb88d2f4206ec9c84219f07d1a`다. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 수정

캡처 준비가 끝난 뒤 Vulkan 명령 기록 시작이 실패하면, 이전 bank나 아직 복사하지 않은 COW bank를 CPU가 읽을 수 있었다. 캡처 command 목록이 남아 있거나 COW 복사가 완료되지 않은 상태의 `ReadRange`·`Snapshot`을 거부한다. 완료된 revision만 유지하고 재시도 성공 후 새 캡처를 공개한다. 1.1.198 Opus 검토에서 후속 항목으로 남긴 기존 오류 경로를 실패 주입으로 재현하고 수정했다.

두 화면을 함께 읽는 임시 버퍼를 할당하지 못하면 화면별 작은 버퍼로 전송한다. 정상 경로는 기존처럼 두 이미지 복사·한 번 제출이고, fallback은 두 번 제출한다. 같은 배율에서는 fallback을 유지해 매 프레임 큰 할당을 재시도하지 않는다. 배율을 바꾸면 통합 할당을 다시 시도할 수 있다. GPU 명령 기록 전에만 경로를 바꾸며 제출·대기 오류를 재실행하지 않는다.

## 검증과 한계

- 실제 Vulkan 캡처에서 `vkBeginCommandBuffer` 실패를 주입해 수정 전의 잘못된 읽기를 재현했다. 수정 후 재사용 bank와 COW bank 모두 CPU 목적지를 바꾸지 않고 읽기·snapshot을 거부하며, 다음 성공한 캡처의 픽셀과 revision을 올바르게 공개한다.
- 기존 retained 3D·1/3배율 캡처 지연·첫 CPU 요구·savestate·reset·파괴 검사도 함께 통과했다.
- 3배율 두 화면+native 픽셀용 약 3.75MiB 할당을 강제로 실패시키고 작은 할당은 허용했다. 화면별 두 번 제출로 성공하고 모든 픽셀이 독립 소프트웨어 출력과 일치했다. 다음 프레임에서 할당 시도 0회, 같은 프레임 재요구에서 추가 전송 0회를 확인했다. 정상 1/3배율 한 번 제출 검사도 유지한다.
- 기존 캡처 중첩·native 텍스처·확대 캡처 배율 변경·GPU2D 전환 검사 4개가 통과했다.
- Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- ROM 장시간 실행·수동 플레이·구형 GPU 실기 측정은 추가하지 않았다. 실제 전체 메모리 부족이나 장치 손실에서 항상 복구한다는 보장은 아니다. 한 화면 버퍼도 할당할 수 없으면 기존 오류 경로로 전달한다. FPS 향상률은 주장하지 않는다.

근거: `local-docs/native-recovery-199/before-fix.log`, `capture-recovery.xml`, `readback-fallback.xml`, `acceptance-*.log`. GPU2D는 선택형·기본 비활성을 유지한다.

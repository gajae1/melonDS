# 1.1.35 — LAN 대기 상한과 빈 Thumb 스택 명령 검증

기준은 1.1.34(`3481d640d952b54d008bcc1e359ff678c03b1434`), 검증일은 2026-09-12다. NP-02/03·FS-17의 host 대기 경계와 CJ-06의 빈 PUSH/POP 후속을 다룬다. 전체 계획이나 원래 책임 버전의 Vulkan 기능 완료를 뜻하지 않는다.

## LAN 대기와 연속 수신

수신 중 제어 이벤트를 처리할 때 host 시각의 하위32비트가 순환하면 남은 대기를 포기하던 반례를 재현했다. 시작 시각 `0xFFFFFFF8`에서8ms 뒤 이벤트를 처리하면25ms 예산 중17ms가 남아도 다음 정상 command를 읽지 않았다. 한 주기보다 긴 정지도 하위32비트만 비교하면 짧은 경과로 오인했다. 대기는64비트 host 경과 시간으로 계산하고, 남은 시간과 비교한 뒤 좁은 정수로 변환한다. 큐에 기록하는 시각과 기존16ms 유효기간은 유지한다.

`RecvReplies`는 중복 응답·다른 MP 프레임까지 패킷마다 대기를 새로 시작했다. 이제 아직 응답하지 않은 참가자의 첫 유효 응답이 왔을 때만 기존 비활동 대기를 갱신한다. 첫 참가자가20ms, 다음 참가자가40ms에 응답하는 정상 입력은 유지하며, 중복 응답이24ms에 도착해도 남은21ms를 새25ms로 늘리지 않는다. 여러 참가자의 정상 진행을 전체25ms 제한으로 잘라 느린 상대를 탈락시키지 않는다. 만료하면 이미 받은 응답 비트·데이터를 반환하고 남은 전송 큐를 비우지 않아 다음 호출에서 늦은 응답을 받을 수 있다.

host 시각이 아직 변하지 않은 연속 수신도 한 호출에서 최대64개 MP 프레임을 처리한 뒤 반환한다. 각 내부 이벤트 처리의 기존64개 상한은 별도다. 이 변경을 전체 호출의 ENet 이벤트가64개라는 의미로 해석하지 않는다. 설정이0이면 즉시 준비된 응답을 유한한 범위에서 계속 읽으며, 음수는 큰 unsigned 대기로 바꾸지 않고0으로 처리한다. 기본25ms와 정상 양수 설정을 유지한다.

이 상한은 요청하는 대기와 시각 확인 사이의 작업에 적용한다. 운영체제 스케줄링·ENet 처리 비용 때문에 실제 반환이 정확히25ms 이내라는 보장은 아니다. guest timestamp·32μs 응답 창·LAN v1 형식·AID·payload 크기는 바꾸지 않는다.

## 검증

기존 실제 LAN 구현 fixture에 서비스 이벤트 시각과 ENet 대기 인자 관측을 추가했다. 느린 참가자 대조에서는 요청한 대기 안에 도착할 수 없는 프레임을 전송 큐에 남긴다. 별도로 복제한 시간 계산 함수를 검사하지 않는다. 변경하지 않은1.1.34 LAN 소스와 최종 fixture를 함께 빌드한 대조는39/44이며, 정상 느린 참가자는 통과하고 다섯 오류 그룹이 실패했다. 최종 수정본은44/44, 해당 CTest1/1이0.39초에 통과했다. 일반/순환 시각·만료·긴 정지·역행, 정상 순차 응답·중복·늦은 peer 재수신, 연속 프레임 뒤 재개,0/음수 설정을 포함한다.

정상 Thumb 스택 명령은 interpreter12/12, x64 JIT24/24, fastmem24/24의 상태 검증을 통과했다. 각 JIT 모드의24건 중18건은 이미 생성된 블록의 직접 native dispatch이며6건은 초기 compile/interpreter 경로다. 전체 Windows Release 빌드와 **CTest634/634·실패0·건너뜀0**, 실제 application object로 실행한 Qt 설정·Cancel·실패 복구·재시도·생성 guest 상태 보존이 통과했다. 전체 CTest는 병렬도2로 한 번 실행했으며80.17초였다. 실제 배포 EXE의1.1.35 및 source ID가 현재 소스와 일치했고 빈 실행 폴더에서 추가 파일을 만들지 않았다. 커밋·EXE·패키지 해시는 배포 manifest에 기록한다.

## 빈 Thumb 명령과 확인한 정상 경계

[ARM Architecture Reference Manual, DDI 0100I](https://documentation-service.arm.com/static/5f8dacc8f86e16515cdb865a)의 A7.1.49/50은 bits[8:0]이 모두0인 `B400` PUSH {}와 `BC00` POP {}를 UNPREDICTABLE로 지정한다. 빈 ARM/Thumb LDM/STM의 동작을 이 두 인코딩으로 추정 확장하지 않았다. 제품 load/store 코드는 유지하고, 두 CPU의 interpreter·cached x64·fastmem을 합친 총40회 관측을 별도로 보존했다. 현재 interpreter는 이전 DataCycles의 영향을 받고 cached x64는0사이클로 반환하지만, 이를 실리콘 정답이나 정확성 통과로 판정하지 않는다.

bit8이1인 `B500` PUSH {LR}와 `BD00` POP {PC}는 정의된 명령이다. 스택 저장/로드·SP·주변 메모리·다른 레지스터·CPSR, ARM7의 Thumb 유지와 ARM9의 odd/even 주소 상태 전환을 검증했다. ARM7 LR-only에서 인위적 C=4 조건의 interpreter13/JIT10사이클 차이도 관측했다. 정상 상태60건의 성공은 절대 타이밍 일치를 뜻하지 않으며, 메모리/파이프라인 조건을 확인할 후속 항목으로 남긴다. native A64 실행 및 두 raw 빈 명령의 직접 하드웨어 증거는 확보하지 않았다.

## 남은 조건

- 자동 네트워크 조절은 아직 도입하지 않았다. host 대기 사용량·빈 반환·부분 응답·큐 나이와 적체·처리 상한 도달을 관찰하는 계측이 다음 단계다. 샘플·초기화·상한·기본값 복귀를 정한 뒤 자동조절을 평가한다.
- 실제 두 PC·구버전 혼합 게임·지터/손실/재정렬·절전·물리 장치·다른 OS/native ARM64는 별도 수락 조건이다. 생성 패킷과 모델 검증을 실기 일치나 게임 호환성으로 확대하지 않는다.
- 일반 게임 저장·설정·LAN v1과 상태 writer14.2를 유지한다.14.2를 읽지 못하는 구버전으로 새 상태 파일을 되돌리는 제한은 그대로다.

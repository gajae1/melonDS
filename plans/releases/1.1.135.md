# 1.1.135 — Vulkan 캡처의 direct-color 비트맵 BG 표시

2026-09-16. 기준 `7fdb93c6`(1.1.134), 메인 `F:/melonDS`에서 중단된 7개 파일을 보존하고 이어서 검토했다.
이 버전은 GR-15/D-004의 비트맵 **배경** 재사용 단계다. 캡처 OBJ·3D texture 재사용과 전체 GPU 2D의 완성은 아니다.

## 구현 경계

Vulkan이 캡처한 RGB555 표시 사본을 engine A/B의 direct-color BG2/BG3에서 참조한다.
기존 native BG/OBJ 렌더링·레지스터 갱신·CPU/DMA용 VRAM 캡처는 한 번만 실행한다.
표시용 후보는 BG0~3·기존 OBJ를 모두 보존하여 고해상도 투명 픽셀이 아래 레이어를 올바르게 드러내도록 합성한다.
창 마스크, BG/OBJ 우선순위, 기존 CompositePixel의 alpha/밝기 규칙을 재사용한다.
Affine 행렬·정수 이동·반전·wrap/범위 밖을 처리하되 모자이크·색인 비트맵·겹친 bank mapping은 native 경로를 유지한다.
합성 결과는 해당 scanline의 새 capture 쓰기 전에 준비한다. 게스트 읽기에 표시용 고해상도 값을 돌려주지 않는다.
CPU alias 쓰기의 provenance 무효화, 1x 전환과 기존 배율의 표시 사본 재샘플링을 구분한다.
표시 후보와 scanline 버퍼는 RAM 객체이며 새로운 디스크 캐시나 저장상태 필드를 만들지 않는다.

## 비용 개선과 남은 성능 문제

1:1 affine 행렬과 정수 이동에는 별도 좌표 경로를 두어 반복적인 64비트 modulo/division을 줄였다.
일반 affine wrap도 중복 modulo를 제거한다. 기존 배율 사본은 필요한 비율 계산을 유지한다.
같은 신규 BG 기능의 일반 좌표 계산과 최적화본을 비교했으며, 고해상도를 보존하지 못하던 1.1.134와의 속도 비교가 아니다.
3x/8x 각각 준비1쌍을 제외한7쌍, 동일 논리 CPU 고정·순서 무작위화, 총32회 실행의 최종 두 화면 checksum이 모두 일치했다.
측정 구간은 synthetic BG의 CPU scanline 처리·확대 합성과 native 반환이며 GPU 초기화/3D raster 시간은 제외한다.

| 배율 | 일반 좌표 경로 중앙값 | 최적화 중앙값 | 해당 합성 시험 시간 감소 |
|---|---:|---:|---:|
| 3x | 10.993218 ms | 6.915793 ms | 37.09% |
| 8x | 78.711250 ms | 48.647137 ms | 38.20% |

CPU 주파수·사용자의 다른 프로그램은 통제하지 않았다. 게임 FPS나 OpenGL 대비 우위로 확대할 수 없다.
특히 8x의 CPU 비용은 여전히 크다. 연속 capture 행을 span으로 읽는 추가 후보의 적용 요청은 차단되어 미반영이다.

## 실행 검증

메인 Windows x64 / CMake4.4.3 / GCC16.2.0 / C23·C++26 / Release / LTO OFF에서 전체 기본 타깃 빌드가 성공했다.
최종 등록 CTest **971/971, 실패0·skip0·disabled0, 155.07초**를 JUnit으로 확인했다. 앱 도움말은1.1.135다.
새 `gpu-vulkan-capture-bitmap-bg` 검사는2/3/5/8배, 양 engine의 affine·우선순위·효과·창·모자이크·배율 전환을 실행한다.
각 배율에서 main63/sub59개의 frame 조건을 확인했다. 이들은 하나의 CTest 내부 조건이며 독립971개 검사에 더하지 않는다.
정수 원점 출력과 native VRAM 보존, 같은 값의 CPU alias 쓰기 후 표시 사본 무효화, 다중 bank mapping의 native fallback을 확인했다.
일반·반투명 OBJ와 captured BG의 겹침은 검증했으나 bitmap OBJ 자체의 고해상도 캡처 참조를 구현한 것은 아니다.
기존 GL·Vulkan·저장·오디오 회귀도 등록 suite에 포함된다. 실제 게임·DSi·다른 GPU/OS·장기 청취는 이번 수락 범위 밖이다.
1~16배의 기존 지원은 유지하지만 신규 BG 확장 조건을16배에서 모두 실행한 것으로 계산하지 않는다.

중단 전 기본 반례의 실패와 양 engine3배 통과 로그를 보존했다. 이번 재개에서 현재 source의 기본/확장 검사를 다시 실행했다.
추가 sub-engine overlap 시험의 첫 실패는 fixture가 VRAM H 대신 WRAMCNT에 쓰던 오류였다.
MMIO 소스를 대조해 H의0x04000248로 고치고 실제 mapping mask assertion을 추가했다. 제품 결함 수정으로 집계하지 않는다.
전체 suite 이후 제품 코드는 바꾸지 않았으며 문서·배포 자료만 추가했다. 빌드 source identity와 최종 commit 대조는 패키지 도구에서 확인한다.

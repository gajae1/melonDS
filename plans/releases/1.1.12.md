# 1.1.12 — 치트 편집의 저장과 적용

상태: 구현·Windows 빌드·로컬 회귀 완료. 기준 1.1.11. FS-15에서 치트 편집·직렬화·파일 commit·실행 적용의 실패 경계를 처리한다.

## 5페이즈

1. **반례:** 정상 mch roundtrip을 대조하고 쓰기/flush 실패, 홀수 코드, 읽기 실패, 저장 실패 뒤 닫히는 창을 재현한다.
2. **코어:** Qt 없이 파일 내용을 먼저 직렬화한다. 로드 실패나 현재 형식으로 보존할 수 없는 입력은 원본을 열기 전에 거부한다. legacy Save는 실제 쓰기 결과를 반환한다.
3. **편집·저장:** 편집용 사본에서 작업하고 QSaveFile commit 성공 뒤 활성 목록을 교체한다. 실패 시 재시도·계속 편집·편집 취소를 제공한다. 실패나 취소에서 원본 파일과 활성 목록을 유지한다.
4. **통합:** Qt 실제 임시 파일·offscreen 창·정상 파싱과 완료 slot·실행 목록 갱신 함수를 연결해 저장/적용/실패 보존을 확인한다. 메시지 대기 경계는 대역으로 두며 최종 Windows 구성에서 전체 회귀를 실행한다.
5. **배포:** 버전·실행 파일·필요 의존성·공개 계획을 검증하고 포크 master에 반영한다. 실제 게임 적용·물리 저장 장치의 전원 손실 수락은 별도다.

코어의 기존 Save API와 Qt의 원자적 파일 교체를 구분한다. QSaveFile을 QFile 기반 Platform FileHandle로 캐스팅하지 않는다. 단순 반환값 확인만으로 Qt의 기존 FileWriteFormatted가 감추는 쓰기 실패를 해결했다고 주장하지 않는다.

## 변경과 근거

| 경계 | 수정 전 | 수정 후 |
|---|---|---|
| 편집과 닫기 | 편집이 활성 트리를 바로 변경하며 Save 실패 후에도 창을 닫음 | 부모 포인터를 다시 연결한 편집 사본 사용. 실패 시 Retry/Discard/Cancel로 재시도·편집 취소·계속 편집 |
| 직렬화·로드 | 홀수 코드·과도한 이름·부분 읽기·일부 쓰기 실패를 안전하게 전달하지 못함 | 표현 가능한 mch 전체를 먼저 직렬화. 실패한 로드는 이전 트리를 보존하고 Error로 저장을 차단. 기존 Save는 실제 write/flush/close 결과 반환 |
| 파일 교체 | 원본을 직접 열어 부분 쓰기에도 내용이 바뀜 | QSaveFile 임시 파일에 완전히 쓰고 commit 성공 후 활성 목록과 교환. 게임 파일이 바뀐 편집 창은 저장·적용 거부 |
| 실행 적용 | 창 종료가 unpause만 수행하여 편집한 목록이 실행 목록에 반영되지 않음 | 성공한 완료 결과에 기존 enableCheats 메시지를 전달하고 대기한 뒤 재개. 비활성 설정과 실패 시 이전 실행 목록 유지 |
| 카테고리 옵션 | 여러 활성 코드에 OnlyOne을 설정하면 재로드 전후 의미가 달라짐 | 항목 Save에서 기존 첫 활성 코드 유지 규칙을 모델에도 즉시 반영 |

[Qt QSaveFile 문서](https://doc.qt.io/qt-6/qsavefile.html)의 임시 파일·commit 경로를 사용하며 직접 덮어쓰기 fallback은 기본 비활성 상태를 유지한다. 코어는 Qt 의존성을 추가하지 않는다.

## 실행 검증

코어 기존 API 반례는 **13개 중 12개 실패**, 정상 대조 1개 통과였다. 새 Serialize API를 포함한 코어 검증 **14/14 통과**를 확인했다. 루트/카테고리/설명/한국어·빈 목록·CRLF/마지막 줄·OnlyOne 로드 규칙과 짧은 쓰기·오류·flush/close 실패, 접근 거부·진행 없는 읽기·잘린 이름·구문 오류에서 파일·트리·Parent를 대조한다. 직렬화는 127바이트 이름·255바이트 설명의 기존 파서 한계와 CR/LF/NUL·선행 공백·중첩 카테고리·홀수 word를 검사하며 실패 시 출력 문자열도 보존한다.

Qt 수정 전 닫기 경로는 정상 적용·open 실패·짧은 쓰기·게임 변경의 **4개 반례가 모두 실패**했다. QWidget·실제 치트 목록/항목 편집·QMessageBox와 생성 파일을 사용한다. 완료 slot과 EmuInstance::enableCheats는 현재 소스에서 추출하고 에뮬레이션/메시지 대기는 대역으로 연결한다. 부분 쓰기는 실제 임시 파일에 쓰기 일부를 주입하며 commit 실패는 cancelWriting으로 주입한다. UI의 성공/실패/재시도/취소·비활성 설정·게임 변경·오류 목록·OnlyOne 변경을 검증한다.

최종 Windows x64 프런트엔드 빌드와 전체 CTest **357/357, skip 0, 27.66초**를 확인했다. 최종 Qt 저장 회귀 10개와 코어 파일 회귀 14개, 기존 JIT·오디오·실제 OpenGL/Compute 출력 검사를 포함한다. UCRT64 GCC 16.2.0·CMake 4.4.3·Qt 6.11.2·SDL 2.32.10, C23/C++26·Release·JIT·OpenGL/Compute·AVX-512 빌드·LTO off 구성이다. FileVersion/ProductVersion은 1.1.12이며 AVX-512 실행은 CPU/OS dispatch 조건을 따른다.

배포 EXE/DLL 129개의 import 누락 0, 독립 PATH의 `--help` 종료 0, 공개 계획 21개의 상대 링크·개인 경로 검사를 확인했다. 패키지는 새 실행 파일과 필요한 DLL/plugin·라이선스로 구성하며 공개 소스 ZIP은 완료 커밋에서 생성한다.

## 남은 범위

실제 게임의 치트 효과·해제, 물리 저장 장치의 전원 손실, 메모리 고갈, 외부 프로그램의 동시 파일 수정과 개인 파일 수락은 별도다. 코어 legacy Save는 실패를 반환하지만 in-place 쓰기의 원자성을 제공하지 않는다. 원본 주석·공백의 byte 보존과 텍스트 파서 전면 교체를 구현한 것은 아니다. 현재 항목의 편집 Save 전 입력 상자 내용은 목록에 확정되지 않는 기존 규칙을 유지한다. 저장 상태 형식 14.1은 바꾸지 않았으며 성능 향상을 측정하지 않았다. 다음 증분은 NP-21 치트 조건·반복 상태의 의미를 기존 명세·정상 입력과 대조한다.

# 1.1.235 — RAM 표시의 두 화면 합성 제출 통합

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 변경

RAM 표시에서 두 화면에 GPU 합성이 필요한 경우 화면별로 제출하고 중간에 CPU에서 GPU 완료를 기다렸다. 캐시 가능·일관성 있는 직접 출력 버퍼가 양쪽에 있으면 두 화면의 합성과 다운로드를 한 command buffer로 묶는다. GPU로 합성한 행만 각 화면의 기존 출력 버퍼에 복사하고 CPU가 채운 Keep·CaptureOverride 행은 보존한다.

1.1.234의 두 작업 세트를 재사용하며, 두 번째 컨텍스트가 없으면 약 0.95 MiB를 할당한다. 화면 크기의 중간 readback 버퍼나 CPU 복사는 추가하지 않는다. 두 요청의 유효성과 버퍼 독립성을 확인하고 필요한 메모리를 확보한 뒤 명령 기록을 시작한다. 최종 CPU 소비 전에는 여전히 펜스 완료를 기다린다.

## 검증과 한계

Radeon 내장그래픽의 실제 렌더러를 호출하는 합성 입력에서 기존 1.1.234는 화면 합성 제출 2회를 기록했고, 수정안은 1회를 기록했다. 프레임 중간에 3D 화면을 바꾸는 입력의 두 화면 픽셀은 CPU 재실행 결과와 일치했다. 일반 단일 화면은 1회, 강제 벡터 폴백은 2회였다. 혼합 CPU 행 보존, 동기·지연 완료, 잘못된 버퍼 거부·재시도와 명령 시작 실패 시 CPU 복구도 확인했다.

기본 NVIDIA 장치의 집중 검사 5개가 통과했다. 기존 resident 합성, RAM/직접 버퍼, CPU 폴백과 진단 관찰 동작을 포함한다. GPU 검사는 로컬에서 수행하며 전체 코어 회귀 검사와 플랫폼 빌드는 CI에서 수행한다. 기존 벡터 경로의 두 번째 화면 시작 실패 검사도 유지했다.

두 화면 모두 합성이 필요한 프레임만 이득을 얻는다. 보통 3D 화면 하나만 사용하는 프레임은 이미 제출 한 번이며 그대로 유지한다. 직접 버퍼를 확보하지 못한 벡터 폴백도 기존 화면별 처리 경로를 사용한다. Radeon에서 GPU 직접 표시를 사용할 수 없는 문제와는 별개로 RAM 출력 경로에 적용된다. Native2D·OpenGL은 이번 변경 대상이 아니다. 게임 FPS·실제 입력/오디오 지연은 측정하지 않았다.

## 구현 — 합성 행의 직접 표시 backing readback

1.1.145까지 GPU 합성 결과는 image 전체를 staging buffer로 readback한 뒤 비보존 행만 ScaledBuffers로 memcpy했다. 16x에서 화면당 최대 ~48MiB의 host copy가 남은 비용이었다(local-docs/realgame-display-cost-20260920/findings.md). 이번 단위는 readback이 합성된 행 범위만 표시 backing의 맞는 오프셋에 직접 기록하게 해 중간 staging과 host memcpy를 제거한다. 분석·채택 기준은 local-docs/pro-vk-present-20260920/analysis.md, 미션은 implement-mission.md다.

확대 표시 backing은 VulkanRenderer 소유의 host-visible 메모리(2 slot x 2 screen의 연속 u32)다. ScaledBuffers는 이제 span이며 기존 소비자 전부 무수정 — mapped backing이 있으면 그것을, 없으면 기존 vector storage(ScaledStorage)를 가리킨다. 메모리 선택은 HOST_CACHED를 엄격 요구(CreateBuffer의 additionalRequired)하고 coherent만 취해 invalidate 경로를 두지 않는다. 네 개 할당은 all-or-vector로 동작해 하나라도 실패하면 네 화면 모두 기존 vector+staging 경로를 유지한다 — CPU-fill/capture 경로에 느린 mapped 메모리를 강제하지 않는다.

DisplayCompositor::Compose의 direct 호출자는 같은 장치·일치하는 extent·정확한 mapped 목적지 주소·TRANSFER_DST usage·HOST_VISIBLE|HOST_COHERENT|HOST_CACHED 속성을 증명해야 하고, 아니면 명령 기록 전에 throw한다. direct 경로는 HOST→TRANSFER barrier 뒤 GPU 합성 행의 연속 범위마다 vkCmdCopyImageToBuffer를 기록하고(Keep·CaptureOverride 행은 건너뛰어 bit-exact 보존) TRANSFER→HOST barrier 뒤 기존 SubmitAndWait에서 동기 완료한다. staging buffer는 legacy 호출자의 첫 사용 시 lazy 할당으로 바뀌어 direct 모드에서는 만들어지지 않는다. CpuBGRA 계약·이중 버퍼·generation·제출 진단 의미·scale=1 경로·프론트엔드는 그대로다.

## 남은 범위·한계

- 유지된 GPU image에는 CPU-only capture override 픽셀이 없다 — GpuImage kind·직접 표시 전에 해결해야 한다.
- 네 개 표시 backing이 heap vector에서 host-visible Vulkan 할당으로 옮겨갔다. legacy staging은 direct 모드에서 할당되지 않지만 비례적 상주 메모리 감소는 주장하지 않는다.
- VkImage 직접 표시·장치 공유/external-memory·acquire/release·전면 GPU 2D/capture 이식은 후속이다.
- 실기·DSi·다른 OS/GPU·대화형 UI·장기 실행·validation layer·실제 OOM은 미검증이다.

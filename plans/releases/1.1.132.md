# 1.1.132 — 메인 작업트리 통합과 Windows 저장상태 교체 재시도

2026-09-16. 기준 코드 `66bb7222`(1.1.131 캐시 제어/업로드 묶음)에서 이어진 별도 견고성 수정이다.
기존 렌더링 캐시 정책은 [Caching.md](../Caching.md), 캐시·전송 구현은 [1.1.131](1.1.131.md)을 따른다.

## 발견과 재현

사용자 요청에 따라 `F:/melonDS`의 깨끗한 체크아웃을 master로 전환하고 메인 경로에서 전체 빌드했다.
기존 `codex/1.1.37-main-checkout` 브랜치의 `b3abc00e`는 보존했다. 다른 작업트리는 수정하지 않았다.
메인 최초 전체 검사에서는 967개 중 966개가 통과하고 `savestate-file-roundtrip` 하나가 실패했다.
QSaveFile의 파일 교체가 접근 거부로 실패했으며 이전 160바이트 저장상태는 그대로 남았다.
단독 반복에서도 6회 통과 뒤 실패가 재현됐다. 외부 프로세스나 드라이버 중 누가 거부했는지는 확인하지 않았다.
이 시험은 GPU를 사용하지 않는 파일 I/O 경로다. 이 현상을 캐시가 그래픽/저장 데이터를 손상시킨 것으로 해석하지 않는다.

별도 결정적 반례는 시험 소유 파일을 FILE_SHARE_DELETE 없이 열어 첫 commit을 거부하고,
그 첫 실패 뒤 핸들을 닫는다. 기존 제품은 Qt RenameError(10), commit 1회, 원본 보존 상태에서 실패했다.

## 구현

저장상태는 먼저 한 번만 직렬화한다. Windows에서 완전한 쓰기 뒤 commit의 RenameError만 최대 5회 시도한다.
각 시도는 새로운 QSaveFile/임시 파일을 사용하며 원본 직접 덮어쓰기 fallback은 명시적으로 끈다.
실패한 QSaveFile을 재개방하거나 동일 객체에 다시 commit하지 않는다. 재시도마다 guest 직렬화를 반복하지 않는다.
재시도 간 sleep은 40ms, 최대 추가 sleep은 160ms다. OS 파일 I/O 자체의 엄밀한 시간 상한은 아니다.
Qt 오류 분류를 사용하므로 영구 RenameError도 제한 횟수 뒤 실패하며, 정상 저장에는 sleep을 추가하지 않는다.
open 실패·짧은 쓰기·쓰기 오류·직렬화 오류는 재시도하지 않는다. 다른 OS의 저장 경로는 단일 시도를 유지한다.
저장 포맷, guest CPU/DMA 시점, 오디오 계산, 셰이더/캡처 수식은 변경하지 않았다.

## 관련 검사

실제 serializer/Qt 파일을 사용하는 저장상태 7개 검사가 모두 통과했다.
정상 왕복·영구 잠금·일시 잠금 해제의 3조건은 각 20회, 총 60회 연속 통과했다.
새 검사는 직렬화 1회, 제한된 재시도, 성공 후 전체 저장 데이터 왕복과 실패 시 이전 파일 보존을 확인한다.

## 최종 메인 경로 검증

설치된 CMake4.4.3 / GCC16.2.0 / C23·C++26 / Windows x64에서 `F:/melonDS/build/windows-dev`의 전체 기본 타깃을 빌드했다.
기존 Qt·OpenGL·Vulkan·JIT·선택적 SIMD 설정과 LTO OFF를 유지했다. Python 경로만 실제 설치본으로 재지정했다.
최종 전체 CTest는 **968/968 통과, 실패0·skip0, 122.15초**이며 `main-132-full-tests.xml`로 확인했다.
이 숫자는 메인 빌드 구성의 등록 테스트 전체다. 앞선 작업트리의 962개와 중복 합산하지 않는다.
앱 `--help`에서도 `melonDS 1.1.132`를 확인했다. 실제 실행 파일은 `F:/melonDS/build/windows-dev/melonDS.exe`다.
이 빌드는 설치된 MSYS2 SDK의 DLL 경로를 사용하며, 별도 독립 배포 패키지는 만들지 않았다.
기존 빌드/evidence를 재사용하고 다른 작업트리·드라이버 캐시·개인 runtime 파일을 삭제하지 않았다.

1.1.131의 캐시/clear 묶음은 이 전체 결과에 포함된다. 최종 두-image 업로드 비교는 해당 릴리스 기록의
213,699ns→126,800ns(40.66% 감소)이며 게임 전체 성능이 아니다. 이번 저장 재시도는 정상 저장 속도 최적화를 주장하지 않는다.
실제 game/DSi·다른 GPU/OS의 화면과 오디오 청취·물리 지연은 이번 실행 범위 밖이다.
전체 빌드에 남은 기존 GLBorrow fixture의 QSemaphore explicit-constructor 경고를 확인했고 warning-free를 선언하지 않는다.

원본 실패·결정적 잠금 반례·최종 로그는 기존 작업 증거 디렉터리의 `main-*`, `state-retry-*` 파일에 보존한다.
원 과제 ID와 과거 이력은 유지한다. 저장상태 파일 교체는 load/undo 복원의 전체 완료로 집계하지 않는다.
Actions는 실행하지 않으며 원격 반영은 게시 후 별도 Git 조회로 확인한다.

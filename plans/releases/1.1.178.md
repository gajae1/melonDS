# 1.1.178 — x64 JIT 인터프리터 대체 실행 뒤 PC 이탈 시 블록 종료

2026-09-24. 이전 버전은 1.1.177이다. 기본 배포는 SDL2이고 SDL3는 `ENABLE_SDL3=ON` 선택형 빌드다.

x64 JIT 블록 안에서 인터프리터 도우미로 실행한 명령이 PC를 순차 경로 밖으로 옮기면, 블록은 이제 그 자리에서 빠져나간다. 이전에는 사용자 모드에서 실행한 CP15 MCR/MRC가 정의되지 않은 명령 예외로 벡터에 들어간 뒤에도 같은 블록의 다음 명령을 계속 실행해 인터프리터와 결과가 달랐다. 수정은 도우미 호출 뒤 `R[15]`를 컴파일 시점의 순차 PC와 비교하고, 다르면 기존 파이프라인 재매핑 종료와 같은 방식(레지스터 캐시 정리, 누적 사이클 반영, `ARM_Ret`)으로 나간다. 일반 명령은 `R[15]`를 바꾸지 않으므로 예외가 없는 경로의 결과는 그대로다.

새 `core-*-cp15-user-und` 검사는 사용자 모드 MCR 뒤에 결과가 드러나는 명령을 두고, 같은 코드를 세 번 실행해 두 번째부터 컴파일된 블록을 거치게 한 뒤 레지스터·CPSR·PC·메모리를 확인한다. 1.1.177에서는 JIT·fastmem이 실패했고 수정 후에는 인터프리터·JIT·fastmem 모두 통과한다. 비공개 게임 두 개의 1200프레임 JIT 실행 결과는 HEAD와 같았고, Black 12라운드 교대 측정의 A/B 중앙값 1.0022는 A/A 1.0085 범위 안이었다. 같은 형태가 `ARMJIT_A64`에도 있지만 이번 수정은 x64 JIT만 다룬다.

같은 라운드에서 CP15 c7 무동작 MCR의 JIT 컴파일은 결과가 같았지만 Black 24쌍 중앙값이 0.64% 느려 채택하지 않았다. 최소 위상 오디오 Read의 희소 꼬리 압축 지연은 해당 커널이 10.7~11.4% 빨라졌지만 조밀한 입력이 3.4~4.8% 느려졌고 전체 이득이 잡음 기준을 넘지 못해 채택하지 않았다. 이 경로는 세 번의 정확 재구성 시도가 모두 기각됐다.

비공개 게임 두 개의 헤드리스 Software 1200프레임 ABBA 실행에서 1.1.177과 1.1.178의 최종 화면·누적 PCM·프레임버퍼 digest가 같았다.

SDL2 전체 CTest는 새 검사 3개를 포함해 **1029/1029**, SDL3 오디오·입력 집중 CTest는 **48/48**이다. 두 배포·패키징은 exit 0이고 두 매니페스트의 소스 ID는 `552d9f6568c92374bd79b3f997976b67e1958c8c1a8a7c7d969e695fc8186449`로 같다. 각 런타임 ZIP은 325개 파일, 검사한 비공개 파일 0개이며 기본 ZIP에는 SDL2 DLL만, 선택형 ZIP에는 SDL3 DLL만 있다. 다른 작업자의 수정된 `src/teakra/src/test_generator.cpp`는 포함되지 않았다.

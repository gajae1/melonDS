# 1.1.22 — 표시 context와 작업 스레드의 수명

기준 1.1.21, 검증일 2026-09-10. GR-11/12의 실제 증분이다. 책임 버전 1.1.22의 전체 과제 완료를 뜻하지 않는다.

## 5페이즈

1. **재현:** 해제 응답 뒤 paused 표시, root context 해제 전 코어 renderer 소유권, 새 context 생성 중 기존 worker 접근을 대조한다.
2. **수정:** 해제된 panel의 draw를 막고 코어 자원·캡처를 기존 context에서 정리한다. 창 생성·교체·등록 해제를 worker 접근 중단 범위에 넣는다.
3. **통합:** 중첩 GUI 작업은 같은 borrow를 공유하고 초기화·종료 메시지 대기 전에 반환한다. worker 간 동기식 broadcast와의 교착을 방지한다.
4. **검증:** 생산 메서드·실제 Qt 동기화와 native GL을 각각 검사한다. 실제 WGL 생성·파괴·재초기화를 대조하고 전체 Windows 회귀를 실행한다.
5. **배포:** 실행 파일·소스·공개 기록을 반영한다. 표시 shader/current/swap 오류 전달과 실제 surface 상실은 계속 진행한다.

## 확인한 동작

해제 응답 뒤에도 일시정지 표시 루프는 기존 panel을 방문할 수 있다. 기존 `drawScreen`은 context 포인터만 확인하여 다시 MakeCurrent·SwapBuffers를 호출했다. 이제 초기화 완료 상태도 확인한다. 실제 화면용·OSD shader를 사용하는 native GL 검사에서 해제 후 current/swap 호출은 각각 1회에서 0회가 됐고 정상 초기화·재초기화 대조는 통과했다.

root 표시 context를 해제할 때 코어 GL renderer가 남아 있던 경로도 수정했다. worker가 기존 root context를 current로 만든 상태에서 software renderer로 교체하므로 pending capture를 CPU 메모리로 가져오고 GL 객체를 먼저 해제한다. OpenGL·Compute 두 경우 모두 실제 source-B 캡처 픽셀과 활성/마지막 renderer 상태를 확인했다. 이것이 예기치 않은 MakeCurrent 실패에서도 성공한다는 뜻은 아니다. [Microsoft current 계약](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-wglmakecurrent), [다른 thread에서 사용 중인 context의 삭제 제한](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-wgldeletecontext).

GUI의 `ScopedGLWorkers`는 실행 중인 worker가 기존 borrow 계약으로 GL을 놓고 대기한 뒤 창 생성·교체·등록 해제를 진행한다. root context 생성의 GL/WGL loader 전체가 이 범위에 포함된다. 중첩 panel 생성은 이미 확보한 대여를 다시 요청하지 않는다. 아직 전역 인스턴스 목록에 등록되지 않은 생성 중 worker도 포함하며, 시작 전 worker에는 응답을 기다리지 않는다. 최외곽 범위가 끝난 뒤 초기화·종료 메시지를 처리한다. 일반 프레임마다 새 global lock을 획득하는 구조는 아니다.

작업 스레드의 hotkey broadcast는 GUI에 복사해 큐로 전달한다. GUI가 A의 borrow를 확보하고 B를 기다리는 동안 B가 A의 명령 완료를 동기 대기하면 교착될 수 있기 때문이다. GUI에서 시작한 broadcast의 기존 동기 동작은 유지한다. [Qt thread 간 queued 호출](https://doc.qt.io/qt-6/threads-qobject.html).

## 검증 범위

- `GLLoaderBoundary`: 현재 창·panel·context 생성 메서드, borrow handler와 GUI guard를 추출해 실제 Qt 두 worker로 검사한다. root 생성·교체·실패에서 loader 접근 중첩, shared/미등록 인스턴스에서 등록 전 접근을 재현했다. 수정 후 7개 case에서 중첩·등록 전 접근 0, 정상 재개·초기화·실패 fallback과 queued broadcast를 확인했다. native loader·widget·driver 호출은 대역이며 실제 함수 포인터를 손상시키지 않는다.
- `GLPresentation`: 생산 표시 init/deinit/draw와 코어 deinit handler를 실제 native GL에서 검사한다. layout·OSD 큐·QWidget은 격리한다. Windows 전용 추가 case는 생산 `Context::Create`/WGL backend로 GUI에서 context를 생성하고, worker의 init/draw/deinit 응답 뒤 GUI에서 파괴·재생성하고 worker가 다시 표시한다.
- Windows x64 Release 전체 frontend 빌드 성공. GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26과 기존 JIT/ISA 구성을 유지했다. 전체 CTest **428/428, skip 0**, 59.47초다.
- 버전 변경의 최종 재링크 뒤 코어 ROM smoke 실행 파일이 달라져, 두 DS 게임 × software/OpenGL/Compute 각각 3,600프레임을 현재 실행 파일로 다시 실행했다. 6개 최종 프레임 모두 같은 입력·renderer의 1.1.21 결과와 바이트가 일치한다. 동일 이미지의 이전 시각 확인은 재사용한다. 이를 새 전체 Qt 게임 실행이나 창 교체 중 게임 화면 수락으로 집계하지 않는다.

실행 파일은 `1.1.22-melonDS.exe`, 패키지는 `1.1.22-melonDS-windows-x64.zip`과 `1.1.22-melonDS-source.zip`이다. 필요한 실행 파일·DLL/plugin·라이선스만 포함하며 게임·설정·저장 자료를 넣지 않는다. 이번 수명 수정에서 FPS·전력·물리 지연 개선량은 측정하지 않았다.

## 남는 범위

표시 ScreenShader/OSDShader·MakeCurrent·SwapBuffers 실패의 상위 전달과 native fallback, 실제 창 이벤트 전체, OSD 재초기화 상태, paused 게임 이미지 유지, 물리 surface 상실·휴면 복귀·다중 GPU/DPI·다른 OS는 남는다. 모든 context의 GL 함수 주소·capability가 호환된다는 증거도 아니므로 서로 다른 장치의 context별 dispatch는 별도 판정한다.

다음 실제 1.1.23은 표시 초기화 실패·부분 해제·오류 통지와 재시도를 우선한다. GPU 정밀도/실기 oracle, Vulkan 단계별 구현, 고급 ISA의 결과·타이밍·실측 이득, 기존 오디오·장치 수락은 계속 유지한다.

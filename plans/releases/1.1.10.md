# 1.1.10 — 저장 파일 정체성과 주변장치 상태

상태: 구현·Windows 빌드·로컬 회귀 완료. 기준 소스 1.1.09. FS-13·NP-13·NP-17·NP-19의 좁은 변경을 묶는다. 새로운 성능 이득이나 주변장치 전체 호환성을 주장하지 않는다.

## 5페이즈

1. **근거와 반례:** 기존 공용 basename 경로의 충돌을 소스에서 확인하고 소유권 정책을 정했다. IR의 미지원 응답·중간 명령 복원, RTC 직렬 입력·분 IRQ·Reset 상태, 진동 AD1 외 비트의 실제 생산 코드 반례를 정상 입력과 대조했다.
2. **구현:** 저장 정체성 선택과 고정된 활성 경로를 추가했다. IR 위치를 상태에 기록하고 불확정 응답을 제거했다. RTC의 실제 clock edge·분 carry 창과 통신 초기값, 진동의 연결된 비트만 수정했다.
3. **통합:** Qt 로드·카트 삽입·Reset 메시지에 선택 결과를 전달했다. worker hotkey Reset은 선택 전에 UI thread로 넘긴다. 상태 형식은 14.1로 올리고 14.0 IR의 새 명령 경계 복원 정책을 정했다.
4. **검증:** 생성 ROM·임시 저장 파일·실제 코어/SaveManager와 Qt offscreen 선택, 생산 주변장치 코드를 실행했다. 최종 Windows 구성은 아래 결과로 기록한다.
5. **배포:** 같은 소스의 Windows EXE·의존성·런처·ZIP을 검증하고 포크 master에 반영한다. 개인 입력과 원본 검토 자료는 배포에 포함하지 않는다.

## 저장 경로 정책

DS/GBA 종류, canonical ROM 대상, 사용한 절대 경로와 archive member를 정체성으로 사용한다. 보이는 별칭 경로와 원래 basename을 함께 보존한다. ROM 위치나 별칭·member 이름을 바꾸면 다른 소스이며, 같은 경로에서 ROM 내용만 교체하는 경우를 판별하는 콘텐츠 지문 기능은 아니다.

새 경로 또는 같은 소유자에서는 원래 이름을 유지한다. 미분류 기존 파일에는 기존 파일 사용·별도 파일 사용·취소를 제공한다. 다른 소유자의 이름과 firmware 예약 이름에는 별도 파일 또는 취소만 제공한다. 별도 이름은 basename 일부와 정체성의 짧은 digest로 만들지만 재사용은 전체 digest로 확인한다. DS 저장·자동 상태 슬롯·치트는 같은 이름을 사용하고 GBA는 저장 폴더만 확인한다. 기존 다중 인스턴스 suffix 정책은 유지한다.

소유권 기록은 Qt `GenericDataLocation` 아래 `melonDS/asset-ownership`의 사용자 공용 보관 위치에 둔다. ROM·치트 폴더에 기록용 파일을 만들지 않는다. 정규화 폴더마다 잠그고 [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html)로 원자적으로 기록한다. 잠금은 같은 기록을 사용하는 프로세스가 참여해야 한다는 [QLockFile의 계약](https://doc.qt.io/qt-6/qlockfile.html)을 따른다. 파일명과 폴더 기록 namespace는 대소문자를 보수적으로 접고 소스 정체성은 철자를 보존한다. 대소문자만 다른 별개의 폴더도 한 기록에 모아 중복 잠금과 누락 검사를 피한다.

기록 손상·잠금 실패·보관 위치 생성 실패는 로드를 진행할 근거가 아니다. 취소나 오류에서는 선택된 활성 경로를 교체하지 않는다. 설정 편집만으로 진행 중인 게임의 저장·치트·상태 경로가 변하지 않으며, 로드/Reset이 적용한다. 경로가 그대로인 Reset은 원본 ROM이 더 이상 디스크에 없어도 동작한다.

기존 파일은 추정 복사/이관하지 않는다. 기존 파일 사용 선택은 신규 로드에서만 제공한다. 활성 저장 데이터를 다른 경로로 옮기는 reset에서는 소유권 불명 파일을 덮어쓰지 않고 별도 이름 또는 취소만 제공한다. 실패한 ROM 부팅 뒤 소유권 metadata가 남을 수 있지만 게임 파일 내용은 변경하지 않으며 같은 소스로 재시도할 수 있다.

기록을 잃었거나 다른 사용자·컴퓨터로 옮긴 경우 기존 파일은 다시 미분류 상태로 확인한다. 이전 버전·다른 사용자·외부 편집기는 이 잠금에 참여하지 않는다. 같은 ROM의 여러 프로세스 저장 충돌, 네트워크 공유의 모든 별칭·캐시 규칙, 완전한 이동/복구 도구는 이번 증분의 보장이 아니다.

## 주변장치 변경

| ID | 변경 | 근거와 한계 |
|---|---|---|
| NP-13 | IRPos Reset·포화 증가·14.1 직렬화, 자체 section 길이 확인, 미지원 명령 응답 FF | FF는 기존 retail SPI fallback에 맞춘 명시적 호환성 값이다. 실제 IR 통신의 측정값이 아니다. 14.0은 저장하지 않은 phase를 재구성할 수 없어 IR/SRAM SPI를 새 명령 경계로 복원하며 SRAM bytes는 보존한다. |
| NP-19 | 입력은 상승 edge·출력은 하강 edge, 반복 low 쓰기의 가짜 bit 진행 제거, 분 carry를 256/32768초 유지, IO·OutputBit 생성/Reset 초기화 | [ABLIC S-35190A 자료](https://www.ablic.com/en/doc/datasheet/real_time_clock/S35190A_E.pdf)의 직렬·7.8125ms 신호 계약과 [libnds RTC transaction](https://github.com/devkitPro/libnds/blob/v1.8.0/source/arm7/clock.c)을 대조했다. IO=0은 deselected 호환성 기본값이며 DS 호스트 MMIO 냉간값의 실측 결과가 아니다. 배터리 날짜·State·IRQ는 보존한다. |
| NP-17 | 진동 제어값과 이전 상태에서 AD1만 비교 | [libnds rumble](https://github.com/devkitPro/libnds/blob/84e6082ce27c87ed218fb369a9944644aa2243a6/source/arm9/rumble.c) 및 [진동 팩 계약](https://problemkaputt.de/gbatek.htm#dscartrumblepak)을 대조했다. AD1 전환의 기존 Stop→Start 16ms callback은 유지한다. 다른 비트만 바뀌면 재진동하지 않는다. |

## 실행 증거

Windows x64, GCC 16.2.0·CMake 4.4.3·Qt 6.11.2·SDL 2.32.10, Release·C23/C++26·JIT·OpenGL/Compute·AVX-512 빌드·LTO off 구성이다. AVX-512 빌드는 모든 실행에서 해당 명령을 사용했다는 뜻이 아니다.

- `AssetIdentityTest` 15개: 실제 임시 registry·파일·잠금과 DS/GBA/archive·대소문자·Windows junction·기존 파일 선택·경로 변경·손상/불능 보관 위치. 기록은 asset 폴더 밖에 생성됨을 확인한다.
- `AssetIdentityUI` 6개: 생산 Qt 선택/메시지 생성과 실제 offscreen 대화상자, 취소·소유자·Reset·worker→UI 전달. 메시지 수신은 제어된 대체 경계다.
- `CartReplacement` 추가 4개: 실제 코어·카트·SaveManager에 선택한 이름/경로를 적용하며 기존 pending bytes·SRAM·실패한 Reset의 활성 경로를 확인한다. 처음의 두 기대값 오류는 미기록 pending bytes와 빈 디스크 파일을 혼동한 fixture 문제였으며 제품 결함 재현으로 세지 않는다.
- `IRCartState` 11개: 실제 카트·상태 parser의 ID/SRAM 대조, 중간 읽기·쓰기·명령 복원, legacy·잘린 section·위치 포화. 초기 반례 2개와 section 경계 1개가 수정 전 실패했다.
- `RTCCalendar` 9개: 전체 생산 RTC와 현재 NDS scheduler 정의에 생성 clock·IRQ sink를 연결한다. 달력/BCD/시간 모드·직렬·alarm/periodic IRQ·분 재활성화·Reset 보존을 검사했다. 최초 3개 case가 실패했고 Reset 후속은 6개 assertion 실패에서 통과했다.
- `GBARumble` 3개: 실제 카트 코드의 정상 AD1 전환·다른 비트·과거 상태 복원을 기록 callback으로 확인한다. 정상 대조는 통과하고 수정 전 2개 case가 실패했다.

최종 Windows frontend 빌드와 전체 CTest **321/321, skip 0, 31.98초**를 확인했다. 기존 interpreter·warmed JIT·fastmem·실제 OpenGL/Compute 출력 회귀를 포함한다. EXE의 FileVersion/ProductVersion은 모두 1.1.10이다. 배포 EXE/DLL 129개에서 import 누락 0, 개발 도구를 제외한 PATH에서 `--help` 종료 0을 확인했다. 공개 계획 19개 상대 링크·개인 경로 검사도 통과했다. 실행 패키지는 이 EXE와 필요한 DLL/plugin·라이선스를 선별하고 공개 소스 ZIP은 완료 커밋에서 생성한다.

## 남은 범위

FS-13의 실제 사용자 선택·게임 저장 재로드·ACL로 보호된 폴더 수락, macOS/다른 파일시스템 동작은 별도다. junction 회귀를 macOS 검증으로 계산하지 않는다. IR의 실제 무선 통신, DS/DSi 날짜 의존 게임과 host 동기화/DST·14.0 중간 RTC transaction 호환성, 실제 pad의 진동·pause/eject·다른 GBA 센서/RAM도 남는다. AUXSPI의 CS 해제와 512B EEPROM page wrap/dirty 통지는 다음 독립 반례로 진행한다. 미측정 BT 프로토콜은 문서만으로 구현 완료 처리하지 않는다.

# 1.1.134 — 해상도 변경의 표시 버퍼 수명과 실패 복구 잠금

2026-09-16. 기준 커밋은 1.1.133 `7e771592`이며 메인 `F:/melonDS`에서 수정한다.
GR-11/15/16의 표시 수명 경계에 한정한다. 전체 로드맵이나 실기 정확성 완료 선언은 아니다.

## 재현한 문제

1.1.133에 별도 보존했던 NativeFrameLifetime을 현재 소스로 다시 빌드·실행했다.
수정 전 `paint consumed retired framebuffer at 2x`로 실패했다.
worker의 drawScreen이 주소를 게시한 뒤 배율/renderer가 교체되고, GUI paint가 그 이전 주소를 복사하는 경로다.
이 시험은 이전 메모리를 의도적으로 남겨 잘못된 주소 선택을 판정한다. 사용자 종료의 crash dump를 분석한 결과는 아니다.

## 수정

ScreenPanelNative::paintEvent는 renderLock와 bufferLock을 잡은 상태에서 현재 renderer의 주소와 크기를 다시 얻는다.
이전 게시 주소를 그대로 역참조하지 않는다. console 부재, RAM view 부재, null 주소, 비양수 크기에서는 기존 QImage를 보존한다.
worker가 별도로 보존한 일시정지 이미지를 게시한 경우에는 새 renderer 결과로 덮어쓰지 않는다.
CPU 복사 횟수, 표시 해상도, 필터와 QPainter 변환은 바꾸지 않았다.

추가로 runtime 3D 실패 및 Compute shader 실패의 Software fallback이 renderLock 없이 renderer를 교체하던 곳을 보완했다.
두 경로가 동일한 잠금으로 교체를 보호하며, 기존의 잠금이 있는 설정 적용/GL 종료 경로에 중복 잠금을 넣지는 않았다.
실제 GL 컴파일/링크 실패 주입을 사용하는 기존 검사를 확장해, 수정 전 잠금 누락과 수정 후 잠금 유지/반납을 확인했다.
런타임 3D 실패 분기는 같은 보호를 적용했으나 그 분기를 강제 실패시킨 별도 Qt end-to-end 검사는 이번 범위 밖이다.

## 동작과 범위

셰이더 수식, CPU/DMA용 캡처, SPU PCM/보간, 저장상태 형식과 pipeline cache 정책은 변경하지 않았다.
앱의 새 디스크 캐시나 전역 드라이버 캐시 정리 기능을 추가하지 않았다. 기존 RAM 캐시 정책은 Caching.md를 따른다.
이 수정은 안정성 개선이며 FPS 개선율을 측정하거나 주장하지 않는다.

## 실제 검증 결과

Windows x64, CMake 4.4.3 / GCC 16.2.0 / C23·C++26 / Release / LTO OFF에서 메인 전체 기본 타깃을 빌드했다.
최종 앱 FileVersion/ProductVersion은 모두 1.1.134다.
전체 등록 CTest **970/970 통과, 실패0·skip0·disabled0, 165.85초**다. JUnit으로 집계도 확인했다.
새 NativeFrameLifetime 1개를 정식 등록했고 기존 ComputeFailure를 확장했다. 과거 별도 반례가 이제 기본 검사에 포함된다.

Native 검사는 2→3→16→1→8→1배, 양 화면의 모든 subpixel, 사라진 view·null·0크기·console 부재,
잠금 중 조회 및 보존된 paused image를 검사한다. 독립 반복10회도 통과했다.
이는 실제 paint 함수를 추출해 Qt QImage에 그리되 renderer/worker는 대역으로 교체한 시험이다.
실제 게임의 renderer 교체와 Qt 이벤트를 동시에 무작위 실행하는 장기 end-to-end 검사는 아니다.
기존 실제 GL shader compile/link 오류 검사에서, 수정 전 잠금 누락 실패→수정 후 소유/반납 통과를 확인했다.
Vulkan 1x/2x/3x, high scales, 고해상도 캡처 표시와 GL 확대 업로드를 포함한 관련8개도 먼저 통과했다.
8개·10회 반복은 전체970개와 중복되며 독립 검사 총수로 더하지 않는다.

최종 소스 빌드 후 제품 코드는 바꾸지 않았다. 이후 변경은 릴리스·상태·검증 문서뿐이다.
사용자가 보고한 crash의 직접 원인 동일성, 실기 그래픽 기대값, 다른 GPU/OS, 물리 장치 상실은 확정하지 않았다.
Vulkan 확대의 bitmap BG/OBJ·3D texture 재사용 경로와 GPU 직접 표시는 별도 후속이다.

# 1.1.206 — Vulkan 표시 전송과 Sinc 스테레오 계수 공유

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

- Vulkan 표시 입력: 합성할 줄은 연속 범위를 묶어 복사하고, Keep/CaptureOverride 줄은 셰이더가 조기 반환에 쓰는 mode 4바이트만 갱신한다. 모든 줄을 보존하면 context 복사·descriptor 갱신·compute bind와 세 장벽을 생략한다. CPU 보존 줄의 GPU 업로드·최종 이미지 의존성·제출·fence·deferred 수명은 유지한다.
- Vulkan CPU 읽기: 일반 배열로 반환하는 staging 경로도 직접 mapped 경로처럼 합성한 줄만 전송한다. 연속 구간은 한 region으로 묶으며 CPU 복사는 기존처럼 필요한 줄만 수행한다. 보존 줄·배율이 맞지 않는 줄 경계·화면 교대·지연 완료의 출력이 기존 CPU 합성과 같다.
- Sinc 출력: `AudioSincOutput::Push`의 네 `DotFloat` 호출을 두 `DotFloatStereo` 호출로 바꿨다. AVX2/FMA·SSE2·NEON은 두 채널의 계수 읽기와 실행 경로 선택을 공유한다. 각 채널의 누적·lane reduction·위상 보간·반올림 순서는 유지한다. 스칼라는 기존 개별 dot 계산을 유지하며 경로 선택만 줄인다. MinimumPhase·guest 캡처·필터 탭 수·샘플레이트·음색 설정은 변경하지 않았다.

## 작업량과 한계

3배율에서 192줄 중 48줄만 합성하는 진단 입력:

| 작업 | 1.1.205 | 1.1.206 |
| --- | ---: | ---: |
| 표시 context·그룹 맵 복사 | 990,144 B | 248,256 B |
| staging GPU→CPU 전송 | 1,769,472 B | 442,368 B |
| Sinc 스테레오 SIMD 계수 행 순회 | 출력당 4회 | 출력당 2회 |

모두 보존하는 화면의 context 복사와 staging 전송은 0이다. 모두 합성하면 복사량은 줄지 않는다. context의 줄 스캔·작은 mode 쓰기와 staging region 작성은 추가 CPU 작업이며 할당량은 변하지 않는다. Sinc의 MAC·탭 수는 그대로이고 계수 벡터 읽기만 공유한다. 실제 캐시·메모리 트래픽과 구형 기기 처리 시간, 게임 FPS 상승률은 측정하지 않았다. 다른 프로그램을 사용 중인 PC의 시간 변동을 채택 근거로 쓰지 않는다.

## 검증

- 실제 Vulkan 표시 합성과 기존 CPU 참조의 픽셀 일치. 직접 mapped·staging 양쪽의 전송 region/바이트, Keep·CaptureOverride 보존, deferred 완료 및 기존 1/3/5/16배율 sparse/full 전환 검사 통과.
- 진단 ON/OFF의 출력·GPU 제출·대기·전송 동일성, frame 진단 검사 통과. 표시 context 복사량도 위 조건으로 확인했다.
- Sinc 이전 소스와 새 소스의 x64 AVX2/FMA, FMA 비활성 SSE2, 각 강제 스칼라 경로: 네 구성에서 각각 483,596 PCM 샘플 해시 일치. 12개 입력/출력 rate 조합·난수/극값/임펄스·rate 변경·reset·ring wrap·chunk 경계를 포함한다. ARM64 PCM의 구버전 직접 비교는 수행하지 않았다.
- 기존 `audio-sinc-history`와 `audio-sinc-history-scalar` 통과. 로컬 집중 검사 총 5개, full suite는 CI에서만 수행한다.
- Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

# 1.1.29 — LAN 재접속·입력 장치 선택·DSi 타이틀 교체

기준은 1.1.28(`04742e167eeba2b26b6099d9982a23c5931fba63`), 검증일은 2026-09-11이다. NP-02/FS-17, FS-12, FS-16을 독립 작성 후 통합했다. 아래 책임 버전 전체와 공개 계획의 완료를 뜻하지 않는다.

## 변경과 근거

**LAN:** 빈 제어 패킷을 해제하지 않는 실패를 기존 구현에서 재현했다. 제어 패킷의 모든 이탈 경로에 단일 소유권을 적용하고, 길이·버전·배정 ID와 호스트의 참가자 목록을 검사한다. 비동기 이름 조회와 ENet 진행 상태를 사용해 연결 중에도 취소할 수 있으며, 연결 성공은 참가자 목록을 받은 뒤 알린다. 종료·시간 초과·호스트 소실 뒤에는 참가자와 대기 프레임을 정리하고 재시도 또는 Local 모드로 돌아간다. 수신 처리량을 제한해 연속 제어 패킷도 UI에 실행 기회를 돌려준다. UI와 에뮬레이션 작업자는 세션 잠금과 소유 핸들을 공유하며, 인터페이스를 교체해도 진행 중인 호출의 객체를 파괴하지 않는다. 모든 창의 메뉴도 함께 갱신한다. [Qt 비동기 이름 조회](https://doc.qt.io/qt-6/qhostinfo.html#lookupHost-2)

**입력:** 열거 번호가 바뀌면 다른 패드를 열던 경로를 재현했다. 연결 중에는 SDL instance identity를, 재연결에는 GUID와 사용 가능한 고유 serial을 사용한다. 과거 숫자 설정은 그 장치가 있을 때 한 번 이관하고, 누락·음수·잘못된 형식·범위 초과를 장치 0으로 바꾸지 않는다. 새 논리 인스턴스는 매핑만 물려받고 패드는 명시적으로 선택한다. 설정창의 미리보기는 별도 핸들을 사용하므로 Cancel이 실제 배정을 바꾸지 않는다. **고유 serial이 없거나 중복된 패드는 재연결·앱 재시작 후 재선택이 필요하다.** 현재 연결만 식별할 수 있다는 이유를 설정창에 표시한다. [SDL serial](https://wiki.libsdl.org/SDL2/SDL_JoystickGetSerial), [SDL 경로의 구현 의존성](https://wiki.libsdl.org/SDL2/SDL_JoystickPath)

**DSi 타이틀:** 기존 title을 먼저 삭제하던 UI를 제거했다. 입력 header·TMD 크기/해시·저장 크기를 확인하고 NAND 내부 임시 경로에서 실행 파일·메타데이터·필요한 저장 파일을 준비한다. 기존 저장 파일과 추가 data 파일은 덮어쓰지 않는다. 콘텐츠·ticket 교체의 일반 오류는 이전 상태로 복구하고, rename 결과나 rollback이 불확실하면 남은 백업을 유지하며 복구 필요 상태를 표시한다. 설치 성공 뒤 정리 실패도 성공과 경고를 함께 알린다. 실제 NAND sector seek/read/write, 짧은 전송, close/flush 실패가 성공으로 바뀌지 않게 한다. TMD와 다른 패치 실행 파일은 일치하는 메타데이터 없이는 가져오지 않는다. 서명의 진위를 인증하는 기능은 아니다.

## 5페이즈와 검증

1. **재현:** 정상 LAN·입력·새 설치와 빈 패킷·장치 이탈·동일 title 교체 실패를 대조했다.
2. **수정:** LAN은 통합 작성자가, 입력과 title은 서로 다른 작업 공간의 작성자가 담당했다.
3. **통합:** 공유 인터페이스·실제 Qt 연결·설정·NAND 오류 결과와 CMake를 순차 연결했다.
4. **검증:** Windows x64 Release 전체 빌드 성공. 최종 소스의 CTest는 **548/548 통과, 실패 0, 건너뜀 0**, 병렬도 2에서 **68.35초**였다. 최종 애플리케이션 객체를 연결한 기존 Qt 생성 guest·오류 주입 검증도 exit 0이었다.
5. **배포:** 검증한 실행 파일·DLL/plugin·라이선스와 커밋된 소스를 버전별 패키지로 선별한다. 패키지 manifest는 source commit과 실행 파일·ZIP 해시를 기록한다.

- `LANPacket`: 실제 LAN 구현과 ENet packet, 제어된 event 전송으로 빈/잘린 입력·버전·시간 초과·취소·재시도·수신 양도 및 기존 MP frame 검증을 수행한다.
- `LANLoopback`: 실제 ENet의 IPv4 loopback에서 handshake·MP frame·이탈/재참가·호스트 소실·동시 snapshot과 인터페이스 수명을 확인한다. discovery는 처리 전에 닫아 broadcast를 보내지 않는다.
- `LANUI`: 실제 dialog·Qt event loop/DNS·ENet에서 응답성, 취소, 부모 파괴, 시간 초과, 재시도, 호스트 소실을 확인한다. 부모와 설정만 대역이며 실제 에뮬레이션 작업자는 별도 Qt 통합 근거다.
- 입력: 실제 SDL 가상 장치와 Qt 매핑·임시 설정의 새 프로세스 재로드를 사용한다. serial과 센서 값은 해당 API 경계의 대역이며 실물 장치 증거가 아니다.
- Title: 생성한 폐기 가능 NAND에서 실제 암호·FatFs·이미지 I/O를 사용한다. 기존 저장의 바이트/속성 보존, 공간 부족·짧은 읽기/쓰기·교체/rollback/정리/flush 실패와 재마운트 읽기를 확인한다. UI 완료 처리는 실제 Qt와 제어된 NAND 결과를 대조한다.

실행 파일 SHA-256: `7fa158a656e63779f439b00153703192fbd3f47054f1cc7c5d8bfe462b154059`.
빌드는 GCC 16.2·Qt 6.11.2·SDL 2.32.10, C23/C++26, JIT 및 실행 시 SIMD 선택, LTO off 구성이다. 실행 명령은 `cmake --build build/windows-dev -j4`, `ctest --test-dir build/windows-dev -j2 --output-on-failure`다. 전체 Qt 검증은 생성 guest·SDL dummy audio와 오류 주입 진입점이므로 실제 게임 또는 물리 고장의 재현으로 집계하지 않는다.

## 호환성과 남은 조건

저장 상태 형식은 **14.2를 유지**한다. 14.2를 읽지 못하는 이전 실행 파일로 이 상태를 되돌려 읽을 수 없으며 일반 게임 저장 형식은 변경하지 않았다. LAN wire protocol은 v1을 유지한다. 소스 소비자는 비동기 `StartClient`의 시작 성공과 `GetClientState`의 연결 완료를 구분하고, 교체와 겹치는 호출은 `MPInterface::Acquire`로 수명을 유지해야 한다.

두 PC의 실제 게임·Windows/Linux 간 LAN·방화벽·휴면·장기 지연·여러 참가자의 peer mesh/주소 재사용은 남는다. Netplay의 비활성 메뉴를 승격하지 않았다. 패드의 실물 hotplug·USB/Bluetooth serial·진동·센서·여러 프로세스도 별도 수락이다.

타이틀 교체에는 새 콘텐츠를 준비할 NAND 공간과 추가 읽기/해시 비용이 든다. 프로세스 종료·전원 상실·영구적인 FAT 손상까지 원자적으로 복구하지 않으며, 불확실한 rename이나 정리 실패는 일부 백업만 남길 수 있다. 실제 NAND 사본에서 DSiWare 부팅·저장 재로드와 수동 복구 절차는 후속이다. 현재 입력·LAN 소유권 처리의 실제 게임 성능 이득은 측정하지 않았다.

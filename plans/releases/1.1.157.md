# 1.1.157 — software 2D brightness scanline fast path

2026-09-22. 기준 1.1.156 HEAD f743797d. 빌드는 93f6 worktree의
build/windows-dev다.

## 구현

- GR-09 선행 계측은 DrawScanline_BGOBJ가 가장 크고, 그 안의
  ColorComposite brightness-up/down 경로가 Solatorobo에서 실제로 지배적인
  것을 확인했다. ScanlineFinalPass는 두 실게임에서 거의 나타나지 않아
  후보에서 제외했다.
- ColorComposite<2/3>에 scanline fast path를 추가했다. target2 blend가
  없고(BlendCnt & 0x3F00 == 0) 모든 target1 레이어가 선택된
  (BlendCnt & 0x3F == 0x3F) 줄에서는 top flag와 effect window가 허용하는
  픽셀을 generic CompositePixel 없이 바로 brightness 계산한다.
- zero top flag나 닫힌 effect window가 하나라도 있으면 같은 출력 버퍼를
  generic 경로가 다시 쓰도록 fallback한다. scaled 3D가 활성이면 기존
  Resolve3DPixel을 먼저 적용해 placeholder/아래 레이어 의미를 유지한다.
- gpu-software-2d-composite에 all-target1/no-target2 조합과 zero flag를
  추가해 fast path와 fallback 경계를 직접 대조한다.

## 계측·검증

- Scratch rdtsc 계측(커밋하지 않음): Solatorobo software 1x 1200프레임에서
  RunFrame 11.084G cycles, ColorComposite 878M cycles. Black software 1x는
  ColorComposite 38M cycles, ScanlineFinalPass 47K cycles였다.
- 계측 제거 후 ROMSmoke A/B, 1200프레임:
  - Solatorobo software 1x, 5쌍 중앙값 2.510s → 2.393s
    (unthrottled fps 478.1 → 501.4), framebuffer digest 동일.
  - Solatorobo Vulkan 16x, 3쌍 중앙값 8.272s → 8.279s로 노이즈 범위,
    framebuffer digest 동일.
  - Black software 1x, 3쌍 중앙값 1.633s → 1.600s, framebuffer digest 동일.
- gpu-software-2d-composite와 software capture/Vulkan display composition
  관련 ctest 9개 통과.

## 남은 범위·한계

- 실게임 이득은 brightness-heavy Solatorobo software 경로의 제한 측정이다.
  전체 게임·다른 CPU/OS·ARM NEON의 속도 향상으로 확대하지 않는다.
- DrawScanline_BGOBJ의 BG/OBJ 렌더링 자체는 여전히 더 큰 잔여 비용이다.
- u64 3-lane brightness SWAR probe는 독립 벤치에서 기존 2-multiply 형태보다
  느려 채택하지 않았다.

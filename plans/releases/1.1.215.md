# 1.1.215 — 렌더러 준비 후 입력 샘플링

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

이전 실행 루프는 입력을 읽은 뒤 GL 컨텍스트 준비와 대기 중인 렌더러 설정을 적용했다. 이 호스트 작업이 지연되면 첫 재개 프레임이 작업 이전 입력을 사용했다. 1.1.214의 시간 기준 재설정은 프레임 몰림을 수정했지만 입력을 다시 읽지는 않았다.

GL 준비를 한 번 실행해 결과를 보관하고, 실행·프레임 스텝 상태의 렌더러 설정을 적용한 다음 입력과 단축키 edge를 한 번 읽는다. GL 준비가 실패해도 단축키를 처리한 뒤 기존 실패 분기로 들어간다. 입력을 읽은 뒤 도착한 새 영상 설정은 다음 반복에서 처리하며, 뒤쪽의 중복 설정 적용 지점을 제거했다. 기존 프레임 시간 재설정과 일시정지 동작은 유지한다.

## 검증과 한계

- 프런트엔드 빌드와 기존 키보드 매핑·GDB 중단·오디오 설정 메시지·재개 프레임 시간·GL 실패 경계 검사 5개를 통과했다. 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- 현재/이전 소스의 호스트 작업·입력 구간을 추출한 격리 검사에서 GL 준비/렌더러 적용 중 입력 변경을 주입했다. 실행·프레임 스텝에서 새 입력을 사용하고, 일시정지·GL 실패에서 단축키를 유지하며, 샘플 이후 영상 변경을 다음 반복으로 넘겼다. 이전 순서는 실행·프레임 스텝·늦은 설정 변경 조건에서 실패하고 현재 순서는 5조건을 통과했다.
- 이 격리 검사는 해당 생산 코드 구간과 fake 입력/호스트 작업을 연결한 것이다. 전체 실행 루프·실제 게임패드·물리 입력 지연·게임 FPS 검증이 아니다. 게임 플레이나 장기 청취는 하지 않았다.
- AudioSync OFF·출력 큐·보간 필터·장치 설정을 바꾸지 않는다. 장기 틱 노이즈와 장치 클록 차이는 해결됐다고 주장하지 않는다. 9800X3D 내장그래픽은 GPU 제약 환경이며 저성능 CPU의 대체 검증으로 취급하지 않는다.

# 1.1.176 — 2D·텍스처·캡처·프레임 제시·저장 경로 최적화 11건

2026-09-24. 이전 버전은 1.1.175이다. 기본 배포는 SDL2이고 SDL3는 `ENABLE_SDL3=ON` 선택형 빌드다. 아래 수치는 모두 함수 단위 합성 부하이며 게임 FPS 향상은 주장하지 않는다.

Software 2D는 세 곳이 빨라졌다. 확장 비트맵 BG는 어파인 행렬이 항등일 때 Y 검사와 행 주소를 루프 밖으로 올리고, 비모자이크 행은 화면 안 구간을 미리 계산해 픽셀별 경계 검사를 없앤다. 122,592개 사례(항등 47,668개, 경계 격자 포함)가 바이트 단위로 같았고 항등 경로가 1.32~1.81배 빨라졌으며 비항등 경로는 A/A 잡음 안이었다. 밝기 효과 합성은 target2가 없고 target1이 모두 선택된 경우 창·플래그 조건을 마스크로 처리해, 한 픽셀 때문에 행 전체를 다시 합성하던 경로를 없앴다. 131,072개 사례가 같았고 밝기 합성이 48~51%, 스프라이트 포함 행이 18~25% 짧아졌다.

텍스처 캐시는 팔레트 색 변환을 픽셀마다 하지 않고 디코드마다 한 번 한다(작은 8bpp 텍스처는 기존 경로 유지). 형식 1~7, 8×8~256×256의 542개 사례가 같았고 256×256 인덱스·AXIY 디코드가 69~83% 빨라졌다. 또 color-zero 투명 비트를 해석하지 않는 형식 1·6·7은 그 비트로 캐시 항목을 나누지 않는다. 디코드 함수가 이 비트를 받지 않음을 확인했고, 비트만 다른 요청이 한 항목을 공유해 업로드가 절반이 됐다.

OpenGL 캡처 동기화는 실제로 읽는 행만 축소 래스터한다(나머지 호출자는 전체 축소 유지). 실제 GL 판독 25,536건이 같았고 256폭 한 줄 동기화가 1×/2×/8×에서 7.3%/13.3%/54.7% 빨라졌다. Vulkan compute는 HOST_CACHED 네이티브 판독 버퍼를 복사하지 않고 그대로 넘긴다. 이미 전체 판독 경로가 쓰던 방식이며 16쌍 측정에서 약 10.4µs가 8.4µs가 됐다.

Qt 화면은 같은 NDS 인스턴스·같은 페이로드·같은 표시 세대의 프레임을 다시 그릴 때 CPU 픽셀 복사와 GL 업로드를 건너뛴다. 세대·크기·배율·회전·레이아웃·필터·렌더러 교체·버퍼 재할당·보존 프레임에서 모두 무효화한다. 반복 페인트당 1× 5.3µs, 4× 91µs, 16× 4.2ms가 줄었다. NDS 교체는 새 객체를 만든 뒤 옛 객체를 지우므로 같은 주소 재사용은 A→B→A′ 교체 중 B에서 한 번도 그리지 않고 페이로드 주소와 세대까지 같을 때만 가능하며, 이때도 다음 세대에서 바로 갱신된다.

DSi 카메라 스캔라인 전송은 워드마다 하던 나눗셈을 몫·나머지 누적으로 바꿨다. 1,347,000회 호출 비교에서 출력·상태가 같았고 21~31% 빨라졌다. SD 폴더 동기화는 마운트 직후 사전 검사에서 이미 내용 해시로 "변경 없음"을 확인한 파일을, 같은 크기·FAT 시각이면 이어지는 내보내기에서 다시 해시하지 않는다. 16MiB 부하에서 86.2ms가 62.8ms가 됐고 10개 시나리오의 결과 보고가 같았다. 카트리지 저장 상태 복원은 곧바로 덮어쓸 스테이징 배열을 0으로 채우지 않는다. 오류 시 배열을 버리는 기존 구조 그대로이며 복원당 0.4~27µs가 줄었다. JIT 레지스터 할당기는 남은 레지스터 사용 집합을 명령마다 다시 훑지 않고 누적 갱신하고, 순위는 축출할 때만 계산한다. 7,083회 실행에서 할당 결정이 같았고 16·32명령 블록의 할당 작업이 3.1배·1.8배 빨라졌으며 1~4명령 블록은 컴파일당 6~10ns 느리다.

비공개 게임 두 개의 헤드리스 Software 1200프레임 ABBA 실행에서 1.1.175와 1.1.176의 최종 화면·누적 PCM·프레임버퍼 digest가 같았다.

같은 라운드에서 최소 위상 오디오 Read 재구성(A/A 잡음 안), 오디오 Finish 반복 구간 경로(연속 변화 구간 2~3% 느림), Software 3D 픽셀 불변식 끌어올리기(1.18% < 잡음 2.18%), JIT 블록 조회 fast-hit(잡음 안), NAND 쓰기 4KiB 묶음(잡음 안), 내장 데이터 `#embed`(4.0% < 잡음 7.5%), 캡처 블렌드 R/B 묶음 계산(컴파일러가 이미 SSE2 벡터화해 약 3배 느림)은 채택하지 않았다. 저장 데이터 더티 구간은 1.1.162에 이미 들어 있었다.

첫 SDL2 빌드는 화면 캐시 멤버를 새로 추가하면서 `.inc` 조각을 쓰는 프런트엔드 테스트 대역에 같은 멤버를 넣지 않아 실패했고, 첫 전체 CTest에서는 수정한 Vulkan 계측 기대값이 네이티브 판독 버퍼가 없는 배율 1에서 널을 역참조했다. 두 테스트 코드를 고친 뒤 새 스냅샷에서 다시 검증했다.

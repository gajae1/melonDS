# 1.1.159 — 텍스처 재사용과 오디오 처리의 중복 작업 감소

2026-09-22. 기준 1.1.158 `1d8e33da`, F:/melonDS, Windows UCRT64 Release.

## 변경

- 텍스처 또는 팔레트 범위가 dirty이면 전체 범위를 한 번 해시해 비교한다.
  내용이 같을 때도 다음 dirty 워드마다 같은 전체 해시를 다시 계산하던 작업을 없앴다.
  VRAM wrap·별칭, 팔레트 무효화, 해시 알고리즘·캐시 키와 capture 동기화는 유지한다.
- 일반 오디오 재생에서 조건 대기가 반환한 mutex를 유지한 채 큐 상태를 재확인한다.
  비활성 time-stretch 함수를 부르기 위해 잠금을 풀었다가 다시 잡던 작업을 없앴다.
  time-stretch가 활성화되면 기존처럼 잠금을 해제하고 native 처리를 실행한다.
- Minimum-phase의 응답 지원 길이는 검증된 정수 범위에서 정확한 올림 나눗셈으로
  계산한다. P<=256은 원래 길이, P>256은 `(length*P+255)/256`이다.
  기존 부동소수점 곱셈·나눗셈·ceil과 결과가 같고 필터 계수와 출력은 바꾸지 않는다.

기본 버퍼, gain, 필터 선택, 음색, guest capture와 저장 형식은 그대로다.
참고한 구현 방식은 기존 파일에 통합했으며 새 의존성이나 출처별 코드 폴더를 만들지 않았다.
외부 코드를 복사하지 않았고 기존 저작권·라이선스 표기는 유지했다.

## 확인된 효과와 집중 검증

실제 XXH64 호출을 계수한 동일 내용 입력의 작업량이다. 변경된 내용은 이전처럼
첫 비교에서 무효화하고, clean 입력은 해시하지 않는다.

| 입력 | 이전 해시 바이트 | 변경 후 |
|---|---:|---:|
| 512 KiB 텍스처 | 8 MiB | 512 KiB |
| VRAM을 반복 참조하는 2 MiB 텍스처 | 128 MiB | 2 MiB |
| 압축 팔레트 | 196,620 | 65,540 |

텍스처 집중 검사 7/7에서 VRAM 은행 OR 중첩·해제·복구, 같은 값 재쓰기와 재사용,
팔레트 변경, 반복 wrap, software/OpenGL/compute의 압축 팔레트·capture를 확인했다.
오디오 생산자 검사에서는 같은 소비량·잔량·대기 횟수에서 명시적 잠금/해제 쌍이
128/256/512프레임 조건의 7/4/2쌍에서 각각 1쌍으로 줄었다.
SDL 조건 대기 내부에 필요한 잠금 전환은 이 수치에 포함하지 않는다.
기존 FrontendAudio의 callback 경계, underrun 집계, 재개·재연결, spurious wake와
취소 검사가 전후 통과했다. 정수 지원 길이 계산을 포함한 DS/DSi 오디오 회귀도 통과했다.

이 작업량 수치를 전체 게임 FPS나 끊김 개선율로 해석하지 않는다.

## 채택하지 않은 후보

- JIT 물리 lookup 슬롯이 CPU·ISA·주소 별칭 때문에 교체됐을 때 기존 native 블록을
  즉시 실행하는 후보는 20만 충돌의 조회 수를 40만에서 20만으로 줄였고 집중 검사
  50/50과 아키텍처·게스트 사이클 기록 336개를 보존했다. 그러나 짧은 측정에서는
  비용이 늘었고, 긴 교대 측정도 충돌 시간 변화가 약 -0.4%에 그쳤으며 바뀌지 않은
  적중 경로의 변동이 더 컸다. 속도 이득을 확정하지 못해 원본을 유지했다.
- Minimum-phase의 응답 인덱스 캐시는 느린 음원 부하에서 약 3~7% 비용을 줄였지만,
  고밀도 대조 부하에서는 약 3~6% 증가했다. 좌우 SIMD 누적을 묶는 추가 후보도
  이를 해결하지 못했다. PCM 동일·처리 중 할당 0·큐 폐기 0만으로 채택하지 않았다.
- 이전 q=1.025 음질 후보도 그대로 보류했다. 이번 버전은 고음 감쇠 특성을 바꾸지 않는다.

## 남은 수락 범위

실제 사용자 장면의 고부하·저버퍼 끊김, Qt 표시와 함께 실행한 장기 청취,
물리 지연·장치 탈착 및 다른 OS/CPU 검증은 별도다. 전체 최적화 완료로 선언하지 않는다.

## 통합 검증

확정 커밋 `01fabcab`의 깨끗한 소스 사본을 F:/melonDS/build에 만들고 배포 빌드를
검증했다. 기존 작업 폴더의 미완성 DSP 수정은 이 빌드와 커밋에서 제외하고 원본을 보존했다.
전체 CTest 1010/1010, 실패·건너뜀·비활성 0, 249.41초, exit 0이다.

Solatorobo와 Pokémon Black을 각각 1200프레임, OpenGL 8배율, Minimum-phase로 실행했다.
게임별 PCM 3,851,152바이트와 최종 화면 294,927바이트가 1.1.158 대조군과 완전히 같았다.
타이밍 측정용 실행이 아니므로 FPS 차이는 개선 근거로 사용하지 않는다.
지원 길이 함수의 배포용 기계어에서도 부동소수점 곱셈·나눗셈이 없어지고 정수 shift로
계산되는 것을 확인했다. 이 관찰을 전체 오디오 CPU 절감률로 확대하지 않는다.

같은 Solatorobo OpenGL 8배율·Minimum-phase 입력을 실제 SDL/WASAPI 48 kHz 장치에
무음으로 20초씩 공급했다. 요청 버퍼와 실제 버퍼는 일치했다. 새 버전의 128프레임
버퍼에서 missing 546프레임·underrun 5회·empty 4회가 발생해 무결점 공급 검사는
실패했다. 256/512에서는 모두 0이고 세 조건의 core drop은 0이었다.
동일 조건의 1.1.158에서도 128은 missing 1174·underrun 11·empty 9,
512는 missing 258·underrun 1이 발생했다(256은 0). 기존에도 발생하던 문제이며,
순차 1회 측정의 숫자로 개선율이나 회귀 부재를 확정하지 않는다.
이번 변경은 저버퍼 끊김 해결로 발표하지 않으며 실제 청취·Qt 표시 경로도 미검증이다.

# 1.1.163 — SDL2 입력 목록 조회와 불필요한 LTO 검사 절감

2026-09-23. 제품 변경 기준 `ff74b81e` (이전 1.1.162 `889cd76d`). Windows UCRT64 Release.

## 변경

- SDL2 입력 처리에서 매 주기 조이스틱 ID 배열을 할당·해제하던 목록 조회를 장치 수와 순서별 instance ID 조회로 바꿨다. 동일한 순서의 ID 변화를 계속 감지하며 기존 잠금·선택·재연결 로직은 유지한다. SDL3는 기존 목록 조회를 유지한다.
- 두 LTO 옵션이 모두 꺼진 빌드에서는 결과가 사용되지 않는 CMake IPO 지원 검사를 건너뛴다. LTO를 사용할 수 있는 설정의 검사는 유지한다.

## 측정과 범위

SDL2 가상 장치 0·1·2개에서 변하지 않은 목록을 각각 50,000번 조회했다. 기존 경로는 각 경우 배열 할당과 해제가 50,000회, 새 경로는 0회였다. 장치 1개 기준 단일 측정 시간은 3,374→1,452µs, 장치 2개는 4,047→2,285µs였다. 장치 수가 같은 교체도 두 경로 모두 감지했다. 이는 입력 조회만의 국소 측정이며 프레임 속도 개선을 뜻하지 않는다. 원시 기록은 `local-docs/optimization-163-20260923/joystick/`에 있다.

SDL2 가상 장치의 분리·순서 교체·선택 모호성·재연결·중복 serial·열기 실패 6개 사례와 기존 FrontendJoystick 검사 10건이 통과했다. SDL3 목록 API의 할당 계약 때문에 해당 경로를 바꾸지 않았다. SDL3의 전체 프런트엔드 연결 실행과 물리 조이스틱 탈착은 수락 범위 밖이다.

GCC 16 UCRT64 Release, LTO 두 옵션 OFF 조건에서 기존 구성은 7.0초, 새 구성은 5.9초였다(각 1회). 새 구성에는 IPO 검사 임시 디렉터리가 생성되지 않았고 두 구성의 LTO cache 값은 OFF였다. 이는 특정 호스트의 구성 단계 관측이며 빌드 전체 시간의 보증이 아니다. 원시 기록은 `local-docs/optimization-163-20260923/ipo-probe/`에 있다.

같은 시기의 native 화면 복사 생략 후보는 같은 세대 재표시 빈도를 계측하지 않아 보류했고, compute span 인덱스 후보는 이미 실제 span 수를 전송·dispatch하고 있어 변경하지 않았다. 두 판단은 `local-docs/optimization-163-20260923/`에 있다.

## 통합 검증과 배포

독립 소스 `build/1.1.163-source`의 Release 빌드는 exit 0, 전체 CTest는 **1,022/1,022** 통과했다(194.87초). 빌드에 기록된 소스 식별자와 커밋된 소스 식별자는 `dbb339b1d77aad61be956305ca2ec3cb85cc84e93251e8b699f42b2d93658eeb`로 일치한다. 기존 작업 중인 `src/teakra/src/test_generator.cpp`는 이 버전의 소스·빌드·커밋에서 제외하고 보존했다. 이번 변경은 GPU·오디오 실행 경로를 수정하지 않아 1.1.162의 게임 대조를 반복하지 않았다.

Windows 런타임·소스 패키지 영수증은 검증 후 기록한다.

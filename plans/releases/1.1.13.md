# 1.1.13 — 치트 조건·반복 상태

상태: 구현·Windows 빌드·로컬 회귀 완료. 기준 1.1.12. NP-21의 D0/D1/D2·C0 의미를 명세와 생산 ARM7 IRQ 경로에서 대조한다. C5 카운터 수명은 근거의 확실성을 별도로 평가한다.

## 5페이즈

1. **근거·반례:** 원 저자 문서의 NEXT 조건 복원·D0 기본 상태·단일 C0 규칙과 현재 코드를 대조한다. false/true/false 조건, ENDIF 없는 반복, 정상 0/2 count와 루프 교체를 생성 입력으로 검증한다.
2. **수정:** 재현한 D1/D2 복원 시점과 D0 종료 상태만 고친다. datareg/offset은 반복 중 유지하고 D2 종료에서 초기화한다. C5 미확정 수명을 전역 counter 등으로 추측 구현하지 않는다.
3. **통합:** 실제 ARM7 VBlank IRQ hook·생산 메모리 read/write 결과를 확인한다. 기존 literal/loop/copy 취소·비활성화와 치트 편집/적용 회귀를 연결한다.
4. **검증:** 최종 Windows 빌드·전체 회귀를 실행하고 counter의 알려진 의미와 미검증 수명을 구분한다. 정상 동작을 보존하며 임의의 작은 실행 상한은 도입하지 않는다.
5. **배포:** 버전·EXE·패키지와 공개 소스/계획을 포크 master에 반영한다. 실제 Datel 장치·게임·다른 플랫폼의 수락은 별도로 남긴다.

[GBATEK 원 저자 문서](https://problemkaputt.de/gbatek.htm#dscartcheatactionreplayds)는 C0의 Y+1회·비중첩 반복과 NEXT의 조건 복원을 설명한다. [EnHacklopedia 작성자 문서](https://doc.kodewerx.org/hacking_nds.html)에서 C0가 실행 상태를 저장하고 반복 시 복원하며 D0에 이전 상태가 없으면 실행을 유지하는 규칙을 교차 확인한다. 이 자료 대조는 새 실기 측정 결과가 아니다.

## 변경과 검증

| 경계 | 수정 전 반례 | 변경·정상 대조 |
|---|---|---|
| D1/D2 | 첫 반복의 false IF가 다음 반복까지 유지되어 후속 data/offset 갱신과 쓰기를 생략함 | 모든 NEXT에서 C0의 조건 상태 복원. 0/2 count·ENDIF 없는 본문·외부 조건·indexed false/true/false를 실제 ARM7 IRQ로 실행 |
| D1/D2 종료 | D1은 상태 유지, D2는 최종 종료 때 초기화해야 함 | 반복 중 data/offset 유지, D1 후 유지, D2 종료 후 data/offset/조건·loop 설정 초기화를 메모리 값과 쓰기 개수로 대조 |
| D0 | 이전 조건이 없거나 이미 종료한 뒤 D0를 만나면 후속 쓰기를 비활성화함 | 이전 조건 없는 종료는 실행 상태 유지. standalone·IF 종료 뒤 추가 D0·D2 뒤 D0를 대조 |
| C0 | 별도 결함은 재현하지 않음 | 새 C0가 기존 loop를 교체하는 단일 레지스터 동작 보존. 종료 후 D1이 옛 반복 횟수를 부활시키지 않는 정상 대조 |

기존 코드의 정상/반례 7개 중 **정상 3개 통과·반례 4개 실패**, 수정 후 기존 literal/loop/copy 취소를 포함한 ARExecution **17/17 통과**를 확인했다. 이어 C5 mask 0과 mask 밖 비교값처럼 counter 수명과 무관한 참/거짓 대조를 추가했다. 검사는 생산 ARM7::TriggerIRQ·AREngine·게스트 메모리를 사용하며 ROM/BIOS나 사용자 치트 파일은 읽지 않는다. 단위 명령 직접 호출·호스트 포인터 대역만으로 코어 수락을 주장하지 않는다.

최종 Windows x64 프런트엔드 빌드와 전체 CTest **363/363, skip 0, 27.30초**를 확인했다. 최종 ARExecution 18개, 기존 치트 저장·Qt 메시지 취소·interpreter/JIT·실제 OpenGL/Compute 출력 회귀를 포함한다. UCRT64 GCC 16.2.0·CMake 4.4.3·Qt 6.11.2·SDL 2.32.10, C23/C++26·Release·JIT·OpenGL/Compute·AVX-512 빌드·LTO off 구성이다. FileVersion/ProductVersion은 1.1.13이며 AVX-512 실행은 CPU/OS dispatch 조건을 따른다.

배포 EXE/DLL 129개의 import 누락 0, 독립 PATH의 `--help` 종료 0, 공개 계획 22개의 상대 링크·개인 경로 검사를 확인했다. 실행 파일·필요 DLL/plugin·라이선스만 패키지에 포함하고 공개 소스 ZIP은 완료 커밋에서 만든다.

## C5와 남은 범위

[NitroHax 원저자 README](https://github.com/chishm/nitrohax/blob/c5b68b31a833d8aece47efe80594dde59e906332/README.md)와 [같은 revision의 ARM 핸들러](https://github.com/chishm/nitrohax/blob/c5b68b31a833d8aece47efe80594dde59e906332/BootLoader/source/cheat_engine.s)는 핸들러 안의 16비트 카운터를 진입마다 한 번 증가시키고 C5들이 그 값을 공유한다. 현행 melonDS의 RunCheat 지역 값·C5 방문마다 증가하는 방식과 다르다. NitroHax는 별도 homebrew 구현이므로 이것을 Datel 원 핸들러의 적합성 증거로 바꾸지 않는다. mask/equality 대조는 가능하지만 호출 간·치트 간 수명, 해제/재활성화, reset·savestate 기대값은 버전이 확인된 Datel 핸들러 또는 실기 trace가 필요하다. 이번에 영속 counter 정책을 추측해 도입하지 않았다.

C4, 불성립 조건 안의 중첩 동작을 포함한 전체 Datel 명령 적합성, 실제 게임 치트 효과·해제·중단 뒤 진행, 다른 플랫폼은 후속 수락이다. 상태 형식 14.1은 유지하며 성능 향상이나 전 명령 완성을 주장하지 않는다. 다음 증분은 CJ-03의 warmed ALU·shift·부분 flags와 CJ-06의 빈 LDM/STM 목록을 CPU별 정의·실행 결과로 대조한다.

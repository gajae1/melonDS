# 1.1.168 — SDL3 출력 주기·게임패드 폴링 보정

2026-09-24. 이전 버전 1.1.167. 기본 배포 설정은 SDL2이며 SDL3는 `ENABLE_SDL3=ON` 선택형 빌드다.

SDL3 출력 장치를 열기 전에 읽은 선호 버퍼 주기를 실제 콜백 주기로 표시하던 오류를 고쳤다. Windows WASAPI에서 128프레임을 요청한 재현 사례는 열린 장치와 콜백이 480프레임인데 UI 상태에는 128프레임을 보고했다. 열린 logical device에서 다시 조회한 뒤 480프레임을 보고하고, 열기·중지·재개·비동기 재열기·닫기 probe가 통과했다. SDL3 게임패드 상태를 수동 갱신하는 경로에서는 사용하지 않는 joystick/gamepad 이벤트 생성을 꺼서, 가상 패드 버튼 100회 전환 때 대기 이벤트 198개가 0개로 줄었다. 버튼 상태와 연결·분리 폴링은 유지됐다.

선택형 SDL3 Qt 전체 빌드를 Windows의 제한된 PATH에서 실행해 ROM 사본 부팅, 살아 있는 창과 정상 종료를 확인했다. SDL3 DLL·라이선스를 포함하고 SDL2 DLL을 제외한 배포 디렉터리에서도 재실행했다. SDL3 disk backend의 제품 출력 probe는 알려진 PCM을 기록했고, 30초 격리 게임 실행은 약 13.18초부터 0이 아닌 게임 PCM을 기록했다. 이는 실제 스피커 청감·지연, 물리 패드, 마이크 캡처, 장치 분리·재연결, 가시 화면 및 장기 사용 수락과 구분한다. 가상 마이크 dummy callback 수명은 별도 sidecar에서만 확인했다. 원시 probe와 로그는 로컬 비공개 `local-docs/bv20-sdl3-runtime-20260924/`, `local-docs/bv20-gamepad-probe-20260924/`, `local-docs/bv20-sdl3-mic-20260924/`에 있다.

ARM9 JIT 저장 후 캐시 재설정의 숨은 CPU·타이머 상태 차이는 [1.1.167](1.1.167.md)의 미해결 사항으로 남는다. 두 정산 시제품은 실게임 상태 또는 기존 출력이 달라 제품에 포함하지 않았다.

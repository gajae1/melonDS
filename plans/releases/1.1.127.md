# 1.1.127 — Vulkan 확대 표시와 오디오 종료 소유권

2026-09-16. 기준 제품은 1.1.126 / `4a6b2e71`, 작업 시작점은 문서와 fixture 수정이 포함된 `55dba795`다.
전체 로드맵 완료나 실기 정확성 승격이 아니라 D-004/GR-15와 AD-04의 제한된 구현 묶음이다.

## 구현

Vulkan의 2x/3x 결과를 native 크기로 줄이기 전에 보존하고, 같은 CPU 2D 레이어·window·OBJ·정수 색합성 규칙으로 표시 subpixel을 합성한다. 2D 배경/스프라이트의 native 디테일은 그대로다.
기존 `GetFramebuffers`와 CPU/DMA capture는 native 256×192로 유지한다. `GetDisplayFramebuffers`는 별도 표시 크기와 tightly-packed BGRA RAM 또는 기존 GL texture를 반환한다.
투명한 native 3D 샘플이 확대 subpixel을 가릴 수 없도록 3D 자리 아래 두 레이어를 보존한다. guest register·sprite·capture 처리는 scanline당 한 번만 실행한다.
배율 변경은 표시 메모리와 3D pipeline 준비 성공 뒤 적용한다. 이전 프레임, 상태 저장/복원, 스크롤, 밝기, 화면 교환과 중단/초기화를 처리한다.
Native QImage, GL RAM texture upload, 일시정지 이미지와 ROMSmoke에 실제 표시 크기를 전달한다. ROMSmoke는 RAM/GL에 같은 box resolve를 사용한다.
GL 확대 texture 할당 실패 때 upload와 크기 갱신을 중단하고 caller에 실패를 전달한다. 실패한 크기를 성공으로 캐시하지 않는다.
일반 동일 배율의 scaled scanline 조회는 연속 copy/blank 구간을 사용하고, 뒤에서 덮어쓸 native 확대 복사를 생략한다. 별도 성능 측정이 없어 FPS 향상률을 주장하지 않는다.

AudioOutput의 종료 시 미시작 요청·미회수 future·retiring 장치를 제어 스레드에서 정리한 뒤 종료 완료를 게시한다. native 해제 중 handoff mutex를 잡지 않는다.
SPU PCM·Minimum-phase 계수·보간/필터 기본값은 변경하지 않았다. callback drain과 최종 join의 무제한 대기 가능성은 남으며, timeout을 native API 취소로 표현하던 주석을 바로잡았다.
Compute Variant 비교에 const/noexcept를 명시하고 Qt의 정수 clamp를 동등한 표준 clamp로 바꿨다. 새 ISA나 전역 fast-math는 추가하지 않았다.

## 검증

설치된 Windows x64 CMake 4.4.3 / GCC 16.2.0, C23/C++26, LTO OFF로 전체 앱과 관련 target을 빌드했다. 앱 `--help`에서 1.1.127을 확인했다.
관련 CTest 110/110, 실패/skip 0(76.59초). 전체 CTest suite가 아니라 renderer/audio/표시·설정/capture 관련 선택이다.
추가 검토에서 발견한 GL resize 실패 처리 보강 뒤 영향받는 GL 표시 12/12를 다시 실행했다(19.96초). 무관한 전체 suite는 반복하지 않았다.

수정 전 실패도 보존했다. pending-open destructor는 `wrong owner=1`로 실패하고 수정 후 통과했다. 확대 표시 extent는 2x/3x에서 모두 실패하고 구현 후 통과했다. GL resize 실패 주입은 `rejected=0, retained=0, uploads=2`에서 실패하고 보강 후 통과했다.
Vulkan 검사는 실제 GPU의 1x/2x/3x 화면·7개 texture 형식·palette 갱신·batch·guest LDRH/capture 재사용·savestate·live scale을 포함한다. 새 검사는 실제 subpixel 디테일, native origin의 동일성, alpha hole/가림/window/밝기/scroll/모드·stop/reset을 확인한다.
GL 검사는 실제 추출한 product 표시 함수와 native GL context에서 양쪽 화면의 전체 texture bytes·확대/축소 전환·고해상도 paused frame·할당 실패/재시도를 확인한다. 전체 Qt event loop나 물리 표시 판정은 아니다.
기존 CPU 합성 기대값 비교와 scaled alpha/second-layer/window/계수 경계, 출력 guard를 함께 검사했다.

실제 Windows 기본 endpoint에서 product AudioOutput 라이브러리로 무음 Open→Start→Stop→Resume→Close를 시험했다. SDL/WASAPI 각각 요청128/512의 4조건 모두 통과했다. SDL은48000Hz·period128/512, WASAPIShared는48000Hz·period480이었다. period를 물리 지연으로 환산하지 않는다.
빌드 과정의 오래된 Compute/Allocation/Presentation config 대역, Vulkan 확대를 금지하던 UI 기대값도 현재 1x/2x/3x 계약에 맞게 수정했다. 허용 범위와 4x 거절을 명시적으로 검사하며 이미지 비교 오차를 넓히지 않았다.
초기109개 실행 중13개는 target 미빌드로 Not Run이었고, 다음14개에서는 오래된 UI 기대값1개가 실패했다. 이 이력은 로그에 남겼으며 최종110개에서 모두 실행/통과했다.

## 한계와 다음 단계

- 새 코드는 고해상도 3D 표시를 연결하지만 GPU 2D/capture·GPU image 직접 표시·4x 이상·Vulkan/OpenGL 성능 최적화 전체를 완료하지 않는다.
- 1x/guest capture 보존은 기존 같은 조건 대비 검증이다. 확대 native resolve를 DS 실기 결과와 동일하다고 선언하지 않는다. Classic도 실기 정답을 대신하지 않는다.
- 실제 게임/DSi·AMD/Intel·다른 OS·장기 사용·물리 장치 탈착/청취/지연은 이번에 검사하지 않았다. Vulkan validation layer 실행 근거도 이번에는 없다.
- 새 데이터 복사 생략과 run-based 조회의 효과는 성능 후보이며, end-to-end FPS나 지연 개선을 측정했다고 하지 않는다.
- third-party TOML의 deprecated literal 경고는 남는다. 모든 의존성 갱신이나 warning-free 빌드를 선언하지 않는다.

실제 현재 상태는 [Current_Status](../Current_Status.md)와 [Audio_Status](../Audio_Status.md)를 우선한다. 역사적 Task_Catalog/Release_Plan의 전체 상태 동기화는 이번 도구 요청 차단으로 남아 있으며, 원 과제 ID는 유지했다.
원본 실패와 최종 로그·JUnit·로컬 무음 검사기는 작업트리의 `build/evidence/resume-20260916/`에 있다.
GitHub Actions/macOS 빌드·개인 ROM/BIOS/NAND/저장 파일 사용은 하지 않았다. 기존 다른 작업트리의 파일은 변경하지 않았다.

# 1.1.14 — 키보드·Joystick 매핑 화면

상태: 구현·Windows 빌드·로컬 회귀 완료. 기준 1.1.13. 입력 설정의 실제 사용 결함을 우선 처리한 증분이다. 기존 책임 버전 1.1.14의 JIT 과제 완료를 뜻하지 않는다.

## 5페이즈

1. **재현:** 실제 InputConfigDialog와 Qt 키 이벤트를 연결한다. 장치 없는 정상 경로와 SDL 가상 컨트롤러가 연결된 경로를 비교한다.
2. **수정:** 장치 존재만으로 Joystick 화면을 여는 자동 전환을 제거한다. Keyboard·Joystick을 명시적 탭으로 표시하고 Keyboard를 기본으로 연다.
3. **통합:** 버튼 클릭→키 캡처→OK/Cancel→설정 파일→실행 매핑 적용을 검증한다. Joystick 설정은 별도 탭에서 접근하고 탭 전환 중 편집값을 보존한다.
4. **검증:** 일반 문자·Space·Enter·Tab·수정키 조합·Escape 취소·Backspace 해제와 재시작 후 설정 유지, 기존 프런트엔드 회귀를 확인한다.
5. **배포:** Windows 버전·실행 파일·공개 코드/계획을 반영한다. 사용자 설정·입력 장치 정보는 배포에 포함하지 않는다.

## 원인과 변경

기존 setupKeypadPage는 SDL 장치가 하나라도 있으면 Joystick 매핑 화면을 연다. 그 버튼의 `None`은 컨트롤러 매핑이 없다는 뜻이며 일반 키보드 키는 지정하지 않는다. 키보드 매핑 버튼이 다른 화면에 숨겨져 있어 키 변경 기능이 없는 것처럼 보인다. 사용자 키를 기본값으로 덮는 런타임 동작은 확인되지 않았다.

기존 아래쪽 화면 전환 버튼을 상단 Keyboard·Joystick 탭으로 교체했다. 각 탭에는 해당 장치의 지정 방법과 Escape/Backspace 안내를 표시한다. 기본 키·기존 사용자 지정 값·키 이벤트 표현·설정 파일 형식은 기존 경로를 사용한다.

기존 단일 KeyMapButton 검사는 전체 설정창과 장치 감지 분기를 실행하지 않아 이 문제를 놓쳤다. 새 InputConfigUI는 생산 `.ui`·dialog·매핑 버튼·Config 저장과 현재 소스에서 추출한 inputLoadConfig/키 핸들러를 사용한다. 수정 전 가상 컨트롤러 조건에서 키보드 버튼 숨김을 재현했고, 수정 후 관련 검사 10개가 통과했다. 변경한 키만 A를 누르고 이전 기본 키는 더 이상 A를 누르지 않는지 확인한다. 저장한 임시 설정을 새 프로세스에서 다시 읽어 실제 입력 마스크를 확인한다.

최종 Windows x64 프런트엔드 빌드와 전체 CTest **372/372, skip 0, 30.82초**를 확인했다. 별도로 Windows Qt 플랫폼의 150% 배율에서도 컨트롤러 연결→키 지정→탭 전환→저장→새 프로세스 적용이 통과했고, 생성 화면의 탭·버튼·안내문 배치를 확인했다. 외부 데스크톱 조작 없이 시험 프로세스 내부 Qt 이벤트를 사용했다. UCRT64 GCC 16.2.0·Qt 6.11.2·SDL 2.32.10, C23/C++26·Release·JIT·OpenGL/Compute 구성이다.

## 남는 범위

실제 물리 키보드·컨트롤러·OS IME와 게임 입력 지연 수락은 자동 Qt 이벤트 검사와 구분한다. 전체 최적화나 JIT 개선을 이 UI 변경의 결과로 주장하지 않는다. 다음은 CJ-03 warmed ALU·shift·부분 flags와 CJ-06 빈 LDM/STM 대조이며, 앞선 미완료 과제와 장치 수락은 유지한다.

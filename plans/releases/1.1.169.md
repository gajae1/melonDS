# 1.1.169 — ARM7 JIT 데이터 적재 타이밍 보정

2026-09-24. 이전 버전 1.1.168. 기본 배포 설정은 SDL2이며 SDL3는 `ENABLE_SDL3=ON` 선택형 빌드다.

ARM7 x64 JIT가 WRAM 주소로 처음 컴파일한 단일 적재 블록을 나중에 메인 RAM 주소에서 재사용하면, 실제 값은 새 주소에서 읽으면서 사이클은 처음 주소의 값을 유지했다. 이번 변경은 실행 주소의 메모리 타이밍과 메인 RAM 분류가 컴파일 당시와 다르면 해당 명령을 기존 해석기 경로에서 다시 실행한다. 같은 블록의 빠른 경로는 주소 비용이 일치할 때 유지된다.

집중 회귀 검사는 같은 `LDR` 블록을 WRAM에서 만든 뒤 메인 RAM에서 재사용하고, 메인 RAM에서 새로 컴파일한 블록 및 해석기와 적재 값·CPU 상태·사이클을 비교한다. 수정 전 코어에서는 값과 상태는 같지만 사이클이 `3/9/9`로 달라 실패했고, 수정 후 코어에서는 일치해 통과했다. 단일 메모리 접근에 대한 검증이며 ARM7 다중 레지스터 전송 전체의 타이밍을 수락하는 근거는 아니다.

같은 게임 입력으로 프레임 6001까지 실행한 비공개 기준/저장 후 JIT 리셋 경로는 수정 전후 모두 화면 해시가 각 쌍에서 같고 정상 종료했다. 두 경로의 숨은 저장 상태 차이는 **여전히 남아 있으므로 BV-17은 미해결**이다. 비공개 ROM, savestate, 계측·실행 로그는 배포와 이 문서에 포함하지 않는다.

소스 커밋 `ed69968ed191bfa115fdedfc5b9d6dac8f0e5df2`의 깨끗한 복제본에서 Windows UCRT64 Release를 기본 SDL2와 선택형 SDL3로 각각 빌드했다. SDL2 전체 CTest는 **1,023/1,023**(새 `core-jit-dynamic-timing` 포함), SDL3 오디오·입력 집중 CTest는 **48/48** 통과했다. 두 실행 파일의 패키지 소스 식별자는 `1d1bb6087c7eaef98aa1487dd5fd2645b9b098705abac68e41e2b86c8d9b39fd`로 같다. 원래 작업 중인 teakra 변경은 깨끗한 복제본에 들어가지 않았다.

두 Windows 배포와 패키징은 각각 exit 0이다. 제한된 시스템 PATH의 `--help` 검사, 배포 manifest 및 ZIP 검증을 통과했다. 각 런타임 ZIP은 325개 파일, 알려진 비공개 파일 0개를 담고, 기본 ZIP에는 SDL2 DLL만, 선택형 ZIP에는 SDL3 DLL만 있다.

두 런타임 ZIP을 각기 새 폴더에 풀고, 한글 이름의 게임 archive와 새 프로필로 첫 실행했다. 기본 SDL2와 선택형 SDL3 모두 약 20초 후 `[60/60]` 창에서 실제 게임 타이틀/메뉴 양 화면(320×508)을 캡처했고, `VCDJ` 카트 진입·부팅 로그, `WM_CLOSE` exit 0, 실행 파일·archive·원본 ROM·기존 작업 파일 해시 보존을 확인했다. 화면과 원시 기록은 로컬 비공개 `local-docs/release-169-20260924/`에 있다. 한 메뉴 화면은 실제 조작·저장 영속성·장기 진행·물리 스피커/마이크/패드 수락을 뜻하지 않는다. SDL3 번역 catalog와 선택적 D3D12 구성요소 부재 경고도 남아 있다.

이 해시와 첫 실행 기록은 패키징 후 추가한 문서이므로, 위 소스 ZIP에 담긴 같은 릴리스 문서에는 최종 표가 없다. 실행 코드와 패키지 소스 식별자는 바뀌지 않았다.

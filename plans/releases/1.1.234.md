# 1.1.234 — Vulkan 화면 쌍 합성 제출 통합

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 변경

확장 해상도의 GPU 직접 표시 합성에서 두 화면이 같은 업로드 메모리와 디스크립터를 재사용해 화면마다 제출하고 CPU에서 완료를 기다렸다. 이제 두 작업 세트를 준비한 뒤 하나의 command buffer에 두 화면을 기록한다. 제출은 2회에서 1회가 되고, 두 화면 사이의 CPU 펜스 대기가 없어진다. 최종 소비 전에 완료를 기다리는 규칙은 유지한다.

기존 단일 화면 합성·RAM 출력은 같은 준비/기록 코드를 사용한다. 화면별 Keep·CaptureOverride 보존, 변경 행 업로드, sparse dispatch, CPU 요청 시 readback, 지연 완료 콜백을 유지한다. Native2D의 기존 배치 경로와 OpenGL은 이번 변경 대상이 아니다. 새 외부 코드나 라이브러리는 도입하지 않았다.

## 검증과 한계

로컬 집중 검사 4개가 통과했다. 기본 NVIDIA 장치에서 화면 쌍 합성, 기존 RAM/직접 버퍼 경로, 실패 시 CPU 폴백과 직접 표시 렌더러를 확인했다. 직접 표시 VBlank는 제출 1회·중간 펜스 대기 0회를 만족했다. 별도 Radeon 합성 검사에서 1배·3배 픽셀을 CPU 합성과 비교하고, 서로 다른 화면·두 버퍼·변경 행 보존·동기/지연 완료·할당 실패 후 재시도를 확인했다. GPU 검사는 로컬에서 수행했고 코어 회귀 검사와 플랫폼 빌드는 CI에서 수행한다.

두 번째 컨텍스트 버퍼는 첫 화면 쌍 합성 때 약 0.95 MiB를 추가 할당한다. 보존할 CPU 행이 있는 경우에만 두 번째 화면 크기의 override 버퍼를 할당하며, 이는 4배에서 3 MiB, 16배에서 48 MiB다. 이미 할당한 작업 세트는 재사용한다.

현재 로컬 Radeon 내장그래픽 드라이버는 기존 직접 표시 경로가 요구하는 swapchain maintenance 확장을 제공하지 않아 RAM 표시를 사용한다. Radeon 합성 단위 검사는 실제 앱의 직접 표시 경로 활성화나 FPS 개선을 뜻하지 않는다. RAM 출력 합성은 아직 화면별 제출을 사용한다. 게임 플레이·창 표시·실제 입력 및 오디오 지연은 측정하지 않았다.

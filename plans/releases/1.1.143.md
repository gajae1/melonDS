# 1.1.143 — Vulkan 업로드의 프레임 단위 묶음 제출

2026-09-20. 기준 1.1.142 HEAD cf923eed. 메인 checkout과 빌드는 F:/melonDS, build/windows-dev다.

## 구현 — 지연 업로드 묶음

지금까지 모든 Vulkan 업로드(texture layer·배열 초기화·clear bitmap·1.1.142의 capture texture)가 각각 Begin→record→SubmitAndWait로 동기 제출됐다. 이제 opt-in 묶음(SetUploadBatching, Vulkan 3D renderer만 활성화)이 각 업로드 입력을 즉시 별도 staging 범위에 복사하고 목적지 image를 유지한 뒤, FlushUploads가 누적된 image copy·clear를 하나의 command buffer로 기록해 기존 Device::SubmitAndWait fence 한 번으로 완료한다. 묶음은 16MiB 또는 256 image op로 제한하고 그보다 큰 단일 업로드는 즉시 동기 제출한다. 순서 계약: capture snapshot 업로드는 Texcache->Update 전에 flush해 wrapping texture의 SyncAllVRAMCaptures 경계를 유지하고, native texture·clear는 RenderView가 소비하기 전에 flush한다. 같은 제출 안의 연속 transfer를 위해 pre-barrier가 TRANSFER_WRITE를 기다린다. clear bitmap 두 image는 원자적으로 예약해 절반만 큐잉되지 않고, fence 성공 후에만 clearBitmapReady가 선다. staging 성장 실패는 기존 할당·데이터를 유지한다. Device::SubmissionCount 진단 카운터를 추가했다.

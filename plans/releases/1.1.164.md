# 1.1.164 — 카메라 변환과 Windows ZIP 검증 비용 절감

2026-09-23. 제품 변경 `0c6e601d`·`aaf895d6` (이전 1.1.163 `5c412bfa`). Windows UCRT64 Release.

## 변경

UYVY·NV12 카메라 프레임을 화면 크기로 옮길 때 매 픽셀 쌍과 행마다 수행하던 좌표 나눗셈을 몫·나머지 누적으로 바꿨다. 입력 stride, 색상 변환, 프레임 게시 방식은 유지한다.

Windows 패키징은 런타임 ZIP의 각 파일을 SHA-256 확인을 위해 끝까지 읽는 동안 ZIP CRC도 확인한다. 이전에는 CRC 확인을 위해 전체 ZIP을 별도로 한 번 더 풀었다. 파일 이름·개수·매니페스트 해시·손상 파일 거부 조건은 유지한다.

## 근거와 범위

추출한 생산 함수에서 UYVY·NV12 변환의 기존·변경 출력은 생성 입력 28,504건씩 두 차례 바이트 단위로 일치했다. 짝 측정의 640×480→256×192 중앙값은 UYVY 31.1→25.8µs, NV12 59.5→37.5µs였고, 패딩 stride를 포함한 8개 조건 모두 두 실행의 18/18 라운드에서 후보가 빨랐다. 기존 CameraSettingsUI 집중 시나리오 11건도 통과했다. 측정은 실제 변환 함수 본문과 공통 `feedFrame` 복사 스텁을 사용했으므로 물리 카메라·전체 Qt 캡처 파이프라인·게임 FPS를 입증하지 않는다. 원시 기록은 `local-docs/optimization-164-20260923/camera/`에 있다.

1.1.163 런타임 ZIP(325파일, 103,949,829바이트)의 검증 단계만 기존·변경·변경·기존 순서로 측정했다. 릴리스 도구의 Python 3.14.7에서 기존 평균 1.029초, 변경 평균 0.508초였다. Python 3.13.11에서도 1.657초와 0.858초였다. 이는 ZIP 압축·배포를 포함한 전체 패키징 시간이나 게임 실행 속도 수치가 아니다. 정상 ZIP, CRC 오류, 잘린 멤버, 정상 CRC에 다른 내용 해시, 추가·중복·이름 변경 등 7개 사례의 합격/실패와 오류 문구가 기존과 일치했다. 원시 기록은 `local-docs/optimization-164-20260923/package/`에 있다.

같은 묶음의 빈 Slirp poll 생략은 유휴 비용이 작고 오류 전달 방식이 달라져 보류했다. Savestate 읽기 버퍼의 초기화 생략도 8MiB에서 차이가 작고 32MiB에서 측정 순서에 따라 결과가 뒤집혀 복원했다. 둘 다 이 버전의 생산 코드에 포함하지 않는다.

# 1.1.207 — GPU2D 복사·텍스처 입력 재사용과 Thumb 시프트

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

- GPU2D 입력 복사: 같은 원본 버퍼에서 출발·도착 주소가 모두 연속인 범위를 한 `vkCmdCopyBuffer`로 합친다. 순서·빈 구간·원본 전환을 보존하고 같은 버퍼 안의 복사는 합치지 않는다. 전송 바이트·입력 수명·장벽·제출·fence는 유지한다.
- 캡처 텍스처: CPU 텍스처 갱신·GPU 소유권 마스크 변경이 없으면 캡처 revision이 바뀌어도 조합 입력과 mapped 버퍼를 재사용한다. 디코드마다 최신 GPU 캡처 스냅샷을 연결하며, CPU 변경·마스크 변경은 입력을 재작성한다. 마지막 GPU 캡처 텍스처가 사라지면 보관한 버퍼를 해제하고 CPU 디코드로 돌아간다. 팔레트 입력은 해당 업데이트에서 디코드가 필요할 때 새로 만든다.
- x64 Thumb 즉시 시프트: 기존 공통 시프트 emitter가 목적지 레지스터에서 계산하게 해 scratch 왕복 복사를 줄인다. ARM 호출자는 기존 기본 scratch를 유지한다. 0/32 시프트·carry·플래그·guest 사이클을 보존한다. ARM64·오디오 코드는 이번 버전에서 바꾸지 않았다.

## 작업량과 한계

| 조건 | 이전 | 1.1.207 |
| --- | ---: | ---: |
| GPU 복사 검증 입력 40개, 합계 10,240 B | 40명령 | 6명령, 바이트 동일 |
| revision만 바뀐 캡처 텍스처의 CPU baseline 복사 | 524,288 B | 0 B |
| 위 조건의 mapped 입력 복사·새 버퍼 요청 | 532,480 B | 0 B·재사용 |
| 일반 Thumb 즉시 시프트의 임시 MOV | 2개 | 목적지 중첩 시 0개, 아니면 1개 |

복사 범위가 연속이지 않거나 CPU 텍스처/소유권이 바뀌면 각각 기존 작업이 필요하다. 캡처 baseline의 마스크·CPU 기여분 조합도 조건 충족 시 생략한다. 텍스처 디코드 자체와 팔레트 복사는 남는다. LSL 0과 LSR 32의 특수 처리는 같은 경로이며 ASR 32의 carry 추출도 보존한다. 실제 메모리 대역폭·처리 시간·게임 FPS 상승률은 측정하지 않았다. 다른 프로그램을 사용 중인 PC의 시간 변동을 채택 근거로 쓰지 않는다. 새 API/ISA 요구는 없고 GPU2D 기본 비활성은 유지한다.

## 검증

- 실제 GPU 복사 명령을 계수하고 CPU에서 독립 조합한 메모리를 참조로 전체 픽셀·빈 구간 보존을 확인했다. 원본 전환·출발/도착의 빈 구간·deferred 완료를 포함한다.
- 실제 프레임 루프와 캡처 레지스터를 통해 캡처 소유권을 등록했다. revision 변경·CPU 뱅크 OR 기여분 갱신·CPU 쓰기로 마지막 GPU 소유권 해제 후 소프트웨어 렌더러와 화면 전체가 일치했다. 입력 버퍼 생성 수로 재사용과 갱신을 확인했다. 초기 fixture는 수동 캡처 할당으로 core 소유권 등록을 누락했으며 정상 경로로 수정했다.
- Thumb 즉시 시프트의 12개 수계산 경계 입력을 추가했다. ARM9/ARM7, 원본/목적지 중첩, carry 0/1, 일부 플래그 덮어쓰기, 컴파일/재실행을 포함한다. 일반 JIT·fastmem 각각 ALU 8,196건과 기존 Thumb shift timing 검사가 통과했다.
- 로컬 집중 검사 5개가 통과했다. 추가 텍스처 변경 뒤 영향받는 `gpu-vulkan-native-deferred`만 재검사해 통과했다. full suite는 CI에서만 수행한다.
- Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

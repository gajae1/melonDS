# 1.1.205 — Vulkan의 불필요한 작업 생성·합성·복사 감소

2026-09-29. 릴리스 소스 커밋은 `61e272a8ace24970e910cdc2d18f057ffa68f961`다. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 3D 단일 종류 배치

raster variant가 하나면 모든 polygon의 variant가 0이므로 다시 분류할 필요가 없다. binning 단계가 fine mask의 polygon 순서를 유지해 최종 설명자를 직접 기록하고, 같은 atomic 카운터로 raster 작업 수를 만든다. CalcOffsets·SortWork의 dispatch와 두 단계 뒤의 장벽을 생략한다. binning 뒤의 compute/indirect 장벽과 배치 재사용 장벽은 유지한다.

배치당 dispatch 2개·장벽 2개, polygon×tile work마다 variant atomic 1개와 중간 설명자 저장·재읽기 16바이트가 줄어든다. 메모리 할당 크기는 그대로다. 다중 variant 경로, GL 참조 경로, 픽셀 깊이·반투명 ID·stencil·최종 효과와 빈 배치 처리는 유지한다. 단일 variant가 단일 polygon·알파·ID를 뜻하지는 않는다.

## 표시 합성과 GPU2D 스냅샷

표시 셰이더가 즉시 반환하던 Keep/CaptureOverride 줄만 포함한 8픽셀 높이 그룹을 CPU에서 제외한다. 남은 원래 그룹 번호를 최대 384개로 기록하고 한 dispatch에서 읽는다. 모든 그룹이 필요하면 원래 좌표를 사용하고 매핑 업로드·조회를 하지 않는다. 필요한 그룹이 없으면 dispatch가 없다. CPU capture override 전송과 읽기·제출·완료 순서는 유지한다.

생성 입력의 가운데 64줄만 합성할 때는 192줄 전체 대비 작업 그룹이 1/3이다. 16배율 사례는 196,608→65,536그룹이며 각 그룹은 64 invocation이다. 이 수치는 실제 vkCmdDispatch 인자를 확인한 작업량이고 FPS 향상률이 아니다. CPU 그룹 스캔, 최대 1,536바이트 매핑 저장소/업로드, uniform 분기와 sparse 경로의 매핑 조회 비용이 추가된다.

GPU2D Memory::Capture의 페이지 테이블은 `arena→stack→arena` 두 복사에서 새 arena 영역으로의 직접 복사 한 번으로 바뀐다. 4KiB 스택 테이블을 없애며, 스냅샷 크기에 따라 갱신 시 1~4KiB 테이블의 중복 복사를 피한다. Reserve/resize 뒤에 오프셋으로 접근하고 검증된 이전 영역과 새 영역은 겹치지 않는다. append 바이트 순서·generation·기존 COW view는 그대로다.

## 검증과 한계

- `gpu-vulkan-compute-spans`: Radeon GL/Vulkan의 1·2·3배율 Z/W 전체 픽셀 대조. shadow mask와 뒤의 shadow draw, 일반·캡처 텍스처를 각각 한 polygon/한 variant 배치로 나눈 결과가 기존 GL과 일치했다. polygon은 있으나 화면 밖이라 bin이 빈 경우에도 이전 프레임이 남지 않는다. 기존 빈 마지막 배치·최종 효과 검사도 통과했다.
- `gpu-vulkan-display-composition`: 기존 CPU compositor와 GPU/direct 출력 대조 통과. resident의 중간 64줄·모두 보존·전체 합성·비정렬 두 줄을 1·3·5·16배율에서 바꾸면서 픽셀과 실제 dispatch 수를 확인했다. 부분/전체 경로 전환 시 오래된 그룹 매핑을 사용하지 않는다.
- `native-2d-memory-snapshots`: 기존 dirty/override·예산 초과 원자성·view 재사용·불변 스냅샷 검사가 통과했다.
- `gpu-vulkan-display-diagnostics-frames`: 이전 1.1.204의 지연 할당 뒤에도 테스트가 readback 버퍼를 무조건 역참조하던 문제를 수정했다. 수정 전 실제 SegFault를 재현했다. 전체 읽기가 있을 때 버퍼 존재를 계속 요구하고, 없을 때도 기존 트래픽·시간 집계 검사를 유지한다. 수정 후 generated frame 진단 검사가 통과했다. 제품 렌더러의 새 충돌을 수정한 것으로 표현하지 않는다.
- Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다. 전체 검사는 CI에서만 실행한다.

새 subgroup/atomic 기능이나 ISA를 요구하지 않는다. GPU shader의 분기·레지스터 배치가 달라질 수 있으므로 모든 구형 GPU의 속도 향상까지 보장하지 않는다. 다른 프로그램 사용을 중단시키거나 게임 플레이·추가 성능 벤치마크를 수행하지 않았다.

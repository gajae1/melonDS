# 1.1.213 — OpenGL Compute 단일 종류 작업 정렬 생략

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

OpenGL Compute는 단일 raster variant만 있는 배치에서도 작업 목록의 시작 위치 계산과 종류별 정렬을 실행했다. 기존 Vulkan 방식처럼 binning이 최종 설명자를 직접 쓰게 하여 CalcOffsets·SortWork dispatch와 후속 장벽을 각각 두 개 생략한다. 종류별 work마다 실행하던 atomic 하나와 중간 설명자의 쓰기·읽기 합계 16바이트도 필요하지 않다. 이는 코드상의 논리적 작업량이며 GPU 하드웨어 트래픽이나 FPS 측정값이 아니다.

간접 dispatch 버퍼 바인딩은 정렬 여부와 무관하게 수행한다. 첫 작업 목록의 시작 위치는 clear 단계에서 초기화한다. 다중 종류 배치는 기존 정렬을 유지하며 빈 화면의 배경 지우기·배치 간 합성도 보존한다. 셰이더 프로그램 수와 요구 OpenGL 버전, 메모리 할당 크기는 늘리지 않는다. 일반 OpenGL 렌더러에는 이번 변경이 적용되지 않는다.

## 검증과 한계

- 실제 GPU에서 1·2배율의 단일 종류와 두 종류 장면 전체 픽셀을 비교하고 빈 화면의 배경을 확인했다. 두 종류 경로는 같은 색을 내는 untextured modulation/decal을 사용한다. 단일 종류의 indirect 호출은 raster 한 번, 두 종류는 정렬 한 번과 raster 두 번, 빈 화면은 0번이다.
- 기존 GL 작업량 안전 검사에서 첫 variant의 W만 읽던 관측을 Z/W 중 큰 값으로 수정했다. 단일 종류의 생산량은 이제 Z에 기록되므로 이 변경 없이 용량 초과 감시가 무력해지는 것을 막는다.
- 로컬 집중 검사 5개(단일 종류·다중 배치 blend·span 한도·Compute 화면/캡처·셰이딩)와 실제 Vulkan/GL 그래프 차등 검사를 통과했다. 생략된 GPU 검사를 성공으로 세지 않는다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다. 게임 플레이·사용 중인 PC의 FPS 비교·물리 입력/소리 지연 측정은 수행하지 않았다.

AudioSync OFF의 사용자 선택과 오디오 출력 버퍼는 유지한다. 비동기 클록 보정·독점 출력은 추가하지 않았다. 이번 GPU 변경을 틱 노이즈 해결이나 리듬게임 입력 지연 개선으로 간주하지 않는다.

## 구현 — DisplayFrame view

지금까지 표시 질의는 bool+void** 한 쌍이었다: true는 RAM BGRA, false는 renderer 특정 값(GL texture array id)을 뜻하고 수명·완료·반납 규칙은 암묵적이었다. 두 번째 GPU API(Vulkan)가 연결된 지금, GR-16의 최소 단위로 타입이 있는 Renderer::DisplayFrame view가 GetDisplayFramebuffers를 대체한다. kind(CpuBGRA/GLTexture2DArray)·표시 크기·payload·generation을 명시하고, GetDisplayFrame은 프레임 이용 가능 여부만 반환한다. native guest/capture 소비자는 GetFramebuffers를 그대로 쓴다.

계약(주석으로 강제): view는 생산자의 다음 프레임 swap·SetRenderSettings·renderer 교체까지 유효하고, 소비자는 renderLock 아래에서만 역참조·매번 재조회한다(1.1.134 규칙의 계약화). generation은 NDS.NumFrames에서 출발하는 host 전용 단조 stamp로, swap·설정/크기 변경·교체·guest NumFrames rewind에서도 이전 view를 부활시키지 않는다. CpuBGRA는 반환 시 완료, GLTexture2DArray는 생산자 프레임 종료 제출 후 완료(기존 공유 context 순서). 생산자가 버퍼/texture를 소유하고 다음 swap에 재사용하며 반납 신호는 없다. 미래 GPU-image kind는 acquire fence+release 신호 의무를 예약만 한다.

소비자 이관: ScreenPanelNative는 CpuBGRA만 받아들이고 paint에서 재조회한 지역 view로 복사한다(Screen.h의 게시 포인터 멤버 제거). ScreenPanelGL은 kind로 CPU 업로드/texture 바인드를 명시 분기하고, 프레임 부재 시 화면 본문을 건너뛰되 기존 present/OSD 흐름은 유지한다. EmuInstance::preserveFrame도 같은 kind 분기다. 생산자: 기본 구현은 GetFramebuffers를 CpuBGRA 256x192로 감싸 SoftRenderer는 무수정, GLRenderer는 texture id+실제 배율 크기, VulkanRenderer는 CPU 합성 ScaledBuffers를 돌려준다.

설계 결정과 직접 표시 보류 근거(GPU에 최종 프레임 부재·Presenter/renderer의 별개 VkDevice·효용 미측정)는 local-docs/pro-gr16-frame-20260920/design.md에 있다.

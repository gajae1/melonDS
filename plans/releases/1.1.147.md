## 구현 — opt-in 비용 분해

1.1.146까지 남은 비용의 위치를 기존 측정으로는 구분할 수 없었다(16x 3D ~3.6ms와 capture-heavy ~29.5ms 안에서 GPU 실행·전송·호스트 대기·캡처 변환·LCDC 재출력이 뭉쳐 있었다). 이번 단위는 local-docs/pro-vk-display-20260920/analysis.md가 권고한 GR-14 계측 단위다 — 다음 최적화 대상을 근거로 고르기 위한 측정 인프라이며, 동작·동기화·출력은 바꾸지 않는다.

MELONDS_RENDER_DIAGNOSTICS=1(opt-in, MELONDS_AUDIO_DIAGNOSTICS와 같은 방식)일 때만 RenderCostVulkanMeter가 할당된다. host 시간은 scope 전이로 겹치지 않게 배정해 DoCapture 안의 full readback을 캡처 루프에 중복 계상하지 않고, RunFrame 총계와 미설명 residual을 함께 둔다. GPU 시간은 별도 축이다 — 기존 command buffer 안의 이미 정렬된 작업 사이에 고정 용량 timestamp를 쓰고, 선택 queue의 timestampValidBits·함수 존재·유한 timestampPeriod를 확인한 뒤 lazy 생성하며, 결과는 변경 없는 fence 대기 성공 후에만 AVAILABILITY로 읽는다. 계측 전용 submit·DeviceWaitIdle·강제 wait·barrier·할당은 없고, pool/result/미지원은 unsupported·unmeasured로 보고한다(0ms나 renderer 실패가 아니다). 프런트엔드는 Presenter의 calls/submits/skips/failures·staging/transfer bytes·upload/submit/queue-present host ns와 paint/window/generation을 host 관측으로만 기록한다 — 표시 완료 시간으로 명명하지 않는다.

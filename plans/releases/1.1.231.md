# 1.1.231 — x64 JIT 레지스터 ROR 개수 검사 축약

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 변경

ARMJIT_x64/ARMJIT_ALU.cpp의 Comp_RegShiftReg에서 레지스터 ROR(op==3)만 개수 0 검사를 AND ECX,255 대신 TEST CL,CL로 바꾼다. ROR CL은 개수를 스스로 5비트로 마스크하므로 ECX 상위 비트가 남아도 결과가 같다. 개수 0에서 기존 carry를 보존하고, 개수가 0이 아닌 32의 배수일 때 결과 비트 31을 carry로 쓰는 처리는 그대로다. LSL·LSR·ASR은 ECX 전체를 32와 비교하므로 기존 AND를 유지한다. ARM64 JIT, ISA 기준선, 오디오·Vulkan·GL과 새 외부 코드는 바뀌지 않았다. 생성 코드는 레지스터 ROR마다 4바이트 줄어든다.

## 검증

- Thumb 3040건과 ARM 2016건에서 native와 interpreter의 레지스터·CPSR·guest 사이클이 일치했다.
- 74개 ARM 프로그램의 생성 코드 크기가 모두 정확히 4바이트 줄었다.
- ARM 고정 시험을 tests/CoreARMRegisterRotate.cpp로 승격했다. x64 전용 CI에서만 등록한다.
- 소스 검토는 op==3에 한정한 변경에서 정확성 차단 항목을 찾지 못했다. 개수 0 분기가 읽는 ZF는 두 방식이 같고, 이후 플래그 계산에 남은 ECX 상위 비트나 개수 검사의 SF·PF가 영향을 주지 않는다.
- 첫 Core CI에서 GCC 14가 새 테스트의 타입·멤버 이름 충돌을 거부해 멤버를 Aliasing으로 수정했다. 에뮬레이터 동작은 바뀌지 않았으며 수정한 소스로 CI와 패키지를 다시 검증한다.
- 게임플레이와 전체 로컬 테스트는 수행하지 않았다. 전체 회귀 검사는 플랫폼 CI 한 곳에서 수행한다.

## 측정

범위는 같은 프로세스에서 밀집 16 레지스터 ROR 블록을 캐시한 활성 스레드 사이클 성분(A/B 3회·A/A 3회, 바쁜 호스트)이다. 결과는 혼재이며 일반적인 속도 이득의 근거가 아니다(비공개 testcl/evidence.json).

| 조건 | 변화 | A/A |
| --- | --- | --- |
| ARM7 carry 미사용, count 256 | +2.28% | 0.91% |
| ARM7 carry 사용, count 32 | +0.72% | 0.63% |

두 조건 모두 A/A를 넘어 느린 쪽이다. 다른 조건은 개선·악화가 섞여 있고 잡음 폭이 커서 유리한 값을 성능 근거로 삼지 않는다. 확인된 것은 16 ROR 블록이 64바이트 작아진 코드 크기 감소뿐이다. 이전에 검토한 zero 분기 제거 후보는 보류로 남는다.

## 남은 범위

게임플레이 FPS, 물리 오디오·입력 지연, 저사양 기기, ARM64 호스트는 확인하지 않았다. 기존 Vulkan 저수준·JIT·오디오 로드맵은 열려 있으며 이 버전은 원래 과제의 전체 완료를 뜻하지 않는다.

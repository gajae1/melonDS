# 1.1.229 — 소프트웨어 3D 팔레트 텍스처 RGB6 변환 캐시

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

소프트웨어 3D 렌더러 인스턴스가 262,656바이트(RGB6 팔레트 256KiB + 페이지 비트맵 512바이트)를 추가로 가진다. 텍스처 format 3·4는 16색 팔레트 페이지를 RenderPolygons 호출마다 필요할 때 한 번 RGB6로 변환하고, 이후 픽셀은 변환값을 읽는다. 텍스처 인덱스 캐시나 전체 텍스처 디코드 캐시는 없다. 페이지 플래그를 호출마다 초기화하므로 재시작·리셋·로드 뒤 재사용도 처리하며 VRAM dirty 소비자를 추가하지 않았다. 압축 텍스처 의미는 바뀌지 않는다. 작은 인라인 공통 경로와 분리한 스칼라 디코더(좌표 래핑 후 실행)로 네이티브 GCC 빌드의 format 3·4 픽셀 경로에서 조회 함수 호출을 없앴다. Vulkan·GL 3D·오디오·입력 변경과 새 외부 코드는 없다. 렌더러당 RAM이 256.5KiB 늘어나는 비용이 명시적으로 따른다.

## 검증

- 정확성 테스트 560,640픽셀(2,242,560바이트)의 출력 SHA-256이 99cbeac2f33e97a5c6f30e712cb6bdc755b227069e7f1cb99f5c6d534cf66ce2로 기준 ae8f0e7f와 일치했다.
- 초기 집중 테스트 8개가 통과했고, 디코더 분리 뒤 최종 셰이더 golden을 다시 확인했다. 영향받지 않은 기존 렌더 스레드 프로토콜 검사 7개의 결과는 재사용했다.
- 내장 DS 부트 ROM을 사용하는 소프트웨어 1배율 Sinc6 ROM 2건(Black·Solatorobo) 1200프레임의 프레임·PCM이 1.1.228과 일치했다. 게임플레이·물리 입력·오디오는 하지 않았다.
- 전체 회귀는 CI에서만 수행한다.
- Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.
- NetBSD의 첫 실행은 코드 빌드 전 VM 패키지 준비에서 sqlite3 의존성을 찾지 못해 실패했다. 공식 저장소에서 요구 버전 이상의 파일 제공을 확인한 뒤 실패한 NetBSD 작업만 한 번 재실행했다. 나머지 성공한 검사는 재사용한다.

## 측정

내장 DS 부트 ROM을 사용하는 소프트웨어 1배율 Sinc6 부팅 구간 1200프레임을 게임당 A/B 2쌍·A/A 2쌍으로 측정했다(캠페인 31.03초). 아래는 A/B 쌍별 중앙값 변화(음수는 감소)와 자기 A/A 절대 중앙 변동이다.

| 게임 | 지표 | 변화 | A/A |
| --- | --- | --- | --- |
| Solatorobo | frame_ns_total | -2.2538% | 0.2881% |
| Solatorobo | 240프레임 이후 | -3.9972% | 0.455% |
| Solatorobo | 사이클 | -4.1898% | 0.6712% |
| Black | frame_ns_total | -0.73% | 12.83% |
| Black | 실행·산출물 확인 경과 시간 | +9.40% | 4.97% |

Solatorobo는 세 지표 모두 자기 A/A를 넘는다. Black의 프레임 처리 결과는 A/A 안의 잡음이므로 개선을 주장하지 않으며, 실행·산출물 확인 경과 시간은 오히려 나빴다. 실행 경과 시간에는 프로세스 종료 후 산출물 해시 확인도 포함된다. 프레임 측정값은 부팅 구간 처리 시간이며 게임플레이 FPS·물리 오디오/입력·저사양 CPU 근거가 아니다. 매우 성긴 256색 사용에서는 팔레트 준비 비용이 절감분보다 클 수 있다(이전 마이크로 측정이 이 절충을 보였으며 최종 마이크로 이득은 주장하지 않는다). 비공개 프로토타입 값과 이전 변형의 결과는 최종 성능으로 공개하지 않는다.

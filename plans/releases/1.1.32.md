# 1.1.32 — 상태 section·파일 내보내기·수신 경계

기준은 1.1.31(`dc29e7b54ec99794f28832598d59c91ff79af3c8`), 검증일은 2026-09-11이다. CJ-10/FS-01/02, FS-06, NP-01/03/10/11의 재현 가능한 경계를 독립 작성 후 통합했다. 원래 책임 버전이나 전체 호환성의 완료를 뜻하지 않는다.

## 변경과 근거

**상태 파일:** 길이가 짧은 section이 다음 section의 헤더·본문을 자기 데이터로 읽던 반례를 거부한다. 각 읽기는 현재 section의 끝을 지키며 실패한 읽기는 대상 값을 부분 변경하지 않는다. 누락·빈 NDSG는 초기 설정 적용 전에 거부하고, 뒤쪽 section의 실패는 기존 frontend 복구 경로로 돌아간다. 읽기 모드의 `Finish()`가 입력 파일의 길이 필드를 고치던 동작도 제거했다. 정상 writer의 14.2 형식은 유지한다.

**FAT/NAND 내보내기:** 두 번째 블록의 읽기 오류·짧은 읽기, 짧은 host 쓰기, source close와 최종 교체 실패를 검사한다. Qt의 QSaveFile을 쓰고 직접 덮어쓰기 fallback을 금지한다. source를 성공적으로 닫은 뒤에만 새 파일을 commit하며, 실패하면 기존 목적지와 해당 파일의 인덱스 정보를 보존한다. 인덱스 파일도 원자적으로 교체한다. NAND는 기존 공개 boolean 결과로 실패를 전달하고, FAT의 private Save 실패는 소멸·이동 소유 경계에서 기록한다.

실패 후 재열기에서 미반영 guest 파일을 host import 정리가 지우던 경로도 수정했다. 기존 인덱스가 있으면 먼저 전체 pending 파일의 충돌을 검사한다. 안전한 미반영 파일은 재시도하고, host 편집·삭제나 증거 부족으로 양쪽을 고를 수 없으면 이미지·host·인덱스를 보존하며 동기화된 열기를 거부한다. 같은 크기·같은 시각의 host 및 guest 편집도 검사한다. 기존 `FILE` 행을 유지하고 별도 선택 `HASH` 행을 추가하므로 구버전 parser가 파일명에 해시를 붙이지 않는다. 기존 SHA-1은 우발적 내용 차이 판별용이며 인증 수단이 아니다.

**LocalMP/LAN:** 수신 함수에 목적지 용량을 전달할 수 있다. 기존 호출의 기본은 Wi-Fi 수신 버퍼에 맞춘 2048바이트이며 reply는 기존의 AID별 1024바이트 슬롯을 지킨다. 넘는 본문은 복사하지 않고 해당 기록을 끝까지 소비하므로 다음 패킷을 손상시키지 않는다. LocalMP의 2376바이트 전송 한도와 LAN v1의 큰 프레임 수용은 그대로이며, 충분한 용량을 넘긴 소비자의 전체 payload 대조를 유지했다. LocalMP의 잘못된 instance·길이·null·AID는 큐 접근·shift·복사 전에 거부한다. 빈 AID0 reply는 정상 동작으로 유지한다.

**GDB qCRC:** 주소와 길이를 끝까지 파싱하고 32비트 주소 공간을 넘는 범위는 거부한다. 끝이 정확히 주소 공간 경계인 정상 요청은 마지막 바이트까지 읽는다. [GDB의 qCRC 명세](https://sourceware.org/gdb/current/onlinedocs/gdb.html/General-Query-Packets.html)에 맞춰 MSB-first, 초기값 `FFFFFFFF`, 최종 XOR 없는 CRC를 사용한다. GNU libiberty의 실제 `xcrc32` 함수를 컴파일한 독립 oracle과 빈 입력·비균일 본문·128바이트 경계·다중 블록을 대조했다. ROM·일반 저장용 공용 CRC 구현은 변경하지 않았다. 예전의 잘못된 zlib CRC를 기대하던 비표준 client의 값은 달라진다.

## 검증

상태 경계는 변경 전 실패와 정상 대조를 기록했고 실제 core/frontend의 기존 세션 보존과 다음 생성 frame을 확인했다. 파일 내보내기는 생성 FAT/NAND와 실제 Qt 쓰기·Windows 교체 거부를 포함한 작업자 집중 검사 40/40을 통과했다. 통합 후 저장·LocalMP·LAN·GDB 관련 검사 91/91이 통과했다. 경계 검사에는 예전 최대 전송 크기를 줄이지 않은 정상 대조와 잘못된 입력 뒤의 정상 통신이 포함된다.

최종 Windows x64 Release 전체 빌드가 성공했고 CTest **607/607 통과·실패 0·건너뜀 0**, 병렬도 2에서 **71.07초**였다. 최종 application object를 사용하는 생성 guest의 Qt 실패/Cancel/명시적 재시도/복구와 guest 보존도 통과했다. 의도적으로 주입한 shader 실패는 복구 검사의 입력이며 정상 게임에서 발견한 오류가 아니다.

원본 writer가 만든 수정하지 않은 14.0 상태 파일을 원본 실행기와 최종 1.1.32 core 양쪽으로 읽었다. 생성 DS 카트의 RAM·32개 CPU 레지스터·일반 save와 다음 263-scanline frame 관측값이 일치했다. 원본 binary·fixture·파일은 이전 manifest와 해시를 대조했고 헤더나 section을 패치하지 않았다. 모든 게임·DSi·모든 상태 버전 이관을 의미하지 않는다.

배포본 129개 PE의 누락 import가 없고, 깨끗한 PATH에서 도움말 실행이 성공했다. 검증한 EXE와 의존성만 runtime에 선별하며, 커밋된 소스·EXE·ZIP 해시를 manifest에 기록한다.

## 호환성과 남은 조건

- 일반 게임 저장·설정·LAN v1 wire 형식과 상태 writer 14.2는 유지한다. 기존 14.x 읽기와 구버전의 새 14.2 읽기 가능 여부는 별개다. 14.2를 지원하지 않는 원본이나 Android의 별도 13.0 형식까지 역방향 지원한다는 뜻은 아니다.
- FAT sidecar의 `HASH` 행은 구버전이 무시할 수 있다. 해시가 없는 정상 legacy 인덱스는 내용 일치를 확인해 받아들인다. 양쪽 내용이 다른데 이전 기준 내용이 없으면 보수적으로 거부할 수 있다. 인덱스 자체가 없는 경우의 기존 source-directory 우선 도입은 유지되므로, 복구를 강제하려고 `.idx`를 지우지 않는다. 충돌 시 세 파일 집합을 보존하고 SourceDir 동기화를 끈 이미지에서 guest 데이터를 추출해 비교한다.
- 파일별 원자적 교체이며 폴더 전체 transaction은 아니다. 별도 파일의 성공, 삭제·디렉터리 작업은 이미 반영될 수 있다. 검사 후 다른 프로그램이 파일을 바꾸는 경쟁, 전원 손실, network filesystem과 상세 복구 UI는 미검증이다. 변경이 없어 보이는 guest·host의 내용 판별에 추가 읽기가 필요하며 성능 최적화로 발표하지 않는다.
- 비Qt frontend는 `Platform::WriteFileAtomically` 계약을 구현하거나 producer를 실행하지 않고 false를 반환해야 한다. Qt 타입은 core API에 들어가지 않았다. 이미지 단독 사용은 성공한 sidecar 쓰기를 요구하지 않는다. MPInterface를 직접 구현하는 외부 frontend는 수신 함수의 capacity 인자를 맞춰야 한다. 실제 Android·다른 frontend 이식과 native ARM64·macOS·Linux 실행은 남는다.
- 원본과의 LAN 방향별 결과는 [1.1.30 기록](1.1.30.md)을 따른다. 이번 수신 경계 검사로 원본 client의 첫 UDP 유실, 구버전 혼합 다자간·두 PC 게임을 해결했다고 주장하지 않는다. 게임 안의 로컬 무선 메뉴와 별도 Internet Wi-Fi 연결은 계속 필요하다.
- 네트워크 자동조절·멀티코어·PGO·새 JIT/GPU 최적화는 이번 코드에 넣지 않았다. 해당 후보는 측정·안정성·구버전 계약을 먼저 확인한다. 실제 게임·DSi·물리 장치·다른 GPU·장기 수락은 계속 열린다. 배포에 개인 ROM/BIOS/NAND/설정/세이브를 포함하지 않는다.

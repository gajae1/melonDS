# 1.1.186 — Vulkan 업로드와 렌더링의 제출·대기 통합

2026-09-26. 구현 커밋 `62a689ea`, 릴리스 소스 `fe3bafac396dc0fded63347b9bc80a21da10e9e2`. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

텍스처나 clear bitmap이 바뀌면 기존 경로는 업로드를 제출하고 기다린 뒤 렌더링을 별도로 제출했다. 이제 대기 중인 업로드를 렌더링 명령 버퍼 앞에 기록하고 같은 fence에서 완료한다. 전송 이후 셰이더가 읽는 barrier와 완료 전 staging·이미지 수명은 유지한다.

명시적 `FlushUploads`, 업로드 배치 크기 제한, 기본 동기 API와 캡처 텍스처의 선행 동기화 경계는 그대로다. 잘못된 프레임도 이미 접수한 업로드를 완료한 뒤 검증 오류를 보고한다. 제출·대기가 실패하면 장치를 퇴역시키고 재제출하지 않는다.

## 확인한 효과와 한계

- ROM 없는 고정 20프레임, 텍스처 32개와 clear bitmap 갱신: 1배율·3배율 각각 제출 **37회 → 19회**. 업로드가 있는 프레임은 2회 → 1회, 캐시가 준비된 프레임은 1회, 완전히 같은 프레임은 0회다.
- 배율별 native 983,040픽셀이 독립 소프트웨어 렌더러와 바이트 단위로 일치했다. 기존과 새 실행의 프레임별 해시도 같다.
- RTX 5080의 집중 headless 검사 **7/7 통과**, skip 없음. 전송 버퍼 재사용, 공유 fence, 입력 snapshot, 잘못된 프레임, 대기 실패·자원 수명, 업로드 batching, 1배율·3배율 렌더링과 캡처 텍스처를 확인했다.
- 이 수치는 GPU 제출·대기 감소이며 FPS 향상률이 아니다. 업로드가 드문 장면의 효과는 작을 수 있다. 모든 구형 GPU나 실제 창 표시 성능을 검증한 것은 아니다.
- 별도로 실험한 native readback 지연 후보는 시간 편차 때문에 개선을 확정하지 못해 채택하지 않았다. 이번 버전은 그 후보를 포함하지 않는다.

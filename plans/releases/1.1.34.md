# 1.1.34 — 알파·안개 정밀도, 조건부 JIT 사이클, 배포 소스 식별

기준은 1.1.33(`ca9cd89d2641b3d6fecac3001730d4d38015ec5a`), 검증일은 2026-09-12다. GR-08, CJ-02, NP-03, BV-01/05/18의 재현 가능한 결함을 통합한다. 전체 계획이나 원래 책임 버전의 Vulkan 기능이 완료됐다는 의미는 아니다.

## 변경과 근거

**Compute 합성:** DISP3DCNT bit3이 꺼져 있어도 반투명 폴리곤과 A5I3 texel을 배경과 섞던 문제를 수정했다. 합성을 끈 경우 기존 배경색과 섞지 않으며, 켠 경우의 정수 합성은 유지한다. 실제 source-A 캡처와 guest ARM9 LDRH로 확인했다.

**클래식 OpenGL 합성:** 고정 기능의 정규화된 부동소수점 합성 대신 6비트 RGB와 5비트 alpha를 사용한다. alpha16 빨강을 불투명 녹색 위에 놓을 때 `0x81F0` 대신 software·Compute와 같은 `0x81D0`을 출력한다. 기존 반투명 batch별 화면 영역을 별도 GPU 텍스처에 복사하며 같은 polygon ID의 중복 픽셀은 기존 stencil 규칙으로 거부한다. 폴리곤마다 batch를 나누지 않는다.

**낮은 alpha와 안개:** polygon alpha4와 texture alpha4/5를 곱했을 때 0인 결과가 1로 올라가는 문제를 실제 GPU에서 확인했다. 텍스처와 폴리곤의 정수 modulate alpha를 먼저 구한 뒤 alpha reference와 비교한다. 최대 안개 농도에서 5비트 녹색8이 6비트16으로 잘리던 별도 오류도 확인했다. 최종 fog는 정수 농도·색·alpha로 합성하고, 기존 두 색 텍스처의 읽기/쓰기 역할을 교환해 전체 화면 복사를 추가하지 않는다. 리뷰에서 제기한 density65 검은 안개 후보는 이 GPU에서 재현되지 않았으며 실행 실패로 계산하지 않는다.

**조건부 JIT 사이클:** A64 생성기의 일반/강제 사이클 누적 경로와 조건부 실행·fallback의 누적을 바로잡았다. x64에서도 건너뛴 명령이 0사이클을 소비하는 결함을 실제 cached block의 native dispatch로 확인했다. 일반 C 사이클은 실행/비실행 경로에서 공통으로 누적하고, 추가 내부 사이클이 있는 명령은 건너뛴 경로의 C를 별도로 더한다. 이전 CPU-loop 관측의 2사이클은 누락된 명령 뒤의 분기까지 실행한 결과였으며, 그 명령 자체가 2사이클을 소비한 것이 아니다.

**LAN host 시각:** 수신 host 시각의 하위32비트가 0~15이거나 wrap을 통과할 때 정상 큐 패킷을 버리던 비교를 unsigned 경과 시간으로 수정했다. 기존 유효기간16ms, 미래·역행 시각의 stale 처리, wire 형식과 guest 시각은 유지한다.

**배포 소스 식별:** 선택 옵션 `MELONDS_PACKAGE_IDENTITY=ON`은 빌드 시 현재 소스 내용의 식별값을 EXE에 넣는다. 패키저는 실제 EXE의 `--build-info`를 읽어 커밋된 소스와 일치하는지 확인한 뒤 ZIP을 만든다. 소스가 바뀐 뒤 이전 EXE를 재사용하면 거부한다. 지정한 문서만 바꾼 커밋은 EXE를 다시 링크하지 않고 포장할 수 있다. Git의 줄바꿈 정규화를 사용하며 신규·삭제·한글·공백 경로도 반영한다. 기본값 OFF의 일반 소스 빌드는 이 기능 때문에 Git이나 Python을 요구하지 않는다.

## 검증

세 렌더러 각각 alpha44조합, 겹침·낮은 밝기·bitmap 배경24조합을 같은 엄격한 기대 픽셀로 대조했다. alpha와 fog 정밀도는 15비트 캡처만으로 구분할 수 없는 채널을 포함하므로 별도의 6비트 출력22조합을 사용했다. 이 직접 GPU readback 검사는 캡처 동기화 증거로 사용하지 않는다. 새 GL 저장 할당 실패의 software 복구·진행 중 캡처 보존·재시도와 객체 수명도 통과했다.

x64 조건부40/40에는 실제 cached native dispatch20개가 포함되며, 기존 block/fallback298/298도 통과했다. A64 production emitter의 생성 코드 모델28/28 및 기존 산술144/144은 native A64 실행과 구분한다. LAN packet38개와 실제 ENet loopback도 통과했다.

배포 식별은 실제 작은 CMake 바이너리의 소스 변경·미재빌드 거부·재빌드 수락·문서만 변경·추가/삭제·CRLF 시나리오, 실제 앱의 JSON 출력, 옵션 ON/OFF 및 Gitless 기본 빌드로 확인했다. 최종 Windows x64 Release 빌드와 CTest **631/631 통과·실패0·건너뜀0**을 확인했다. 병렬도2에서 **75.94초**였으며 같은 최종 코드의 전체 검사는 한 번 실행했다. 실제 application object로 실행한 생성 guest의 Qt 설정·Cancel·실패·재시도와 guest 상태 보존도 통과했다. 안개 출력 텍스처 교환 뒤의 실제 캡처 소비자 대조도 세 렌더러에서 통과했다.

배포본129개 PE에 누락 import가 없고 깨끗한 PATH의 도움말 실행이 성공했다. 실제 EXE의 `--build-info`는 표시 버전1.1.34와 현재 source ID가 일치하며 빈 실행 폴더에 파일을 만들지 않았다. 소스 ID 계산은 이 환경에서 약0.67초였다. 커밋·EXE·ZIP 해시는 배포 manifest와 로컬 검증 기록으로 남긴다.

## 호환성과 남은 조건

- 일반 게임 저장·설정·LAN v1·상태 writer14.2는 유지한다. 이전 writer를 지원하지 않는 바이너리의 역방향 상태 읽기 및 Android의 별도 상태 형식은 다른 범위다.
- GL 보조 색 저장은 배율 적용 픽셀당4바이트(1배율192KiB)를 추가하며 반투명 batch마다 GPU 영역 복사 비용이 있다. 안개는 보조 텍스처를 출력으로 재사용한다. 실제 게임 FPS 향상이나 다른 GPU의 성능을 주장하지 않는다. shadow stencil 정리에서의 중복 복사 비용은 후속 최적화 후보로 기록한다.
- material RGB 보간·toon/decal·edge/AA·실기 shading 전체가 정확해졌다는 의미는 아니다. 이 변경은 확인한 최종 alpha·반투명 합성·fog 경계의 증거를 제공한다.
- native ARM64·Android·Linux/macOS·다른 GPU·실제 DS/DSi 게임·물리 장치·장기 실행은 별도 수락 조건이다. GitHub Actions와 macOS 빌드는 사용하지 않았다.
- source ID는 소스 내용과 EXE의 결속이며 컴파일러·외부 DLL·재현 빌드·전자서명이나 진본 증명이 아니다. 기본 OFF나 이전 EXE는 이 패키저의 식별 검사를 통과할 수 없다.
- 자동 네트워크 조절은 아직 도입하지 않았다. host 대기 budget의 wrap·취소 응답성·관찰 전용 계측을 다음 작업으로 남기며 실제 두 PC·구버전 혼합 통신은 별도 검증한다.

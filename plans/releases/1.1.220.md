# 1.1.220 — Sinc 정렬 위상의 다운샘플 계수 공유

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 문제와 변경

Sinc 다운샘플 경로는 각 채널 출력마다 커널 계수와 정규화 합을 계산했다. SPU의 채널 시작은 Timer를 TimerReload로 맞추며, 샘플 주기가 믹서 주기를 정확히 나누면 위상 0이 반복된다. 이제 elapsed가 0이고 mixPeriod/period가 정확한 정수이며 2..512 범위의 2의 거듭제곱일 때 원래 계수를 공유한다. 다른 위상·비율은 기존 계산을 유지한다.

48×(2+4+…+512)=49,056개의 raw float 계수와 double 합 9개를 처음 Sinc 채널 생성 때 한 번 준비한다. 배열 payload는 196,296바이트(약 192KiB)로 모든 채널이 공유하며 채널마다 추가되지 않는다. 출력 중 새 배열을 할당하지 않는다. 각 16탭 dot의 누적 순서와 마지막 double 합으로 나누는 연산을 보존한다. 계수를 미리 정규화하거나 큰 dot로 합치지 않는다. 기존 무음 생략, 필터 계수·히스토리·저장 상태·SIMD 선택·오디오 버퍼 설정은 유지한다.

## 검증과 한계

- 기존 Sinc 이력 검사와 추가된 캐시/대체 경로 540개 출력의 전후 서명이 자동 SIMD와 강제 scalar 각각 일치했다. 캐시 경로 서명은 native `7c35fd7e94c5c193`, scalar `67ebbc0d88f27d53`이며 둘 사이의 차이를 없애려는 변경은 아니다. 기존 무음/저장 상태 서명 `f71a19652aed948a`도 유지했다. 캐시의 9개 비율과 인접 위상, 352/512 믹서 주기, 링 경계, 비영/0 이력, DC 정규화를 확인했다.
- 실제 NDS SPU·믹서·48kHz PCM 출력을 쓰는 합성 PCM16 반복 입력 4개를 비교했다. 각 입력의 전후 PCM 바이트가 같았으며 합계 66,078개의 s16 샘플이다. ROM·BIOS나 물리 오디오 장치를 사용한 플레이 검사는 아니다.
- 같은 실행 파일 쌍을 순서 교차로 7회 측정한 중앙값은 아래와 같다. 워밍업 후 SPU Mix와 출력 읽기 시간을 포함한다. 사용 중인 Windows 호스트에서 측정했으므로 작은 차이·실제 게임 전체 속도·물리 지연으로 일반화하지 않는다.

| 입력 (샘플 주기 / 믹서 주기 / 채널 / ticks) | 이전 ms | 현재 ms | 조건 |
| --- | --- | --- | --- |
| 256 / 512 / 16 / 8192 | 43.47 | 21.81 | 캐시 적용 |
| 176 / 352 / 16 / 8192 | 49.02 | 21.42 | 캐시 적용 |
| 1 / 512 / 1 / 512 | 27.82 | 3.94 | 가장 긴 캐시 support |
| 384 / 512 / 16 / 8192 | 36.95 | 36.00 | 기존 계산 경로 |

- 캐시는 시작 때 준비하므로 연산 비용이 사라지는 것은 아니다. 위 실행들의 NDS 생성 중앙값은 이전 약 21.2..22.2ms, 현재 약 21.5..22.4ms였으나 이는 전체 생성 비용이며 캐시 초기화 비용만 분리한 측정이 아니다. 공유 메모리 증가와 위상·비율 조건을 함께 고려해야 한다.
- 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다. 기존 x86 JIT ON/OFF·ARM64의 Sinc 이력/scalar 검사에 새 경로 검증이 포함된다.
- 게임 플레이·장기 청취·물리 입력/오디오 지연·구형 기기 전체 성능은 측정하지 않았다. 특정 합성 입력의 개선을 음질 향상이나 틱 노이즈 완전 해결로 주장하지 않는다.

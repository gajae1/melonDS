# 1.1.11 — 카트 SPI 부분 쓰기와 EEPROM 페이지

상태: 구현·Windows 빌드·로컬 회귀 완료. 기준 1.1.10. NP-15 AUXSPI와 NP-18의 작은 EEPROM을 실제 카트·저장 통지까지 검증한다.

## 5페이즈

1. **반례:** AUXSPICNT 하위 byte가 bit13을 보존하면서도 SPIRelease를 호출하는지 ARM9/ARM7 MMIO와 held WRITE 데이터로 확인한다. 512B EEPROM의 16B 페이지 끝 쓰기를 정상 구간과 대조한다.
2. **수정:** AUXSPI는 mask를 적용한 최종 레지스터 값의 실제 mode 전이만 전달한다. 작은 EEPROM은 페이지 안 주소 진행과 저장 통지를 함께 수정한다. 다른 저장 장치 종류의 의미를 추측 변경하지 않는다.
3. **통합:** busy·hold·CPU 소유권·정상 mode 전이와 중간 저장 상태 복원을 확인한다. 전체 SRAM과 통지 범위로 재구성한 저장 결과가 같아야 한다.
4. **검증:** 생산 core·scheduler·카트에 생성 입력을 사용해 정상/실패 대조를 실행하고 기존 IR·상태·저장 회귀를 확인한다. 최종 Windows 구성의 전체 회귀는 한 번 실행한다.
5. **배포:** 버전·EXE·의존성·패키지를 확인하고 공개 소스·계획을 포크 master에 반영한다. 물리 전송 속도·WIP·장치 프로토콜 수락은 별도 기록한다.

## 근거

[libnds card.h](https://github.com/devkitPro/libnds/blob/v1.8.0/include/nds/card.h)는 AUXSPICNT의 SPI mode를 bit13, hold를 bit6, busy를 bit7로 정의한다. byte 쓰기에서 mask 밖의 값을 전이 판단에 사용하지 않는다. [ST M95040-W 자료](https://www.st.com/resource/en/datasheet/m95040-w.pdf)는 16B 페이지와 같은 페이지로 돌아오는 WRITE, CS 상승에 따른 쓰기 종료를 설명한다. 코드 실행으로 확인할 경계이며 새로운 실기 측정 결과는 아니다.

## 변경과 실행 증거

| ID | 수정 전 반례 | 변경·정상 대조 | 결과 |
|---|---|---|---|
| NP-15 | WREN 후 held WRITE에 A1, 하위 control byte, B2를 보내면 register.bit13은 유지되어도 중간 CS 해제로 A1/FF만 저장됨 | mask·읽기 전용·쓰기 가능 bit를 합친 최종 register의 실제 mode 전이만 비교. ARM9/ARM7 MMIO·scheduler·실제 카트 및 전체 savestate 사용 | 수정 전 3/7, 수정 후 7/7 PASS |
| NP-18 | 00F/0FF/1FF부터 쓰면 다음 페이지를 변경하고, 512 data byte에서는 dirty 길이가 0이 됨 | 기존 저장된 시작 주소로 16B 페이지를 고정하고 페이지 전체를 한 번 통지. SRAM 예상값과 통지 범위로 재구성한 저장 image를 각각 비교 | 수정 전 2/5, 수정 후 5/5 PASS |

AUXSPI의 정상 high-byte/word mode 전이, bit15만 변경, 소유하지 않은 CPU·eject 상태, busy 완료와 중간 상태 복원 뒤 이어 쓰기를 대조했다. read-only busy와 기존 속도 변경 TODO는 유지한다. 이 회귀는 실제 CPU MMIO 함수 이후의 경계를 실행하며 ARM 명령 디코드/JIT로 시작하는 전체 게임 실행은 아니다.

EEPROM은 WREN/WRDI·주소만 보낸 WRITE·정상 페이지 내부 쓰기·low/high 페이지 끝·40/512 byte 반복 wrap·READ의 전체 array 순회·14.1 중간 WRITE 복원·8KiB 장치의 연속 접근을 확인했다. 통지에는 일부 비변경 byte가 포함될 수 있지만 동일한 16B 페이지 안이며 다른 페이지를 덮어쓰지 않는다. 실제 디스크 파일 대신 통지 범위만 반영하는 메모리 image를 사용했다. 상태 형식 14.1과 기존 필드 배치는 유지하며 이미 과거 버그로 바뀐 저장 bytes를 자동 복구하지 않는다.

Windows x64·UCRT64 GCC 16.2.0·CMake 4.4.3·Qt 6.11.2·SDL 2.32.10, C23/C++26·Release·JIT·OpenGL/Compute·AVX-512 빌드·LTO off. AVX-512 실행 지원과 실제 사용은 CPU/OS dispatch에 따른다.

최종 Windows frontend 빌드와 전체 CTest **333/333, skip 0, 31.51초**를 확인했다. 기존 interpreter·warmed JIT·fastmem·실제 OpenGL/Compute 출력 회귀를 포함한다. EXE의 FileVersion/ProductVersion은 1.1.11이다. EXE/DLL 129개에서 import 누락 0, 독립 PATH의 `--help` 종료 0을 확인했다. 공개 계획 20개 상대 링크·개인 경로 검사도 통과했다. 실행 패키지는 이 EXE와 필요한 DLL/plugin·라이선스로 구성하고 공개 소스 ZIP은 완료 커밋에서 생성한다.

## 남은 범위

실제 게임 저장·EEPROM WIP/WP·전원 중단·전송 중 baud 변경·물리 CS/IRQ/DRQ 타이밍은 별도다. 크기만으로 EEPROM/FRAM 종류를 추측하지 않으며 GBA EEPROM의 DS ROM bus/DMA 접근과 BT 키보드 transport는 아직 구현 완료가 아니다. 다음 증분은 FS-15 치트 직렬화·원자적 저장·오류 때 편집 보존을 다룬다. 새 성능 이득은 측정하지 않았다.

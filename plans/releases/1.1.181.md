# 1.1.181 — x64 JIT 블록 직접 연결, ARM64 JIT 수정, 전 플랫폼 CI 복구, SDL3 기본

2026-09-25. 이전 버전은 1.1.180이다. Windows 기본 배포가 SDL3로 바뀌었고, SDL2 빌드는 `-sdl2` 접미사 ZIP으로 함께 낸다.

**x64 JIT 블록 직접 연결.** 컴파일 시점에 목적지가 정해진 분기로 끝나는 블록은 다음 블록이 컴파일되면 C++ 디스패처로 돌아가지 않고 바로 들어간다. 연결 지점의 가드 코드는 디스패처가 블록 사이에서 하는 검사(조건 분기의 실제 PC, 파이프라인 드레인, StopExecution, 사이클 예산, ARM9 실행 권한, 빠른 조회 항목과 태그)를 그대로 반복하고, 하나라도 실패하면 기존 ARM_Ret 경로로 나간다. 블록 무효화는 조회 항목 검사로, JIT 리셋은 연결 지점 전체 삭제로 처리한다. 두 게임의 화면·PCM과 400M/1000M 사이클 시점 저장 상태가 fastmem 켜고 끈 경우 모두 바이트 동일했고, 1200프레임 실행 시간은 Solatorobo −3.1%, Black −4.7%(A/A 잡음 0.6/1.1%)였다. 새 `core-jit-chain-link` 검사는 연결 진입·차단 조건·재연결·저장 상태 일치를 확인하고, 예산 검사나 진입 재검증을 없앤 변형에서 실패한다. 근거는 `local-docs/jit-block-link-20260925/`.

**ARM64 JIT 수정.** CI에 aarch64 러너의 코어 검사를 처음 추가하자 x64에서는 통과하던 4건이 실패했다. Thumb PC 상대 리터럴 로드가 등록되지 않은 레지스터를 써서 릴리스 빌드에서 주소 0을 읽던 결함, 조건부 PC 쓰기 사이클(건너뜀 2→1, 실행 17→3), ARM9 PC 쓰기가 MemTimings를 잘못된 간격으로 읽던 트램펄린, 동적 메모리 타이밍 가드 누락을 x64 수정과 같은 방식으로 고쳤다. 인터프리터 fallback이 PC를 옮기면 블록을 떠나는 1.1.178 x64 수정도 ARM64에 옮겼다. aarch64 네이티브 CI에서 `^core-|^arm64-` 150개가 통과한다.

**보간 뱅크 준비 병렬화.** 최소 위상 보간의 희소 응답 표를 검증 후 최대 8개 스레드로 채운다. 각 값은 같은 Dot 계산이라 표 전체가 바이트 동일하고(덤프 SHA `110f12bb`), 재생 경로(Read/StepPosition)는 기계어까지 그대로다. 뱅크 생성 45.9→12.1ms, 시작 시간 −27/−42ms. 1.1.180에서 뺀 지연 전개와 달리 프레임 루프 비용이 늘지 않는다. `local-docs/audio-bank-v2-20260925/`.

**CI 복구.** GitHub CI가 1.1.175 이전부터 Core regressions·Windows·BSD에서 계속 실패하고 있었다. GDB 테스트의 poll 대체 함수 이름 충돌, x86 호스트에서 ARM64 전용 캐시 명령을 컴파일하던 에뮬레이터 테스트, SDL 헤더 경로를 받지 못하던 오디오 출력 라이브러리, BSD libc++의 `std::stop_token`(스레드 라이브러리 링크와 `_LIBCPP_ENABLE_EXPERIMENTAL` 검사), ASan 작업의 C/C++ 컴파일러 불일치를 고쳤다. OpenBSD는 실행 전용 코드 영역이 libco 문맥 전환을 거부하므로 GDB 스텁을 기본으로 끈다. Windows·Ubuntu(x64/aarch64)·macOS·BSD·Core regressions가 모두 통과한다.

**SDL3 기본.** pkg-config가 SDL3를 찾으면 Qt 프런트엔드는 SDL3로 빌드된다. vcpkg와 많은 배포판은 아직 SDL2만 있어 그 경우 SDL2로 빌드한다. 사용자 요청으로 SDL3 빌드도 전체 CTest를 돌렸다.

같은 라운드에서 채택하지 않은 것: 오디오 Read 4꼬리 SIMD(잡음 이하, `audio-read-v5-20260925`), 이전에 잡음 이하로 기각된 8개 후보의 결합(잡음 이하, `combo-rejected-20260925`). Vulkan GPU 직접 표시는 1단계 구현만 있고 앱 연결 전이라 포함하지 않았다. 구형 CPU 점검에서 1.1.180 실행 파일은 런타임 선택 밖의 AVX/FMA 명령이 없고, 스칼라 강제 모드 CTest가 통과했다(`old-device-matrix-20260925`).

비공개 게임 두 개의 헤드리스 Software 1200프레임 ABBA 실행에서 1.1.180과 1.1.181의 최종 화면·누적 PCM·프레임버퍼 digest가 같았다.

소스 커밋 `830b3d8d4408cd4d3fce539d1277fd46976fdf65`의 깨끗한 스냅샷에서 Windows UCRT64 Release를 SDL3·SDL2로 각각 빌드했다. 두 빌드 모두 전체 CTest **1034/1034**다. 두 배포·패키징은 exit 0이고 두 매니페스트의 소스 ID는 `ef917a51e481fc86ba5ad37a438f02c9507988ad483eb3b17c02b9b799f33fc7`로 같다. 각 런타임 ZIP은 325개 파일, 검사한 비공개 파일 0개이며 기본 ZIP에는 SDL3 DLL만, `-sdl2` ZIP에는 SDL2 DLL만 있다. 다른 작업자의 수정인 `src/teakra/src/test_generator.cpp`와 미완성 Vulkan 직접 표시 작업은 포함하지 않았다.

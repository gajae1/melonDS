# 1.1.233 — WASAPI 장치 전환 후 출력 정보 갱신

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 변경

Windows 기본 출력 장치가 바뀌면 miniaudio가 새 장치의 버퍼 주기를 협상하지만, 앱의 출력 정보와 오디오 큐 목표는 이전 값을 유지할 수 있었다. 장치 전환 알림 뒤 재생 시작 알림이 오면 재연결 필요 상태도 사라졌다.

이제 WASAPI 전환 알림을 별도 원자적 플래그에 기록한다. 재생 시작이나 일시정지로 이 요청을 지우지 않고, 기존 출력 소유 스레드의 재연결 절차를 거쳐 새 장치의 출력 정보를 반영한다. 알림 스레드에서 공개 출력 정보를 수정하거나 UI 스레드에서 변경 중인 네이티브 장치 필드를 읽지 않는다. SDL 출력과 일반 일시정지 동작은 유지하며 새 외부 코드는 도입하지 않았다.

## 검증과 한계

네이티브 장치 초기화·시작·해제를 대체한 WASAPI 모의 백엔드에서 기존 코드는 복구 상태 검사 6건에 실패했고 수정안은 통과했다. SDL2·SDL3 구성으로 검사했으며, 256→480프레임과 256→256프레임 전환, 재생 재개 후 복구 요청 보존, 재연결 후 버퍼 값 반영, 소유 스레드에서의 자원 해제를 확인했다.

주기가 같은 장치 전환도 재연결하므로 전환 때 추가 끊김이 생길 수 있다. 실제 출력 장치 전환, 청취 품질과 물리 지연은 측정하지 않았다. 장치를 전환하지 않아도 시간이 지나며 커지는 틱 노이즈의 원인은 이번 검사로 입증하지 않았다. WASAPI 모의 검사는 로컬에서 수행했고, 코어 회귀 검사와 플랫폼 빌드는 CI에서 수행한다.

# 1.1.226 — 렌더러 재구성·셰이더 컴파일 중 오디오 큐 보존

2026-09-29. SDL3·SDL2 패키지와 플랫폼 CI 검증을 완료했다.

## 변경

렌더러 재구성과 셰이더 컴파일 같은 호스트 작업은 게임 프레임을 실행하지 않는데, 이전에는 AudioOutput 클라이언트 콜백이 계속 남은 PCM만 소비했다. 1.1.226은 기존 AudioOutput.Stop 게이트로 클라이언트 콜백만 멈추고(네이티브 백엔드는 페이드·무음을 계속) 큐·마이크·네이티브 장치·필터 상태를 보존한다. 렌더러가 준비되면(마지막 컴파일 chunk와 대체 경로 포함) 기존 준비 게이트의 시작 대기로 남은 PCM 재생을 즉시 재개하며 추가 에뮬레이션 프레임을 기다리지 않는다. 일부 컴파일 chunk 사이에는 NeedsShaderCompile 가드로 일시정지를 유지한다. 버퍼 크기·기본값·DSP는 바꾸지 않았다.

이 변경은 EmuInstanceAudio::audioSuspendForHostWork와 EmuThread의 updateRenderer·compileShaders에 있다. 콜백 소비를 먼저 끝낸 뒤 대기 중이던 시작 상태를 기억하고, 재개는 렌더러 준비 조건을 통과한 뒤에만 한다. 시계 임계값 조정, 입력 변경, 정상 상태 필터 계수 생략(1.1.222에서 기각)은 하지 않았다.

## 검증

- 오디오 검사 3개(SDL2 dummy 드라이버의 실제 AudioOutput 경로 포함)와 그래픽 실패 복귀 검사 2개가 통과했다. 네 검사는 focused.xml의 통과를 쓰고, 새 audio-host-work는 요청 cutoff 목표가 어긋난 시험 fixture를 고친 뒤 host-work.xml에서 한 번 다시 실행했다. 최초 실패는 focused.xml·focused.log에 남겼고 시간 합계는 2.63초다. 소스 GL 시험 fixture에는 오디오 인터페이스 어댑터 두 개가 필요했다.

| 검사 | 시간(초) |
| --- | ---: |
| `audio-callback-buffer` | 0.22 |
| `audio-clock-lifecycle` | 0.02 |
| `gpu-compute-failure-frontend` | 1.47 |
| `gpu-gl-allocation-buffer-fail` | 0.45 |
| `audio-host-work` | 0.48 |

- 변경한 7개 소스·테스트 파일의 최종 diff를 검토해 수락했다. 파일 해시는 source-review.json에 있고 줄 끝 정규화 후 소스 커밋의 내용과 일치한다.
- 게임 플레이·사용자 창·실제 오디오 장치 조작은 하지 않았다. 전체 회귀는 CI에서만 수행한다. Windows x64·ARM64, Ubuntu, macOS, BSD, Core regressions CI가 모두 통과했다.

## 컴파일 중 큐 시험

비공개 compile_probe가 실제 제품 compileShaders와 호출 꼬리를 추출하고 가짜 렌더러와 수동 콜백 사건으로 실행했다. 대기 프레임은 800개다.

| 경로 | 컴파일 성공 | 컴파일 실패 | 정지 대조 |
| --- | --- | --- | --- |
| 이전 | 800프레임 소비, 2528프레임 부족 | 800프레임 소비, 480프레임 부족 | 800프레임 유지 |
| 현재 | 컴파일 중 0 소비, 800프레임 보존 | 컴파일 중 0 소비, 800프레임 보존 | 800프레임 유지 |

현재 경로는 준비 후 재개에서 256프레임을 소비했다. 원본은 legacy.log와 current.log다. 이 결과는 추출한 제품 compileShaders와 호출 꼬리를 가짜 렌더러·수동 콜백 사건으로 시험한 것이며 실제 WASAPI 출력이나 사용자가 들은 문제의 완전한 재현이 아니다. 게임 FPS, 물리 입력·오디오 지연, 음질 향상은 주장하지 않는다. 추가 에뮬레이션 프레임을 기다리지 않으므로 큐 채움이나 넘침을 늘리지 않는다.

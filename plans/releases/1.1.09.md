# 1.1.09 — 홈브루와 치트 입력·실행 보호

상태: 구현·Windows 빌드·로컬 회귀 검증 완료(2026-09-10). 기준 소스: 1.1.08. NP-16/20/21의 재현 가능한 경계를 선반영한다. 책임 버전 1.1.24·1.1.13의 전체 수락은 남긴다.

## 이번 증분의 5페이즈

1. **재현:** 긴 argv·주소 wrap, 잘린 DLDI source/target, DB header/index/string/code, 빈/홀수 치트와 넘치는 literal을 정상 입력과 대조한다.
2. **입력:** 파일 주입·ROM 패치·guest 쓰기 전에 해당 범위를 검증한다. 손상 DB 항목은 통째로 제외하고 정상 항목의 순서·checksum·단일 활성화 정책을 보존한다.
3. **중단:** 긴 loop/copy에 기존 Qt 메시지의 중단 요청을 전달한다. 실행 도중 중단한 치트는 현재 실행본에서 비활성화하고 이미 적용된 변경이 남는다고 알린다.
4. **검증:** 생성 입력·보호 페이지·실제 Qt 파일/선택 UI·ARM7 VBlank hook·통제된 스레드 전달을 검사한다. Windows 전체 frontend와 기존 JIT/GPU 회귀를 확인한다.
5. **배포:** 동일 커밋의 소스·공개 계획·실행 파일을 포크 master에 반영한다. 실제 홈브루/게임·다른 플랫폼과 미확인 opcode 의미를 후속으로 유지한다.

## 변경 범위와 계약

홈브루 argv는 `fat:/` 접두사와 NUL을 포함한 512바이트 용량을 검사한다. ROM명은 최대 506바이트이며 내부 NUL과 32비트 guest 주소 wrap도 SD 주입 전에 거부한다. 이름을 잘라 다른 파일을 열게 하지 않는다. word 복사는 정렬되지 않은 host 포인터 역참조 대신 `memcpy`를 사용한다.

DLDI는 실제 ARM9 ROM 범위와 패치 header/version·예약 크기·source/target/fixup/BSS·진입점 범위를 검사한 뒤 적용한다. 내장 driver의 실제 파일 548바이트와 예약 크기 1024바이트는 서로 다르므로 같은 값이라고 가정하지 않는다. 겹치는 fixup은 원본 값을 한 번만 재배치하며 target의 할당 크기를 보존해 reset 재패치를 유지한다. 이 할당 크기 보존은 [devkitPro dlditool](https://github.com/devkitPro/dstools/blob/master/src/dlditool/dlditool.c)과 대조했다. 읽기 전용 변환은 8바이트 ARM 진입점 범위를 확인한 뒤 write thunk를 교체하며 Thumb 진입점은 이 변환에서 지원하지 않는다.

치트 DB는 header/index 종결·offset·각 게임의 다음 offset·문자열 끝·항목/코드 word 수와 read/seek 성공을 확인한다. 파일 I/O 오류나 손상된 게임 항목은 부분 코드 없이 제외한다. 정상 항목은 기존 표시 순서대로 반환하며 `Error`는 유지된다. 게임 항목 수의 28비트 필드는 [TWiLightMenu parser](https://github.com/DS-Homebrew/TWiLightMenu/blob/master/romsel_dsimenutheme/arm9/source/cheat.cpp)와 대조했다. 반환된 목록의 root/child 부모 포인터를 보존한다. 기존 파일 크기·평면 category·코드 크기 제한은 유지한다.

가져오기에서 읽을 수 있는 항목이 없으면 기존 치트를 삭제하거나 import하지 않는다. 일부 항목만 실패하면 누락 안내 후 정상 항목을 선택할 수 있다. 선택이 없어지면 OK를 비활성화하고 프로그램에 의한 accept도 차단한다. 기존 checksum 필터와 정상 import는 유지한다.

치트 실행은 전체 word 쌍과 E literal의 8바이트 padding을 먼저 검사한다. 빈 코드는 아무 작업도 하지 않고, 홀수/잘린 literal은 앞의 유효 쓰기까지 적용하기 전에 거부한다. skip 중 큰 E 길이도 wrap하는 반복문 없이 검사한다. 정상 8/16/32비트 접근 순서, literal tail, F guest copy와 C0의 포함 반복 횟수는 보존한다.

긴 C0/D1/D2 반복과 E/F 복사는 `std::stop_token`을 확인한다. Qt에 메시지가 게시되면 stop을 요청하여 일시정지·종료 등의 동기 대기가 긴 치트 안에 갇히지 않게 한다. 이미 대기 중인 메시지가 있으면 stop 요청을 보존하고 큐가 비워진 뒤 새 토큰을 만든다. [C++ stop source 계약](https://eel.is/c++draft/stopsource)에 따른 협력적 중단이며 callback은 등록하지 않는다. UI 요청이나 별도의 host stop token이 없는 실행에 자동 시간 제한을 추가하지 않는다.

실행 전 취소는 해당 치트를 비활성화하지 않는다. 실행 중 중단 또는 미지원 opcode는 현재 runtime 코드만 비활성화하고 한 번 보고한다. 중단 시 후속 치트는 실행하지 않으며 파일의 활성 설정은 변경하지 않는다. 이전 guest 쓰기는 되돌리지 않는다. 다시 활성화하거나 새 코드 목록을 설치하면 새 실행본으로 처리한다. 지원하지 않는 C4/D4 연산 등을 추측 구현하지 않는다.

## 검증 기록과 한계

홈브루는 수정 전 argv 1/4·DLDI 2/14만 통과했고 수정 후 18/18 통과했다. 보호 페이지의 source/target 끝과 거부 입력의 부분 ROM 수정, 정상 RW/RO·겹치는 fixup·재패치를 확인했다. 실제 FAT 주입·홈브루 부팅 성공의 증거는 아니다.

치트 DB는 수정 전 1/11에서 수정 후 11/11 통과했다. 실제 parser와 현재 Qt 파일 함수에 short/error/zero-read와 seek 실패를 주입한다. 부모 포인터·checksum·부분 정상 항목을 함께 확인한다. 실제 대용량 공개 DB와 선택 창 수락은 남는다.

치트 코어는 빈 코드/큰 literal의 접근 위반, 홀수/잘린 본문 뒤 부분 쓰기, skip 중 큰 길이의 timeout을 수정 전에 확인했다. 수정 후 정상 쓰기/loop와 입력 경계·취소·미지원 코드 12/12가 통과했다. 실제 ARM7 IRQ로 실행하며 생성 코드와 코어 메모리만 사용한다. 가져오기 UI 1개와 Qt 메시지→코어 취소 4개도 통과했다. 메시지 fixture는 실제 send/token/wait를 사용하되 코어가 돌아온 뒤 큐를 확인·승인하는 worker로 dispatcher 경계를 대체한다. 전체 창/장치 종료 검증으로 확대하지 않는다.

최종 Windows frontend 빌드와 CTest 273/273, skip 0, 26.69초를 확인했다. 기존 interpreter·warmed JIT·fastmem과 실제 OpenGL/Compute 출력 회귀를 포함한다. UCRT64 GCC 16.2.0, CMake 4.4.3, Qt 6.11.2, SDL 2.32.10, C23/C++26, 선택적 AVX2/AVX-512와 LTO OFF 구성이다.

배포 EXE/DLL 129개에서 import 누락 0, 개발 도구를 제외한 PATH의 `--help` 종료 0을 확인했다. 공개 계획 18개의 상대 링크와 개인 경로 제외 검사도 통과했다. 실행 패키지는 EXE·필요 DLL/plugin·라이선스로 구성한다.

실제 홈브루 FAT RW/RO·reset 반복, 게임 치트 적용/해제/중단 뒤 진행과 다른 플랫폼 실행은 남는다. D1/D2 backedge의 조건 상태 복원과 C5 counter 수명은 별도 opcode 의미 검증이 필요하다. 성능·지연 수치는 측정하지 않았다.

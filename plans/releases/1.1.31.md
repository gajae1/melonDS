# 1.1.31 — SD 이미지 보존·DSP FIFO·Compute 초기화

기준은 1.1.30(`0dba3a4b9a2bb03f44a6e7fe3b0d6915f37dd469`), 검증일은 2026-09-11이다. [1차 감사](../Audit_2026-09-11.md)의 FS-02, AD-21, GR-02 경계를 독립 작성 후 통합했다. 원래 책임 버전의 전체 목표나 전체 코드 감사의 완료를 뜻하지 않는다.

## 변경과 근거

**SD 이미지:** 기존 FAT 이미지를 한 번 읽거나 탐색하는 데 실패하면 포맷으로 넘어가던 반례를 생성 파일로 확인했다. 읽기·탐색 반례에서 이미지 쓰기 169회와 인덱스 쓰기 2회가 발생했다. 이제 기존 데이터의 마운트 실패를 포맷의 근거로 사용하지 않는다. 새 이미지와 실제로 비어 있는 이미지는 만들 수 있고, 크기 조회가 0을 반환할 때는 별도 읽기와 EOF 확인으로 빈 파일인지 판별한다. 실패한 마운트·포맷은 handle을 닫고 용량을 0으로 만들며, DSi와 homebrew 카트는 그 객체를 SD 슬롯에 삽입하지 않는다. 실패 객체와 이동된 객체의 소멸자는 폴더 동기화를 시작하지 않는다. 새 인덱스는 포맷·마운트 성공 뒤 기록한다.

**DSP:** BTDMP 송신 FIFO에 한 word를 넣고 sample clock 한 번을 호출하면 두 번째 `front()`가 빈 큐에 접근했다. checked STL의 assertion 실패로 재현했고, 두 번째 word를 읽기 전에 잔여량을 확인한다. 있는 왼쪽 word를 소비하고 부족한 오른쪽만 0으로 출력한 뒤 기존 위치에서 상태와 IRQ를 갱신한다. 정상 stereo·RX 처리·clock 소유권은 유지한다. 0은 [Teakra의 채널별 부족 처리 선례](https://github.com/wwylele/teakra/blob/master/src/btdmp.cpp#L21-L44)를 따른 안전정책이며 **DSi 실기 출력값이라는 주장은 아니다**. 실기의 부족 출력·IRQ 시점·다음 채널 정렬은 별도 확인이 필요하다.

**Compute:** 첫 비텍스처 polygon에서 대입되지 않은 texture layer를 float로 읽고, variant 비교에 미초기화 capture offset을 사용할 수 있었다. 지역값과 variant를 초기화하는 두 줄을 수정했다. 활성 캡처 offset, sampler, shader, alpha, dispatch 한도와 처리 순서는 바꾸지 않았다. 생성 frame/capture의 수정 전후 결과가 같았으므로 관찰된 화면 오류나 속도 향상으로 확대하지 않는다.

## 5페이즈와 검증

1. **재현:** 실제 FATStorage·FatFs·Qt 파일 처리에서 실패 주입 전후 쓰기를 관찰하고 DSP는 실제 빈 큐 접근을 확인했다. Compute는 소스의 대입·읽기 경로와 기존 생성 장면을 대조했다.
2. **수정:** 저장 경계는 통합 작성자, DSP 판단·구현은 독립 Astra 작업자, 확정된 Compute 초기화는 독립 GLM 작업자가 맡았다.
3. **통합:** 공용 CMake와 core dispatcher는 통합 작성자만 수정했다. 새 제품 소스 파일은 없으며 FAT 파일 수명 검증 한 파일을 기존 Qt/FatFs 구성에 추가했다.
4. **검증:** FAT 정상·빈 이미지·마운트/길이 오류·비정상 이미지·포맷 실패, 실제 DSi/카트의 실패 SD 미삽입을 통과했다. DSP는 0/1/2/홀수 FIFO·후속 쓰기·용량·IRQ·flush·동시 RX와 실제 I2S/DSP 경로의 두 rate 설정을 확인했다. Compute는 실제 GL context의 frame, capture-readback, capture-jit 세 실행에서 전후 결과가 같았다. 최종 Windows x64 Release 전체 빌드 성공, CTest **564/564 통과·실패 0·건너뜀 0**, 병렬도 2에서 **61.41초**였다. 최종 application object를 사용하는 생성 guest의 Qt 복구 검사도 통과했다. 배포본 129개 PE의 누락 import가 없고 깨끗한 PATH에서 도움말 실행이 성공했다.
5. **배포:** 검증한 Windows 실행 파일과 의존성을 선별하고 커밋된 소스·EXE·ZIP 해시를 manifest에 연결한다.

## 호환성과 남은 조건

상태 파일은 14.2, 설정·일반 게임 저장·LAN v1 형식은 유지한다. [1.1.30의 원본 이관·LAN 기록](1.1.30.md)을 재사용하며 이번 증분에서 원본 전체나 원본 클라이언트 방향을 다시 시험했다고 주장하지 않는다. 원본 클라이언트 접속의 환경별 첫 UDP 유실, 구버전이 섞인 다자간 mesh와 두 PC 실제 게임 수락은 남는다. 실제 게임의 로컬 무선 메뉴를 우회하는 변경은 없다.

기존의 명시적 SD 크기 변경은 정상 마운트 뒤 재포맷하는 동작을 유지한다. 모든 파일 작업이 원자적이라는 뜻은 아니며, 폴더 export 중간 읽기·쓰기 실패와 동기화 오류의 상세 UI는 후속이다. 오류로 SD가 빠지는 것은 파일 보존을 위한 실패 전달이다. 읽을 수 없는 기존 이미지를 자동 복구하거나 데이터를 재생성하지 않는다.

검증은 생성 파일·생성 입력·Windows x64와 현재 GL driver의 경계에 한정한다. 게임·물리 SD/오디오·DSi 실기, 다른 GPU, native ARM64·Android·macOS·Linux의 실행과 장기 수락은 남는다. DSP 부족 처리의 실기 일치나 gameplay 성능 이득은 측정하지 않았다. 패키지에는 게임·BIOS·firmware·NAND·개인 설정·세이브를 포함하지 않는다.

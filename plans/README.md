# 개발 계획

현재 구현·배포 상태는 [현재 상태와 다음 구현](Current_Status.md)을 먼저 읽는다. 아래 1.1.02 분석과 1.1.03~1.1.44 계획은 역사적 책임 배정이며 현재 구현 완료 목록이 아니다.

1.1.02 소스 분석과 2026-09-09 문서 검토를 반영한 공개 계획이다. 기존 C++ 코어·Qt 프런트엔드·렌더러·JIT를 기반으로, 재현한 결함을 먼저 수정하고 측정으로 효용을 확인한 기능을 채택한다.

## 적용 원칙

- 분석 후보, 실행으로 재현한 결함, 구현, 회귀 통과, 안정 지원을 구분한다. 문서 검토는 새 코드 감사나 실행 검증을 대신하지 않는다.
- 정확성·저장 데이터 보존은 반례와 관련 회귀로 판단한다. 성능만을 위한 변경은 출력 동등성과 실제 이득을 모두 요구한다.
- 게스트 정수·플래그·사이클·저장 형식을 보존한다. 부동소수점 재결합·FMA·벡터 폭 변경은 해당 수치 계약을 검증한다.
- ISA는 컴파일러 지원과 CPU·OS 실행 상태를 함께 확인한다. 미지원 경로는 기존 fallback을 유지한다. 64비트 호스트를 개발 대상으로 한다.
- C23/C++26 모드와 개별 라이브러리 기능의 지원을 구분한다. 의존성·ISA·새 GPU API를 버전 숫자만 보고 전면 교체하지 않는다.
- 기존 기능과 해결한 문제를 재구현하지 않는다. upstream 변경은 코드·revision·영향 경로를 대조한 뒤 채택한다.
- Vulkan은 표시→3D→2D/capture/readback→복구·성능 순서로 개발한다. 첫 표시 성공을 전체 renderer 완성으로 기록하지 않는다.
- 코어 rollback, host 오디오·GPU 큐, NAND/SD·네트워크에 발생한 외부 부작용은 별개다. 하나의 복원 성공을 전체 복구로 확대하지 않는다.
- 기존 CMake·CTest·합성 입력을 재사용한다. 새로 변경한 경계의 검증부터 실행하고, 같은 소스·환경에서 성공한 전체 검사를 반복하지 않는다.

개인 환경·기기 목록·연결 및 구매 계획·비공개 입력·원본 리뷰는 이 공개 계획에 포함하지 않는다. 제품에 필요한 플랫폼별 검증 계약만 기록한다.
추가 아이디어의 채택 검토는 현재 과제와 별도로 진행한다.
